# 2026-07-12 — session 001

## 這次做了什麼(S3×S4 端到端真實驗收:PSD→件→mesh 對照 Award 生產 mesh)

依 STATE「下一步」最高優先塊:用 Award(機器人 big win 生產 spine)的 3 個 mesh 件當真值,
端到端驗證 S3 生成器對真實標的的收斂。

1. **探查真值**:Award 中會 warp 的件做 mesh —— `機器人拆件/{光暈,身體,左手}`(右手/頭為 region)。
   確認 atlas 區塊 = 0.70× 邏輯尺寸(offset=0/無 trim)→ 藝術家 `uvs` 為 region-local [0,1],
   可與生成 mesh 同座標系對照。
2. **關鍵發現:這 3 件無 deform**(12 動畫掃描確認,骨骼驅動)→ 真實位移場閘 N/A。
   改用**靜態拓樸有效性**(setup:0 自交/翻面/退化)+ **覆蓋率 IoU 對照藝術家基準**。
3. **新工具** `tools/mesh_gen/validate_robot_parts.py`:每件 atlas 切圖 → `generate_mesh_v2` → 三閘評分。
4. **首輪 2/3 過**:左手 0.960/身體 0.968 過;**光暈 FAIL**(0.929 < 基準 0.980)。診斷:近方形 → 全走
   v1 Delaunay;圓形光暈用預設 eps=0.008 只得 hull=14 → 邊界欠取樣。eps 掃描證實愈細愈準但頂點漲。
5. **修正(第 2 輪,within-budget 迭代)**:給 v2 加 **adaptive 邊界取樣**(opt-in):eps 階梯上取
   「nv ≤ budget 的最細」。**預設 `adaptive=False` → 既有 caller 零影響**。重跑:光暈 eps0.004/0.966、
   左手 eps0.003/0.988、身體 eps0.006/0.971,全 ≤64 頂點 → **overall_pass=True**。
6. **回歸驗證**:main_draw 4 mesh 以 `--gen v2` 全 `overall_pass`(皆 strip 路徑,不碰新分支)→ 零回歸。

## 關鍵結論 / 教訓

- **S3×S4 端到端對真實生產標的驗收通過(里程碑)**:PSD→件→mesh 對「有藝術家真值」的 spine 追平覆蓋率。
- **閘要對得上標的的實際運動**:非變形件(骨驅)不套變形件的位移場閘,改靜態拓樸+覆蓋率。
- **生成器發現**:預設 Douglas-Peucker eps 對圓形/細緻邊界欠取樣 → adaptive 邊界取樣(頂點預算內取最細)修正;
  以 opt-in 保護既有結果不回歸。
- 生成 mesh 頂點數少於藝術家仍追平覆蓋率(藝術家多的內部點是為 warp 控制;此件不變形)。
