推進 `STATE.md` 最高優先候選 1:**PSD件 → S3 mesh → 對照 Award 真實生產 mesh**(有 ground truth、純 CPU)。

### AC(動手前定的可檢查目標)
對機器人 3 件(Award 中為 mesh 的 光暈/身體/左手),生成 mesh 需:
- IoU 覆蓋率 ≥ 藝術家自身覆蓋率(相對基準,不用武斷絕對值);
- 頂點數 ≤ 藝術家頂點數(不能靠灌頂點刷 IoU);
- setup pose 幾何乾淨(0 退化 / 0 孤兒 / 質心在遮罩內)。

### 過程與發現
1. 探測 Award 3 件:全是 **weighted mesh、無 deform timeline**(骨權重變形)→ `deform_eval` 真實位移場閘
   不適用,改「靜態覆蓋率對照藝術家真值」+ 幾何乾淨。
2. 預設參數初跑:光暈 IoU 0.929 << 藝術家 0.980(身體/左手已近平)。查因:
   **v1 邊界容差 `epsilon_frac=0.008` 是周長比例,大件(光暈周長 ~1927px)被過度簡化**。
3. 修正:改用**固定絕對像素容差 `eps_px`**;sweep 得 **eps_px=3.5** 對 3 件全部「nv ≤ 藝術家 且 IoU ≥ 藝術家」。
   把 `eps_px` 加進 `generate_mesh.generate()`(向後相容,預設 None 走原周長比例)。
4. footprint 一致性把關:藝術家 uvs 為 region-local → 遮罩須用 **atlas 切件**(權威);psd 切件因 frame
   錯位低估藝術家基準,只作生成品質交叉檢查。
