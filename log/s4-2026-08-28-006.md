# 2026-08-28 — S4 session 006(PSD 內編輯,統一切圖/補圖座標系)

## 這次做了什麼

使用者要求:「無論是切圖還是補圖,都是在 PSD 檔中編輯,如此才能建立相同座標系。」

### 1. 確認技術可行性

psd-tools 1.18.0 支援 `PSDImage.create_pixel_layer(image, name, top, left)`(`top`/`left`
是 PSD **全域**畫布座標)、`psd.remove()`/`insert()`/`index()`(list-like z 序操作)。

### 2. 新增 `tools/mesh_gen/psd_inplace_patch.py`

- `patch_layer_with_image(psd_path, layer_name, patched_local_rgba, out_path)`:找同名圖層 →
  讀 `layer.left/top`(全域)+ z 序 → 移除舊圖層 → 用同一組座標建新圖層 → 存檔。座標一致性
  由 psd-tools API 保證,不必自己換算 offset。
- `demo_hole_patch(...)`:重用 `inpaint_eval.py` 的挖洞/填補函式做示範/自我測試。
- CLI 含 `--eval`,自動呼叫 `psd_slice.evaluate()` 驗證座標系/重組是否一致。

### 3. 踩到並修正兩個真實 psd-tools 陷阱

**陷阱 1**:`create_pixel_layer(name="身體", ...)` 存檔時 `UnicodeEncodeError`(legacy Pascal
string 預設 macroman 編碼,中文編不進去)。檢查真實 PSD 發現 Photoshop 自己也不是這樣存——
真正名稱在 `Tag.UNICODE_LAYER_NAME`(`luni`)tagged block,legacy 欄位是亂碼佔位。改用同樣
慣例修正,存出的檔案我方工具跟真正 Photoshop 都讀得對。

**陷阱 2**(較嚴重):patch 完存檔重開,`psd_slice.py --eval` 從 `overall_pass: true` 掉到
`orphan_ratio=0.55`、`premult_rgb_mae=143`。排查發現:`psd.composite()`**預設**回傳的圖是
`mode="RGB"`(**完全沒有 alpha 通道**),`.convert("RGBA")` 會把 alpha 全填 255,導致
`evaluate()` 把整個 713×693 畫布當「有內容」的參照範圍,重組結果自然蓋不滿。根因:psd-tools
存檔時內嵌的合併預覽圖,在**我方工具程式化重存**的檔案裡沒有正確帶出 alpha,`composite()`
預設會先吃這張壞掉的預覽。**修法**:`composite(force=True)` 強制跳過預覽、直接從圖層重算。
已在 `psd_slice.py` 兩處呼叫加上;對原生 Photoshop 檔案回歸測試數字完全一致(純捨入誤差
<1),無副作用。

### 4. 端到端驗證

對 `robot_parts.psd` 的「身體」「左手」兩層分別跑合成挖洞(cv2_ns / nearest)→ 寫回 → `--eval`
自驗,兩次皆 `overall_pass: true`(`premult_rgb_mae≈0.01`,跟未修改原檔幾乎一致)。確認錯誤
處理(不存在圖層名報清楚錯誤)、`build_spine.py`+`validate_build.py` 全流程對原始
`robot_parts.psd` 重跑無回歸。
