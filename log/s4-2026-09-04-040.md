# S4 chunk 40 — 2026-09-04(viewer v3:統一主素材架構)

## 觸發

使用者兩件事:(1) 提供一個本機 Windows 路徑(`C:\Users\user\Desktop\aiSpine\...`)要求
解析一張角色設定圖——已回覆說明我在雲端沙盒環境無法讀取使用者本機檔案,需要對方直接把圖
上傳到對話裡。(2)「調整viewer 介面, 主畫面 以 匯入的 png或psd為主, 我想看到 主素材及
當前的圖層, 補圖/切片/拆解 等功能, 對焦到同一個檔案(不要各別載入)」——這是本次實際
推進的工作。

## 問題診斷

v2(chunk 39)把切片/拆解/需求精靈接進 viewer,但拆解分頁有自己獨立的 `#decomposeInput`
file picker,跟左側「圖層/圖片」載入區完全無關——使用者要拆解一張已經在補圖分頁載入過的
圖,得在拆解分頁重新選一次檔。這正是使用者要求改掉的核心問題。

## 過程

1. 重讀現有 `s4_ai_viewer.html`(v2,約900行)確認狀態管理現況:`workingImg`/`workingName`
   只服務補圖;切片靠 `manifestParts`+`fileMap`(本來就共用,沒問題);拆解完全獨立
   (`decomposeOrigImg` 來自 `#decomposeInput` 自己的 change 事件)。
2. 重構為「單一主素材」架構:
   - HTML:拿掉分頁各自的 canvas(`baseCanvas`/`sliceComposite`/`decomposeOrigCanvas`),
     改成一個持續存在的「主素材」面板(`mainCanvas`+`maskCanvas`),置於 mode tabs 上方,
     不因切換模式而消失。
   - JS 狀態:`mainImg`/`mainName` 取代原本補圖專屬的 `workingImg`/`workingName`;
     `setMainAsset(img, name, isComposite)` 是唯一寫入點,`selectLayer()`/
     `selectComposite()`/補圖 `applyBtn` 都改呼叫它。
   - 新增 `compositeSource` 概念:PSD 解析出 `psd.canvas`、或 manifest.json 的
     `composite` 欄位對應到已上傳的 `composite.png`(`psd_slice.py` 本來就會產生這個檔),
     兩種情況都在圖層清單頂端插入一個「◆整體(composite)」偽列,載入完成後**自動選取**
     它當初始主素材(沒有 composite 來源則自動選第一個圖層/圖片)。
   - 拆解:刪除 `#decomposeInput` 與其 change 監聽,「1. 用主素材 AI 重繪拆件版面」按鈕
     改直接讀 `mainImg`。
   - 用量記錄表格移出補圖分頁,變成頁面底部持續顯示的共用區塊(補圖/拆解呼叫都寫進同一份
     `usageRows`),欄位新增「來源」(record.tag,如「補圖:左手」「拆解:整體(composite)」)
     方便分辨。
3. `node --check` 語法驗證通過。

## 驗證(Playwright headless Chromium,全程 mock 真實付費 API)

**寫測試過程抓到一個真實 bug**:第一輪測試「畫遮罩」步驟,`maskInfo` 顯示 `0.0%`——
追查發現 `#maskCanvas` 只有在 modebtn 的 click 事件處理常式裡才會被 JS 加上 `.active`
class(CSS 控制 `pointer-events`),但「補圖」是頁面載入時 HTML 就寫死 `active` 的預設
模式,從未真的觸發那個 click 事件,所以遮罩畫布從頭到尾都是 `pointer-events:none`——
**肉眼看畫面完全正常(遮罩疊圖顏色顯示邏輯沒問題),但滑鼠事件根本沒被吃進去**,若只靠
截圖目視檢查很可能不會發現。修正:`#maskCanvas` 的 HTML 直接帶初始 `class="active"`。

修正後 5 組測試全過:

1. 單張 PNG 載入 → 自動成為主素材,補圖模式預設啟用。
2. 遮罩繪製(涵蓋率正確算出 28.7%)+ mock 補圖呼叫 → 結果顯示、用量記錄新增一列、套用後
   主素材正確更新、`targetLabel` 維持一致。
3. 真實 `robot_parts.psd` 載入:composite 偽列出現且**自動選取**(713×693);點選圖層
   「光暈」後主素材正確切換(706×683);**切到切片模式主素材不受影響**(驗證跨模式共用
   狀態);點回 composite 列正確切回整體。
4. 拆解模式:確認頁面**不存在** `#decomposeInput` 元素;送出直接用主素材(mock API 回傳
   合成測試圖含3個獨立色塊),分割正確偵測出 3 個部件;用量記錄累積到 2 列(補圖1+拆解1,
   同一份共用 log)。
5. 需求精靈跳轉正常。

全程 **零 JS console error**。
