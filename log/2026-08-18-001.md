# 2026-08-18 — session 001

## 這次做了什麼(S3+S4 端到端:PSD件→生成 mesh→對照 Award 真實 mesh)

接手 STATE 最高優先 #1:把「PSD 切件 → S3 mesh」下游 pipeline 對真實生產標的(Award,機器人 big win)驗收。

1. **定位輸入**:`robot_parts.psd` 5 圖層(光暈/右手/頭/身體/左手),其中光暈/左手/身體 在 Award 中為 mesh。
   解析 Award.json:7 個 mesh **全部 weighted**;3 個機器人 mesh(80/98/78 頂點)。
2. **AC(可自量測)**:每件 生成 mesh 覆蓋率 IoU(vs PSD 切件 alpha)≥ 藝術家真實 mesh 覆蓋率基準 − 0.02。
3. **對齊驗證**:先確認 `artist_iou` 對 3 件(光暈/身體 在 atlas 內 rotate、左手不 rotate)vs atlas 切件皆 0.95+,
   證明 uvs/切件同框、可信;PSD 切件與 atlas 切件同朝向(前次已測 alpha-IoU 0.92~0.99)。
4. **建工具** `tools/mesh_gen/psd_to_award.py`:slice_psd 切件 → generate_mesh_v2(auto) → evaluate 覆蓋率 →
   artist_iou 基準對照 → overall_pass。一鍵、純 CPU 可自驅。
5. **結果**:3 件全 PASS(光暈 0.9331/0.9486、左手 0.9642/0.9768、身體 0.9660/0.9477),生成頂點 35~60 遠少於
   藝術家 78~98 卻覆蓋相當。
6. **負對照**:左手 mesh vs 身體/光暈 mask 掉到 0.52/0.58 → 覆蓋率閘有鑑別力。

## 關鍵發現 / 決策

- **⚠️ 機器人 mesh 全 weighted 且 bone 驅動、無 deform timeline**(逐幀掃 12 動畫確認 0 非零 deform)。
  現有 `deform_eval.real_deform_field`/`transfer_deform_check`/`load_mesh` 假設 unweighted per-vertex deform,
  對它們 N/A(硬跑 `ValueError: different number of values and points`)。
  → 本閘只做靜態覆蓋 + 拓樸預算;**骨驅 deform 耐受度是評估器缺口**,定為下一 chunk。
- 覆蓋率對照公平性:生成 IoU 與藝術家基準都對**同一份 PSD mask** 量測,apples-to-apples。
