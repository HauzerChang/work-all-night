## 過程

1. **架構風險驗證(動工前)**:viewer 要「純前端直接跟 ChatGPT 溝通」,關鍵風險是瀏覽器
   跨來源呼叫 OpenAI API 會不會被 CORS 擋。用 `curl -X OPTIONS
   https://api.openai.com/v1/images/edits` 帶 preflight header 測試,回傳
   `access-control-allow-origin: *`,確認允許——這個架構成立,不需要中介後端代理。
2. **建立 `tools/mesh_gen/s4_ai_viewer.html`**:純瀏覽器單檔工具,比照
   `psd_preview.html`/`spine_inspector.html` 架構慣例。功能:圖層載入(manifest.json+PNG
   或單張 PNG)、canvas 筆刷畫遮罩、prompt 輸入、直接 `fetch()` 打 OpenAI images/edits、
   結果三欄比對(原圖/AI完整回傳/套用後)、套用/下載、用量記錄(session內表格 + 可選
   File System Access API 直接寫入 `s4_data/openai_usage.jsonl`)。mask 編碼與
   `s4_openai_client.py` 一致(OpenAI 官方慣例)。key 只存 localStorage,原始碼無硬編碼。
3. **驗證**:用 Playwright(`/opt/pw-browsers/chromium` +
   `NODE_PATH=/opt/node22/lib/node_modules` 的全域套件)跑 6 項互動測試:單張PNG載入、
   滑鼠拖曳畫遮罩(驗證涵蓋率數字即時更新)、未填key送出正確擋錯、**mock 掉真實 fetch**
   (回傳假 200+假 token usage)驗證送出成功後的結果面板/用量表格/套用邏輯無 JS error、
   真實 `psd_slice.py -o` 輸出資料夾(manifest.json+PNG)載入正確顯示 5 個材質名稱。
   **未打真實付費 API**(mock 掉),避免測試階段產生非必要花費。
   過程中用 Playwright 對中文檔名 manifest 測試時撞到「找不到檔案」,換純 ASCII 檔名後
   立刻正常,確認是 Playwright `setInputFiles` 已知限制(`psd_preview.html` 先前記錄過
   同一個問題),不是本工具 bug。
4. **建立 `.claude/skills/spine-asset-request/SKILL.md`**(初步版):把既有 S4 工具串成
   「使用者描述動畫需求→判斷缺口類型→驅動對應工具→驗證→記錄」的可重複流程。缺口分類
   沿用既有 `s4-inpaint-taxonomy.md`(1a/1b/情境2)延伸出 A(需切圖)/B(補圖-CPU優先)/
   C(補圖-生成式)/D(視角外推,無解)四類,附決策順序(CPU優先,1b fail 才上生成式)、
   工具速查表、以及「誠實回報無法自動處理的情況」清單(平圖拆件/視角外推/生成結果像素
   漂移)。

## 檔案隔離契約的例外說明

`.claude/skills/spine-asset-request/SKILL.md` 不在 `prompts/run_s4.md` 列出的 S4 專屬
路徑(`STATE_S4.md`/`log/s4-*`/`knowledge/s4-*`/`tools/mesh_gen/`)清單內。判斷理由:
(1) 該契約的目的是「避免與主排程衝突」,`.claude/skills/` 是全新目錄,不觸碰
`STATE.md`/`PLAN.md`/`prompts/run.md`/主排程 log 等任何既有檔案,不構成衝突;
(2) 使用者在本次對話中直接要求「建立初步skill」,是明確指示,不是排程自主延伸範圍;
(3) skill 本質是「應用層封裝」,合理的落點就是 `.claude/skills/`(Claude Code 的標準
skill 位置),放進 `knowledge/s4-*.md` 會失去可被 `Skill` 工具直接呼叫的能力,偏離使用者
原意。
