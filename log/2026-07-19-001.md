## 這次做了什麼(S3 端到端對照第二份真實生產 spine：Award 機器人拆件 3 mesh 件)

推進 STATE 最高優先 bounded chunk：「PSD件→S3 mesh→對照 Award 真實 mesh」。

1. **定位標的**：Award(機器人 big win 主角,對應 robot_parts.psd)有 3 個 mesh 件 —
   `機器人拆件/{光暈,左手,身體}`(藝術家 78/80/98 頂點),另 2 件(右手/頭)為 region。
2. **AC(可量測)**:對每件,生成 mesh 的 IoU ≥ 藝術家 mesh 對同一 region alpha 的 IoU 基準
   (`artist_iou`),且無 deform 崩壞。
3. **踩到新 regime + 修 toolchain**:3 件皆 **weighted(vertices 長度 ≠ uvs×2)且無 deform timeline**
   (骨骼驅動)—— 與 main_draw 4 mesh(unweighted+每動畫有 deform)相反。`real_deform_field` 對
   weighted `zeros_like(setup)` shape 崩潰。修:偵測 has_deform,無 → 回傳 `field=None`;
   `validate_against_real` 見 None → `AC_real_deform.applicable=false`,overall 只看 IoU,並回報
   `artist_mesh` 對照欄。weighted+有 deform → 明確 NotImplementedError(無此資產)。
4. **v1 epsilon 校準(對藝術家真值)**:3 件不夠高瘦 → v2 auto 回退 v1 Delaunay。v1 舊預設
   `epsilon_frac=0.008` hull 只有 14~21、IoU 低於基準(全 fail)。掃描 → **0.002 為甜蜜點**:
   hull 37~43 ≈ 藝術家、頂點預算相當、3 件全 PASS;0.001 過頭(頂點爆量)。改預設 0.008→0.002。
5. **迴歸**:main_draw 4 mesh(v2 strip)全 `overall_pass` 不變;v1 fallback IoU 反而更好
   (shadow 0.904→0.998、curtain 0.980→0.995);切圖閘全過。
   (`image/shadow2` slot 的 attachment 名為 `image/shadow` 共用 region → 驗證用 `--name image/shadow`。)

## 關鍵結論

- **端到端「PSD件→S3 mesh→對照真實生產藝術家 mesh」對第二份真實標的(Award 3 件)IoU 全過基準(里程碑)**。
- **S3 覆蓋率已在兩種拓樸 regime 驗證**:直條(v2 strip)與 面/環狀(v1 Delaunay@eps0.002)。

  端到端「可綁骨的件」需 S5 骨架 + 權重(計畫最卡 pivot 環節)。
