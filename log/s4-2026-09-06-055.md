# S4 chunk 55(2026-09-06)— 對 `skirt` 測點提示,正面結果

## 動機

chunk54 用 chunk53 定案決策檔重跑 `--contour sam`,發現 `skirt` 是全新的靜默錯誤
(框正確,但 SAM 選到皮膚而非裙擺紅布主體),heuristic 未攔截。chunk54 明確在「下一步
候選」把它跟已測 4 次點提示無效的 `bodice`/`sleeve_right` 分開,標註「材質/重疊模式
不同,值得獨立測試而非直接假設無效」。本次執行這個候選。

## 做了什麼

1. 重裝環境依賴(容器不持久化,沿用 chunk54 記錄的可重現指令):`curl` 抓 MobileSAM
   權重(sha256 核對通過)、`git clone` MobileSAM 原始碼到 `/tmp/mobilesam_src`、
   `pip install torch timm`(走預設 PyPI index,同 chunk54 記錄的路徑)。
2. 寫一次性驗證腳本 `tools/mesh_gen/s4_data/chunk55/point_prompt_test.py`(比照
   chunk48「先在 Python 層驗證再蓋 UI」的做法,不碰 production 代碼)。
3. **先重現 baseline 失敗**:用 `skirt` 的框(`bbox_px=[156,359,327,548]`,來自
   chunk53 `decision_final.json`)純 box-prompted 跑一次,`fg_ratio_in_box=0.1964`,
   跟 chunk54 原始記錄的 `0.20` 一致,確認腳本設定正確、能重現問題(見
   `tools/mesh_gen/s4_data/chunk55/skirt_box_only.png`,紅色疊圖蓋在大腿皮膚上)。
4. 用網格疊圖工具(`step=20px`)放大框內容,目視確認裙擺紅布主體(含金色刺繡紋樣)
   實際座標(約 x=220~320, y=380~460)、皮膚位置(約 y=470~540 大腿,以及左側手部)。
5. 測 5 種點提示組合:
   - `pos_only`(2 正向點,裙擺布料)→ 成功,`fg_ratio=0.445`,`n_components=1`,
     `largest_component_frac=1.0`,視覺確認乾淨裙擺輪廓。
   - `pos_neg`(2 正向 + 2 負向,皮膚/手)→ 成功,`fg_ratio=0.459`,主體同上,
     多出微小碎片(`n_components=3` 但 `largest_component_frac=0.998`)。
   - `single_pt_A`/`single_pt_B`/`single_pt_C`(3 種不同座標的單一正向點,不加負向點)
     → **全部成功**,`fg_ratio` 落在 0.448~0.457,`n_components=1`,
     `largest_component_frac=1.0`。對 `single_pt_B`/`single_pt_C` 額外存疊圖視覺
     確認(非只看數字)。

## 結果

5/5 點提示組合全部成功選出乾淨、單一連通元件的裙擺紅布輪廓,不需要負向點,單一正向點
即足夠。跟 chunk48 對 `bodice`/`sleeve_right` 測 4 次(正向點、正向+負向點組合)全部
失敗的結果**方向相反**——證實 chunk54 的判斷是對的,`skirt` 是不同的失敗病因。

**方法論結論**:「框正確、SAM選錯鄰居內容」這個表面症狀底下,至少有兩種不同的根本
原因,不能只看症狀就預判點提示有沒有用:

- `bodice`/`sleeve_right` 型:候選物件(髮絲/胸衣;胸衣/袖子)在模型的特徵空間裡離得
  很近,點提示提供的方向性訊息不足以扭轉判斷。
- `skirt` 型:候選物件(裙擺布料/皮膚)特徵空間差異夠大,純 box prompt 缺乏方向性
  訊息時模型選錯,加一個點就足以扭轉。

需要逐案實測才能知道屬於哪一種。

## 誠實限制 / 未做的事

  `bbox_xyxy`,不支援點提示參數。這次驗證證明點提示對 `skirt` 有價值,但要讓它真正
  解決 production pipeline 裡的 `skirt` 案例,需要:(1) decision JSON schema 加輔助
  點欄位、(2) `s4_decompose_assist.html` 加互動點選 UI(chunk48 當時因驗證失敗而
  撤掉的功能骨架,這次是正面結果,補做有意義了)、(3) `s4_decompose_cut.py` 接線讀取
  決策檔的點資訊傳給 `SamSegmenter`。都還沒做,留給下一次排程。
- 未對 `hair_front`(語意邊界問題,非候選選錯問題)測點提示,判斷不適用,故意跳過。
- 只測 3 種單一正向點座標變體 + 1 組正負點組合,沒做更大規模座標敏感度掃描——5/5
  一致已是足夠訊號,邊際報酬遞減。
