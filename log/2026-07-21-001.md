# 2026-07-21 — session 001

## 這次做了什麼(S3×S4 端到端:PSD 件 → 生成 mesh vs Award 真實生產 mesh)

接手 STATE.md「下一步動作」最高優先塊:把 S3(mesh 生成)與 S4(PSD 切圖)串成端到端,
並對**真實生產標的**(`Award.json` 的機器人 mesh)驗收。純 CPU 可自驅。

1. **定位真值**:Award 有 5 個 `機器人拆件/*` slot,其中 **3 個是 mesh**(光暈 78v/hull78、身體 98v/hull40、
   左手 80v/hull42),另 2 個(右手/頭)是 region。這 3 個 mesh 就是藝術家真值。
2. **切件**:`psd_slice` 切 `robot_parts.psd` → 5 件 PNG(件尺寸與 Award mesh 尺寸差 +2px padding,吻合)。
3. **新工具 `tools/mesh_gen/validate_psd_to_mesh.py`**:每件 → `generate_mesh_v2`(auto) → 對照 Award 真實 mesh
   在**同一切件 alpha 上重建三角求 IoU**(消除 +2px/offset 影響)。AC = 覆蓋(gen ≥ artist−0.02)+ 預算
   (gen_v ≤ artist_v×1.5)+ 靜態拓樸乾淨。
4. **關鍵稽核**:5 個 `機器人拆件/*` slot 在 Award **12 動畫全部無 deform timeline**(骨骼驅動,mesh 不變形)。
   → 生產相關 AC 是「靜態覆蓋」而非「耐變形」;要求生成 mesh 比真實資產本身更耐變形是過度嚴格。
5. **deform 探針(informational)**:仍把 main_draw curtain 真實位移場轉移到生成 mesh 當「若被 warp」探針,
   並記錄強制 strip 的補救。

## 結果(3/3 生產 AC 過,exit 0)

| slot | 生成 v/hull/IoU | 藝術家 v/hull/IoU | AC |
|---|---|---|---|
| 光暈 | 35/16/**0.933** | 78/78/0.949 | ✅ |
| 身體 | 60/20/**0.966** | 98/40/0.948 | ✅ |
| 左手 | 59/19/**0.964** | 80/42/0.977 | ✅ |

- 覆蓋率不輸藝術家真值,且**頂點更精簡**(35/60/59 vs 78/98/80)。
- **deform 探針**:光暈/身體 auto(v1)乾淨;**左手 auto(v1)大拉伸自交 si=10**,**強制 strip 則乾淨(si=0 @30v)**。

## 關鍵結論

- **里程碑:端到端「PSD → 件 → S3 mesh」首次對真實生產標的驗收通過**,S3×S4 串接成立。
- **真實生產慣例校準**:機器人拆件靠骨骼動、mesh 無 deform → 端到端閘的正確 bar 是靜態覆蓋+預算+拓樸。
- **改進候選(探針揭示)**:`generate_mesh_v2` auto 的 `aspect≥1.2` strip 門檻,會讓「近方形但會 warp」的件
  落回不耐變形的 v1(左手為例)。對本批件無影響(不 deform),但若件確定要變形應由上游指定 mode=strip。
