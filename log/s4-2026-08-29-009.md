# 2026-08-29 — S4 session 009(候選 8:1b `tone_gap` 在新材質上重新校準)

## 這次做了什麼

從 `STATE_S4.md` 候選清單挑了 #8(session 008 順帶發現:`Symbol_Ww.psd::框`/`臉部陰影`
的 1b 正對照 `tone_gap` 誤判 fail)推進。

### 先發現並修正一個真實 bug

追查 `框`(環形鏤空件)的異常時,發現 `punch_hole(mode="interior")` 在材質太薄、找不到
任何符合 margin(`r*1.15`)的候選圓心時,原本會**靜默退化成「隨便挑一個內容像素當圓心」**,
完全不保證洞真的落在內部,卻仍標成 `"interior"`。實測 `框.png` 的內部最大深度只有 7.0px,
但 `frac=0.12` 要求的洞半徑 margin 是 13.8px——原本的 fallback 因此偷偷產出一個貼/跨輪廓
的假 interior 洞,汙染了 session 008 對這個材質的異常發現。

**修正**:`punch_hole` 找不到候選點時先嘗試縮小洞去符合 `max_margin`;縮到底仍不足
(`max_margin<4.5px`)就明確 `raise ValueError`,不再偽造洞。`run_one()` catch 這個例外
記成 `{"skipped": true, "reason": ...}`,`calibration_check()` 對 skipped case 只記筆記
不算失敗——批次評測不再因單一材質太薄就整批 crash。

修正後 `框` 的洞半徑從 12→6(面積 4165px 級縮到 63px),`tone_gap` 從 81.75 降到 32.84
(仍壓線 fail,但已排除偽造洞的干擾——這個殘餘的壓線 fail 判斷是內部深度太淺、樣本量太小
導致統計噪聲,不是材質真的有問題)。

**回歸驗證**(AC:原本已校準的材質不能變):
- `inpaint_eval.py` 對原 3 個機器人件(光暈/身體/左手,interior+edge)重跑:
  `calibration.pass=True`,數字與 session 008 完全一致。
- `psd_inplace_patch.py assets/robot_parts.psd 身體 --method cv2_ns --mode interior --eval`:
  `overall_pass:true`,無回歸。
- `psd_inplace_patch.py assets/robot_parts.psd 左手 --auto --mode edge --eval`:
  `reveal_1a_score_of_chosen.alpha_mae=2.978`,與 log 008 記錄的數字一致。
- 額外構造一個比 `框` 更薄的合成環(厚度 3px)驗證 `punch_hole` 正確拋錯、CLI 正確把該
  case 標 skipped 且不影響其他 case 的評測與 `calibration.pass`。

### 對真正殘留案例(`臉部陰影`)的調查

`臉部陰影`(87×36,柔和放射狀陰影)**本來就有合法的 interior 候選點**,不是上面那個
bug 造成的——它的高 `tone_gap`(57.30 vs 門檻 28.0)是材質本身在 `width` 尺度上局部色調
變化大所致,不需要真的有接縫。

嘗試兩種正規化想讓 `tone_gap` 變成跟材質無關的比值(`tone_ratio`):

1. **位置比對取樣基準**:在材質其他位置放同尺寸假洞算「材質本來的色差」當 baseline。
   `框` 找不到足夠不重疊的候選位置(0 個有效樣本);`臉部陰影` 只有 2 個有效樣本,
   gt/none/random 算出的 ratio 幾乎相同(0.75/0.94/0.76)——樣本量不足,無鑑別力。
2. **局部色調粗糙度基準**:不需要跟洞同形狀取樣,量測材質在 `width` 尺度的局部高通能量
   當 baseline。跨 5 個材質(光暈/身體/左手/框[已修正]/臉部陰影)量出 `tone_ratio`:

   | 材質 | gt ratio | none ratio | random ratio |
   |---|---|---|---|
   | 光暈 | 0.020 | 24.21 | 9.74 |
   | 身體 | 0.083 | 1.006 | 2.805 |
   | 左手 | 0.076 | 1.884 | **0.852** |
   | 框 | 0.600 | 1.689 | 0.577 |
   | 臉部陰影 | **0.747** | 0.940 | 0.760 |

   **無法選出單一門檻同時滿足**:讓 `臉部陰影` 的 gt(0.747)通過、又讓 `左手` 的
   random(0.852)不通過——這兩個要求互斥。`框` 的 gt(0.600)跟 random(0.577)幾乎相等,
   任何門檻都無法讓它同時「gt 過、random 不過」。

**結論(誠實界定,不強行修正)**:`tone_gap`(不論原始值或這兩種正規化)無法用單一全域
門檻跨材質可攜——不是門檻沒調好,是 `框`/`臉部陰影` 這類材質在這個特徵維度上,gt 與
random 的分布本身就重疊,沒有統計上的可分性。程式碼**維持原本絕對門檻不變**(在機器人
拆件材質家族內仍可信、無回歸),不塞入會製造假信心的全域正規化。`tone_gap`/1b 目前的
可信範圍僅限機器人拆件這類材質家族;要在新材質家族上信任 1b,需要對那個家族重新跑
`calibration_check` 才能決定門檻是否可用。對 `框`/`臉部陰影` 這類材質,唯一還可靠的
1b 信號剩 `alpha_gap`(跨全部材質 100% 抓到「洞未補」);真正需要驗證補圖品質時應優先
考慮候選 1(遮擋真值法)拿真實 1a 比對。
