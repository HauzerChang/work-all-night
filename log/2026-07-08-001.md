# 2026-07-08 — session 001

## 這次做了什麼(S3+S4 端到端:PSD件 → 生成 mesh → 對照 Award 真實 mesh)

推進 STATE 的**最高優先 bounded chunk #1**:用 `robot_parts.psd` 的 3 個 mesh 件對真實生產標的
(Award spine `機器人拆件/*`)驗收「PSD→件→mesh」。

1. **前置探查**:確認 Award 中 光暈/左手/身體 是 mesh(右手/頭是 region);且這 3 mesh 在**全部 12 支
   動畫皆無 deform timeline** → 定調此驗收為**靜態**(耐變形無真值可比,誠實標記)。
2. **寫端到端閘 `compare_award_mesh.py`**:psd_slice 切件 → generate_mesh_v2(auto)→ 三條靜態 AC
   (覆蓋率 IoU vs 藝術家基準 margin 0.03 / nv≤64 / 0 自交 0 退化)。藝術家基準用 Award 真實 mesh 對其
   atlas region alpha 的覆蓋率(uvs region-local;`atlas_crop.extract` 自動找 Award2.png 頁 + derotate)。
3. **初測 2/3 過**:左手/身體 過;**光暈 fail**(IoU 0.933 < 基準 0.980)。查因:光暈是 halo 柔邊、
   邊界主導,藝術家用 **78 全 hull 點**密描;v1 固定 epsilon=0.008 只描 16 hull 點 → 覆蓋不足。
4. **epsilon 掃描 → 修法**:eps=0.002 時 nv=64(剛好預算)、IoU 0.9796 ≥ 基準且 0 自交。發現「邊界複雜度
   因件而異,單一 epsilon 不通用」→ 改 `generate_mesh_v2.gen_delaunay_adaptive()`:沿 epsilon 階梯由粗到細,
   取「nv≤budget 內 IoU 最高」。光暈自動選 eps=0.002 過關;手/身體維持 0.008。
5. **回歸驗證**:main_draw 4 mesh(全 strip 分支)`validate_against_real --gen v2` 不受影響、仍全過
   (shadow2 共用 shadow region,名稱為既有資產細節非回歸)。**三件端到端 overall_pass,exit 0。**

## 關鍵結論

- **S3+S4 端到端對真實生產 mesh 靜態驗收通過**(里程碑):切件→生成 mesh 的覆蓋率/預算/良構貼近藝術家。
- **通用性修復**:delaunay 覆蓋率槓桿 = hull 邊界取樣密度(epsilon);與 strip「IoU 由 rows 決定」同理。
  固定值不通用 → 預算內自適應加密才對柔邊/環狀件通用。
- **誠實邊界**:真實標的無 deform → 不宣稱此處驗過耐變形(耐變形已在 main_draw 4 mesh 驗過)。
