# 2026-07-07 — session 001

## 這次做了什麼(S3×S4 端到端:PSD件 → 生成 mesh → 對照 Award 真實 mesh)

接 STATE.md 最高優先 chunk(候選 1)。把 S4(PSD 切件)與 S3(mesh 生成)串成端到端,
並對**真實生產 spine(Award)的 mesh** 做覆蓋率對照。純 CPU、可自驅、有 ground truth。

1. **Frame 驗證(前置)**:把 Award mesh `uvs` 直接疊到 PSD 切件 alpha 上量覆蓋率 —
   as-is IoU 0.95/0.95/0.98、v-flip 0.43/0.60/0.59 → 證實 Spine JSON mesh `uvs`=**region-local [0,1]**
   (非整頁 atlas UV、不需翻 v);PSD 切件 = spine mesh 素材、同朝向。
2. **跑 S3 生成 + 對照**:3 個 mesh 件(光暈/身體/左手)。`generate_mesh_v2(auto)` 對這些 blobby 件
   全部正確回退 v1 Delaunay(strip 只適直條件)。
3. **關鍵參數發現**:v1 覆蓋率由 **`epsilon_frac`(hull 簡化)** 決定 —— 舊預設 0.008 對 ~700px 大件太粗
   (hull 只 16~19 點,IoU 略低於藝術家)。掃描後 **eps=0.003 → 3 件覆蓋率全 ≥ 藝術家**且頂點更精簡。
4. **拓樸 + 負對照**:生成 mesh 基礎拓樸乾淨(setup 0 自交/0 退化);跨件負對照(生成 mesh 疊錯件 alpha)
   對角 0.97~0.99 vs 非對角 0.48~0.58 → 閘有鑑別力。
5. **產工具** `validate_psd_mesh.py`:PSD → 切件 → 對 mesh 件生成+驗(IoU vs 藝術家 / 拓樸 / 頂點預算),
   `overall_pass=True`。

## 關鍵結論 / 決策

- **S3+S4 端到端對真實生產 mesh 驗收通過**:生成 mesh 覆蓋率 ≥ 藝術家、頂點更少、拓樸乾淨。
- **`epsilon_frac` 是 v1 的覆蓋率旋鈕**(對應 strip 的 rows);件尺寸變大時要調小,0.003 是甜蜜點。
- **限制**:這 3 件在 Award 是 **weighted mesh 且無 deform timeline**,故本閘只量靜態覆蓋率+基礎拓樸,
  未套 transfer_deform_check;真正替換走骨骼變形需 S5 綁 BBW 權重(下一道關)。
