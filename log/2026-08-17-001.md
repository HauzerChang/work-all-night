# 2026-08-17 — session 001

## 這次做了什麼(S3+S4 端到端:PSD 機器人件 → generate_mesh_v2 → 對照 Award 真實 mesh)

依 STATE 下一步 #1(最高優先、有真值、純 CPU 可自驅),把 S3 mesh 生成器對**真實生產標的**
做端到端驗收:`robot_parts.psd` 的 3 件(光暈/左手/身體)在 Award spine 中是 mesh,用 Award 真實
atlas 貼圖切件為 alpha 來源,跑 v2 生成 mesh,與 Award 藝術家 mesh 做 IoU + 頂點預算對照。

### AC(先定)
- ① IoU_gen ≥ IoU_artist(覆蓋率不低於藝術家自身 mesh)。
- ② 頂點數 ≤ 藝術家頂點數 ×1.1(精簡度相當)。
- deform 閘:先查 Award 是否有這些件的 deform timeline。

### 過程 / 發現
1. **查真值**:Award 3 件皆 **weighted mesh**(uv 78/80/98 頂點),**無任何 deform timeline** →
   確認靠加權骨骼驅動 warp(呼應 log 005)。故 deform 閘對這 3 件 **N/A**,硬跑 `real_deform_field`
   會拿到零位移的**假性乾淨** → 誠實標 N/A,不 vacuous pass。
2. **首測即現缺陷**:v2 auto 對這些圓潤/寬扁件走 **delaunay 回退**(非 strip);固定
   `epsilon_frac=0.008` 的 Douglas-Peucker 對真實**羽化軟邊 under-cover**,IoU 低於藝術家
   (光暈 0.929<0.980,左手/身體亦低)→ 3 件全 fail。合成 fixture 是硬邊,又一次掩蓋真實問題。
3. **修法(asset-independent)**:`boundary_points` 加 `cover_target` —— 從 epsilon 起 ×0.8 縮小,
   直到 hull 多邊形填滿 ≥ target×mask 面積。掃描確認 **0.99** 是甜蜜點(3 件 IoU 全過藝術家、
   頂點全 ≤ 藝術家;0.995 會讓光暈灌到 104 頂點過頭)。v2 delaunay 回退設 0.99。
4. **自我驗證**:`validate_robot_parts.py` → 3 件 overall_pass=true;靜態評估器拓樸全乾淨
   (0 退化 / 0 孤兒 / centroid 1.0)。**回歸**:4 個 main_draw mesh 全走 strip,`validate_against_real
   --gen v2` 重驗全 overall_pass → 無回歸。

## 關鍵結論
- **S3+S4 端到端對真實生產 mesh 驗收通過(里程碑)**:PSD件→生成 mesh 的覆蓋率與精簡度 ≥ 藝術家手做。
- **教訓再現**:「合成通過、真實才現形」—— delaunay 固定 epsilon 缺陷只在真實羽化件曝光。修法用
  「覆蓋率當旋鈕」而非硬編 epsilon,避免 overfit 單一 asset。
- **變形閘缺口**:無 deform timeline 的骨骼驅動件,現有 deform 閘量不到 → 列為下一課題(需 bone transform)。
- 靜態評估器 `vertex_budget=64` 是合成期預設,真實件本身就 >64,對照應以藝術家頂點數為準。
