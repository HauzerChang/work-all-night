## 這次做了什麼(S3 對真實生產 mesh 端到端驗收 — 里程碑)

推進 STATE 最高優先 bounded chunk:**PSD 件 → S3 mesh → 對照 Award 真實 mesh**(有真值、純 CPU)。

1. **定位標的**:Award.json 機器人 3 件是**手做 weighted mesh** —
   光暈(nv78/hull78)、身體(98/40)、左手(80/42)。PSD 圖層 ⇄ atlas region ⇄ Award slot 三方對應確認。
2. **AC(可機讀)**:自動 mesh coverage IoU **≥ 藝術家 mesh 覆蓋率**(相對閘,沿用 validate_against_real 邏輯),
   且 setup 內在拓樸乾淨,且 PSD→mesh ≡ atlas→mesh。
3. **新工具** `tools/mesh_gen/compare_award_mesh.py`:三條腿(A 覆蓋率 vs 藝術家、B PSD↔atlas 輪廓、
   C PSD-mesh vs atlas-mesh),reuse atlas_crop/evaluate_mesh/generate_mesh_v2/artist_iou。
4. **自我驗證迴圈抓修 2 個問題**:
   - **假性失敗**:初跑 3 件都略低於藝術家 baseline(gap 0.008~0.05)。掃 epsilon_frac 發現
     **coverage IoU 由 hull 邊界密度決定**;舊預設 0.008(為 main_draw 簡單形調)對有機件取樣不足。
     降到 **0.002 三件全過**,且頂點 nv(73/77/67)**仍 ≤ 藝術家(78/98/80)**。
   - **閘 bug**:leg B 身體件輪廓 IoU 只有 0.62(與先前 0.92~0.99 矛盾)→ 查出是 atlas region 有透明
     padding、我沒把兩來源各自裁到 alpha bbox 就配準。修正後身體 0.62→0.95,三件 0.91~0.97 一致。
5. **零回歸驗證**:`generate_mesh_v2.generate` 新增 `eps=None`(預設沿用舊 0.008);main_draw
   curtain_left/right + shadow 整合 AC 全 overall_pass、deform 乾淨(shadow2 與 shadow 共用 region)。
6. **視覺確認**:`knowledge/figures/s3-award-mesh-compare.png`(橙=生成/綠=藝術家 疊同一 alpha)。

## 關鍵結論 / 決策

- **里程碑**:S3 首次對「有真值的真實生產標的」閉環 — 自動 mesh 覆蓋輪廓 **≥ 出貨藝術家 mesh**,
  頂點更省;S3(mesh 生成)+ S4(PSD 切圖)端到端串通(靜態部分)。
- **可重用洞見**:覆蓋率的樞紐永遠是**邊界取樣密度**(strip 是 rows、Delaunay 是 epsilon),
  內部點只影響三角化不影響覆蓋。
- **誠實界定限制**:Award 3 件是 weighted mesh,`real_deform_field` 只支援 unweighted →
  **真實 deform 轉移閘對 Award 件尚未做**。已明確列為下一 chunk(需 weighted 世界座標重現器)。
