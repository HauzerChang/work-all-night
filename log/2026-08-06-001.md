## 這次做了什麼(S3 端到端對照真實生產標的:Award 機器人 mesh)

推進 STATE 的「❗最高優先」候選:atlas 件 → `generate_mesh_v2` → 對照 Award big win
機器人 3 件真實藝術家 mesh(光暈/身體/左手,Award 中為 weighted mesh)。

1. **偵察**:Award 3 件為 weighted mesh、**無 deform timeline**(靠骨骼蒙皮動)→ 與 main_draw
   窗簾(unweighted+deform)不同,故本輪只做**靜態 IoU 對照**(變形需先做權重轉移)。
2. **確認 uv 映射**:Award mesh uvs 是 **region-local 0..1**(不是整頁 UV);`(u*cropW, v*cropH)`
   直接命中 `atlas_crop.extract` derotate crop → 藝術家 mesh 對自身 alpha IoU 0.967~0.972(自檢通過)。
3. **量測**:v2 auto 正確把 3 件路由到 delaunay(非 strip)。預設 eps=0.008 時光暈 IoU 0.929 <<
   藝術家 0.971 → 追因是**圓弧邊界取樣太稀**(hull 僅 14 點)。掃 eps:0.004→0.966 / 0.002→0.983 /
   0.001→0.992。**eps=0.003 為甜蜜點**:3 件全勝藝術家、頂點反而更少。
4. **修正**:`generate_mesh_v2.generate` delaunay fallback 加 `eps` 參數,預設 **0.003**(+CLI `--eps`)。
5. **新驗證器**:`validate_robot_mesh.py`(atlas 件→生成→對照 Award 藝術家 mesh,含映射自檢)。
6. **回歸**:窗簾走 strip 不受 eps 影響 → main_draw 4 mesh(curtain_left/right/shadow)validate 全 PASS(mode=strip, si=0)。

## 關鍵結論 / 教訓

- **S3 對非窗簾真實生產標的通用**:靜態輪廓吻合全達/超藝術家水準,頂點更精簡。
- **邊界 epsilon 主宰圓弧覆蓋**:圓/軟邊件的短板是 hull 取樣密度,不是拓樸選擇(auto 路由正確)。
- **誠實界線**:只驗靜態,沒驗變形(件為 weighted、生成 mesh 無權重)。變形對照需先做權重轉移。
