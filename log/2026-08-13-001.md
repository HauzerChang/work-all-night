# 2026-08-13 — session 001

## 這次做了什麼（S3 端到端：件 → 生成 mesh → 對照 Award 真實生產 mesh）

推進 STATE 最高優先候選 #1：用 Award 的 3 個真實 weighted mesh 件(`機器人拆件/{光暈,左手,身體}`)
當**外部真值**,驗收 `generate_mesh_v2` 的靜態覆蓋率。純 CPU、可自驅。

### AC（動手前定的可檢查目標）
- 對 3 件各自:生成 mesh 的覆蓋率 IoU ≥ 藝術家真實 mesh 的覆蓋率 IoU(對齊藝術家,非武斷 0.95)。
- 評估器先過**校準閘**:藝術家 mesh 對自身 alpha 的 IoU 要高(≥0.85),否則判定不可信。

### 過程與自我驗證
1. 寫 `tools/mesh_gen/award_mesh_compare.py`:atlas 取件直立 crop(alpha=共同畫布)→ 藝術家 uvs
   raster 得覆蓋遮罩(自 IoU 校準)→ `generate_mesh_v2` 生成 → `evaluate` 得 gen IoU → 判定。
2. **抓到並修正一個評估器 miscalibration(第四次)**:初版沿用 session-006 log「Award uvs 為 atlas-UV」
   去做 sheet-fill+去旋轉,得到藝術家自 IoU 0.0~0.49(明顯壞掉)。實測 8 種翻轉/旋轉組合後發現
   **uvs 其實是 region-local、對應去旋轉後直立影像**;最單純的 `u*Wc,v*Hc` 自 IoU=0.968~0.980(唯一高分)。
   → 修正 artist mask 為 direct;**同時獨立佐證 session-006 的 CW 去旋轉**(第二條證據)。
3. 校準後首輪:default eps=0.008 → gen 落後藝術家 0.008(左手/身體)~0.050(光暈,羽化邊)。
4. Sweep 定位:覆蓋率由 **hull 密度(epsilon_frac)** 主導,`max_interior` 幾乎不影響;eps=0.002 三件全達標。
5. **改成自我精修(不硬塞常數)**:`generate_mesh.generate(target_iou=...)` 用評估器量自身覆蓋率、
   未達標就 ×0.6 降 epsilon 加密邊界(opt-in);`generate_mesh_v2` blob fallback 預設 target_iou=0.98。
6. 回歸:main_draw 4 mesh(strip 路徑)全 overall_pass 不受影響;v1 預設(無 target_iou)curtain_left 仍 0.9796;slicing 閘 pass。
