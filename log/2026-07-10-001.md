## 這次做了什麼(S3×S4 端到端:PSD件→mesh→對照 Award 真實 mesh)

推進 STATE.md 最高優先 bounded chunk #1:把 S4(PSD 切件)與 S3(mesh 生成)串成端到端,
並對**真實生產標的**(Award spine 的機器人 mesh 件)驗收。

1. **AC 先定**:生成 mesh 覆蓋率 IoU >= 藝術家真實 mesh baseline - 0.02、格式合法、
   0 退化/孤兒、setup-pose 0 靜態自交、頂點在預算內。(不靠肉眼)
2. **切件**:`psd_slice.py assets/robot_parts.psd` → 5 件(光暈/右手/頭/身體/左手);
   其中光暈/身體/左手在 Award 為 mesh。
3. **實測校正**:Award 這 3 件 mesh uvs 範圍近 [0,1](光暈 x[0.012,0.99] 等)→ 確認是
   **region-local**,非先前 knowledge 註記的 atlas-global;直接 `uv×件W,H` 即得件像素框。
   另確認這 3 件是 **weighted mesh、無 deform timeline**(骨骼權重驅動)→ 本閘不跑 deform 轉移。
4. **新工具 `validate_psd_to_award.py`**:件 alpha → generate_mesh_v2(auto→v1 Delaunay,
   3 件 aspect<1.2)→ 覆蓋率 IoU(生成/藝術家)+ mesh↔mesh IoU + 格式 + 靜態自交。
5. **結果全 PASS**:光暈 0.933/0.949、身體 0.966/0.948(勝)、左手 0.964/0.977;
   mesh↔mesh 0.918/0.928/0.957;頂點 35/60/59 < 藝術家 78/98/80;0 自交/退化/孤兒。
6. **負對照**(評估器可信度):mesh↔mesh IoU 交叉矩陣對角 0.92–0.96 vs 錯配 0.49–0.59 → 鑑別力清楚。
7. **視覺**:`knowledge/figures/psd-to-award-mesh-overlay.png`(blue 生成 / red 藝術家,同 silhouette)。
