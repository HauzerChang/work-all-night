## 產出的知識(詳見 `knowledge/s4-gptfill-plugin-knowledge.md`)

四項對 S4 有實質影響的收穫:

1. **mask 慣例外部真值**(我們一直沒有基準的東西):重建型補圖的洞 dilate **8px** 當融合邊界
   (`REPAIR_MASK_DILATE`);移除物件時把被移除件 footprint dilate **24px** 併入遮罩讓陰影能
   重建(`REMOVED_SHADOW_DILATE`);任務模式自動判定門檻 = 選區內透明占比 **≥30%**
   (`REPAIR_HOLE_THRESHOLD`);mask 編碼是 `alpha = 255 - selection`(**透明=可編輯**)。
   我們的 `punch_hole` 從來沒有「洞」與「融合邊界」分離的概念。
2. 🔥 **揭露我們一個沒意識到的方法論限制**:插件給重建模式的上下文**下限 512px**
   (`REPAIR_MIN_CONTEXT`,pad = 選區 1.2 倍、160~1600),而我們的補圖閘從頭到尾只吃
   **單一圖層裁切、零周圍上下文**。「1a 對機械紋理材質全 fail」這個貫穿 S4 的核心結論,
   是在「只看單層」條件下量出來的 → **候選 19**(純 CPU、零成本、可能收窄或推翻既有結論,
   建議下一個 chunk 就做)。
3. ⚠️ **生成結果不會像素對位**——這是我們完全沒處理過的一整類問題。插件為此做了五層對位:
   全域平移(`DRIFT_RADIUS=10`)、全域縮放(±5%/step 0.5%)、8 錨點 IDW 局部位移場
   (`ANCHOR_WINDOW=48`/`ANCHOR_SEARCH=4`,權重 `1/(d²+400)`)、拋物線次像素、以及
   **「改善不夠顯著就不套用」的接受門檻**(平移 ≤92%、縮放 ≤90% 且 ≤97%、錨點 ≤97% of
   zero-shift SAD)。全部在梯度圖上比 SAD,且**只用選區外 24px 環狀帶**當比對區。
   我們 `psd_inplace_patch.py` 的「補出來的像素就地落在 mask 原位」假設,一接生成路徑就破
   → 這是候選 17 真正的工程主體,不是呼叫 API 那一行。
4. ★ **獨立來源佐證 chunk 18(候選 7)的發現**:插件 prompt 的 SHADOW REASONING 明確禁止
   「flat, uniformly-lit color」填補,理由寫得很直接:「亮度與它的暗邊界不匹配的填補看起來
   就是貼上去的,是錯的」。這與我上一個 chunk 用 vision 發現的「CPU baseline 產出奶油糊、
   丟失邊界證據所暗示的結構明暗」**完全同構**——兩個完全獨立的來源(prompt 工程實戰 vs
   我們的視覺自評)指向同一失真維度。故候選 16 的指標方向**從籠統的「高頻細節保留度」
   具體化為「邊界證據延續性」**(量洞內亮度/梯度場是否延續邊界暗邊暗示的陰影方向與衰減)
   → 候選 18。

另外三項「外部獨立收斂到本 repo 既有做法」的佐證(不改變結論,但提升信心):插件在有 alpha 時
用 **premultiplied 加權再除回** 做插值(我們踩過三次 miscalibration 才定下 premultiplied 比對);
多候選用**便宜的幾何代理指標**(對位品質 SAD/n)盲選而非「哪個好看」(對應我們 `select_best`
用 `seam_ratio`);v1.18 的 `GPT •` 圖層守衛是**防自我輸出污染自我評估**(我們踩過同型的
「edge 模式套 interior 校準」,靠 `applicable` 旗標修掉)。
