G-4'''' 的 `gen_squash` 產出面積守恆的 squash 對(scaleX=1+q、scaleY=1/(1+q)),但舊檔位幅度增益
`_amp_scale` 只放大 identity **上方**(拉長軸放大、壓縮軸樓地板不動)→ 對 squash 會破壞 `scaleX·scaleY==1`,

## 做了什麼(全 additive,coupled 預設 False → 向後相容逐位元不變)

1. **`tier_variants._amp_scale_coupled(x, y, g)`**(新):squash 對是面積守恆對(一軸拉長≥1、一軸壓縮≤1、
   積=1)。放大**拉長軸** overshoot(同 `_amp_scale`:`x'=1+g(x−1)`),壓縮軸**重算為其倒數**(`y'=1/x'`)
   → `x'·y'≡1` 對所有檔位保持。identity 幀(x==y==1)→ 仍 identity。對稱認軸(拉長軸=較大者)為未來
   雙軸 squash / shearY 預留。**關鍵:放大守恆結構的不變量 q(q→g·q),非各軸獨立放大。**
2. **`amplify_bone_tl(b, g, coupled=False)`** / **`amplify_anim(anim, g, coupled=False)`**:coupled=True 時
   scale 走 `_amp_scale_coupled`;**預設 False → 逐位元同舊行為**(hit/combo/… 獨立雙軸 scale 不變)。
   shear/rotate/translate 與 coupled 無關(仍 g*v)。

4. **`gen_animations.build_animations`**:tier 迴圈 `coupled = cat in COUPLED_SCALE_CATS`,傳給 `_amplify_anim`。

   combo)—— 直接證 nhits 不觸及非-combo beat,更強且不受幅度成長擾動。

## 決策 / 關鍵發現

- **守恆量的檔位差異化必須放大守恆結構的自由參數,不能各軸獨立放大**。squash 對由單一 q 參數化,`q→g·q`
  保守恆;各軸獨立套 `_amp_scale`(拉長軸放大、壓縮軸樓地板不動)Legend 檔破壞達 15%。這是**「守恆不變量
  的檔位差異化」通則**首例,對後續任何守恆/等長/不可壓縮運動基元皆適用。
- **shear 峰(g*v)與非均勻幅度(耦合 q)兩通道正交放大**:同一 g 同時放大 shear(對 0 對稱)與 squash
  (守恆耦合),兩簽章各自保形。續 G-4''(wobble shear 峰接檔位)再證「檔位機制就緒 ≠ 每個新通道/守恆結構接上」。
- **加 squash 為 main-show 暴露 K5c 的脆弱 proxy**:impact-峰數作為 count-隔離 proxy 會被「幅度隨檔位跨越
  峰門檻」誤判。改為本質比對(full==amp_only)—— 測「nhits 是否觸及非-combo beat」的**真正性質**,更強且不受
  幅度成長干擾。這是 J 閘 J3 改 channel-aware(G-4'')之後,又一次「新通道逼閘從 proxy 升級到本質」。
