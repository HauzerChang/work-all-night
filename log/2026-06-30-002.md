## 這次做了什麼（SkelToJson：件→可載入 Spine 資產集，S3+S4 端到端串接）

接 STATE 候選 #2（上一塊完成後升為最高優先）：把已對真實生產檔（Award）驗證過的慣例固化成
寫出工具，端到端產出「PSD→件→(S3 mesh)→可載入 Spine JSON」。

1. **新工具 `tools/mesh_gen/skel_to_json.py`**：吃 `psd_slice` 的 manifest（各件 PNG + offset/size/z）
   → 產 `<name>.json + .atlas + .png` 整組。
2. **固化慣例**（全來自 Award 真值）：
   - slot=attachment=region = `<PSD檔名>/<圖層名>`；
   - 一件 → 一 slot → 一 bone（置於件中心，PSD y-down→Spine y-up 換算）→ attachment 置中；
   - draw order = PSD z；`--mesh <圖層名>` 的件走 S3 `generate_mesh_v2(auto)`，其餘 region；
   - skin array 形式、`spine:3.8.99`。
3. **atlas 打包**：簡單 shelf packer + 2px gap（=padding）、**無旋轉/無縮放、無損**；PIL 合成 sheet PNG。
   （生產 packer 的 ~0.70 縮放/旋轉是省記憶體細節、非正確性所需 → 從略，保持件尺寸自洽。）
4. **5 條自驗 AC**（`--verify`）：AC0 結構完整性（slot.bone 存在、mesh 三角索引在界內、長度整除）、
   AC1 結構/命名、AC2 attachment 尺寸==件、AC3 atlas region 對應、**AC4 端到端 round-trip**
   （從產出 atlas+png 切回各件 alpha-IoU vs 原件）。
5. **驗證**：robot_parts（5 件，光暈/身體/左手=mesh）+ Symbol_Ww（18 件，region-only）
   → **兩份真實 PSD 全 5 AC 過，min round-trip IoU = 1.0（無損）**。

## 關鍵結論 / 教訓

- S3（mesh）+ S4（切圖/PSD 契約）至此**串成端到端**：PSD → 件 → (S3 mesh) → 結構正確、可載入的 Spine JSON。
- **自洽的尺寸選擇**：attachment width/height = 真實件尺寸、atlas region 與之吻合、padding 放在 atlas gap
  → 比硬模仿 Award 的 +2px/0.70 更簡單且端到端無損。
- **誠實範圍**：產出是**中性骨架**（每件一根置中 bone、unweighted mesh、region rotation=0、無動畫）——
  「位置正確、可載入、可檢視」的起點，非含骨骼動畫/權重的成品。配權（BBW）與骨架階層/pivot 屬 **S5**。
- 無法實機 spine-webgl 載入確認（CDN blocked）→ 以結構完整性 + 端到端 round-trip 替代。
