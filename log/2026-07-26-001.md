## 這次做了什麼(S3+S4 端到端:PSD 件 → S3 mesh 對真實生產 mesh 驗收)

推進 STATE 下一步 #1(最高優先、有真值可比)。`robot_parts.psd` 有 3 個 mesh 件
(光暈/身體/左手),在 Award 生產 spine 中為 weighted mesh,可做外部真值對照。

1. **新工具 `tools/mesh_gen/compare_robot_mesh.py`**:對每件 atlas 切 region alpha(CW derotate)
   → `generate_mesh_v2(auto)` 生成 → 量 IoU vs 藝術家 mesh 覆蓋率基準 + rest-pose 幾何(自交/翻面/索引)。
2. **首測光暈 FAIL**:固定 `epsilon_frac=0.008` 只給 14 hull 點 → IoU 0.929 < 藝術家 0.98。
   eps 掃描確認 IoU 受 hull 密度限制(eps 0.008→0.002:hull 14→38、IoU 0.929→0.983)。
3. **修法(非特例化)**:`generate_mesh.py` 新增 `auto_epsilon_frac()` —— 由 hull 多邊形填滿 IoU 驅動,
   逐步縮 eps 到覆蓋率達 0.985 或 hull 達 80。`generate()` 預設 `epsilon_frac="auto"`。
4. **重驗全過** + 產出對照圖 `knowledge/figures/robot_mesh_compare.png`。

## 結果

- **3 mesh 件 IoU 全超藝術家基準**:光暈 0.988(vs 0.980)、身體 0.987(vs 0.976)、左手 0.988(vs 0.968);
  rest-pose 0 自交/0 翻面/索引合法。**端到端「PSD→件→mesh」對真實標的驗收通過(里程碑)。**
- **無回歸**:4 main_draw mesh(curtain_left/right/shadow/shadow2)v2 strip 全 overall_pass、deform si=0。
  (auto-epsilon 只影響 v1 Delaunay 路徑;curtain/shadow 走 v2 strip 不受影響。)

## 關鍵發現 / 教訓

- **v1 邊界密度限制 = v2「IoU 由 rows 決定」在 v1 邊界上的對應**:大而平滑輪廓需更多 hull 點才貼合。
  coverage-targeted auto-epsilon 讓密度隨曲率自適應,取代武斷常數。
- **Award mesh uvs 為 region 局部 0..1**(可直接 ×region W,H),**修正 session 006 log「uvs 為 atlas UV」臆測**。
- 光暈藝術家 mesh 為純扇形(hull=頂點數、0 內部點)→ 生成器內部點對這類件冗餘(下步可加抑制啟發式)。
- 3 件在 Award 皆無 deform(靠骨骼)→ 本輪以 IoU + rest 幾何為 AC;deform 耐受已在 curtain/shadow 驗過。
