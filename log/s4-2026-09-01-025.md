# S4 chunk 25(2026-09-01)——候選16路徑(b)第三個案例:機器人拆件/光暈(第三種材質類型)

## 背景

承接 chunk 23/24(候選16路徑(b)前兩個案例 `左手`、`身體`,皆為機械紋理材質)。兩次的
「下一步」都列出同一個延伸方向:擴大到 `光暈`(平滑漸層材質,候選0/10 已知的「1a 補得動」
代表材質),補齊三種材質類型的覆蓋,並檢驗「量級是否真的更小」這個預期。本次做這個延伸。

## 做了什麼

`tools/mesh_gen/s4_award_screenshot_compare.py` 沿用既有通用工具,不改動任何 production
代碼,只換參數重跑:

```
python3 tools/mesh_gen/s4_award_screenshot_compare.py \
    --slot "機器人拆件/光暈" --att-name "機器人拆件/光暈" -o <scratch>/s4_out_glow
```

先用 `atlas_crop.parse_atlas` 確認 atlas 裡有 9 個含「光暈」字樣的 region,篩出真正對應
Award slot 的 `機器人拆件/光暈`(`Award2.png`,`rotate=true`,496×480,是本檔測過最大尺寸
的 region),並用 `assets/Award.json` 確認該 slot 綁在 `4_LEG` 骨頭,存在且非死 slot。

## 結果

- **1b 盲選**:`nearest` 勝出(`pass_1b`,`alpha_gap=0.0, seam_ratio=0.427, tone_gap=0.597`),
  與前兩案例同型。
- **零外洩驗證**:額外寫一段 Python(不改動 production 代碼,純驗證腳本)逐像素比對 11 個
  時間點的全場景截圖,確認所有差異像素(閾值>2)的實際 bbox 都落在該 slot 的 `screen_box_px`
  框內,0 外洩到其他 slot 或 `Award.png`/`Award2.png` 另一頁。
- **量級遠低於前兩案例**:材質完全出現後 `mae_0_255` 穩定在 0.01~0.04(對比 `左手`/`身體`
  的 0.9~1.05,低約兩個數量級);每幀差異像素數僅 52~83 px(對比框面積 3 萬多 px)。動畫
  剛開始 3 個時間點(`Award_Legend_In` t=0/0.233/0.367)`mae_0_255` 恰好 = 0(材質尚未出現,
  同前兩案例已知的 scale 過渡期現象)。
- **實際螢幕佔比**:約 3.4%~7.3% 畫布面積(隨時間點變化,因光暈本身有縮放/擴散動態),是
  三案例中最大的(`身體` 1.0~1.1%、`左手` 0.5~0.6%)。
- **人眼複查**:對差異像素集中的 bbox 周圍區域裁切放大 8 倍(`Award_Legend_Loop t=0.6`),
  orig/patched 視覺上無法分辨——不像前兩案例在同等放大倍率下還能看出「奶油糊」高頻細節
  丟失痕跡,`光暈` 這裡完全看不出差異。

## 結論

候選16路徑(b)三種材質類型(機械紋理×2 + 平滑漸層×1)覆蓋完成。核心新發現:**平滑材質
不只是「不構成一眼可見穿幫」,而是在放大複查下已經看不出任何差異**,且這個案例的實際
佔比是三者中最大的——排除了「因為佔比小才不明顯」的另一種解釋,支持既有結論(材質紋理
複雜度而非佔比大小才是補圖難度的決定因素,見候選0/8/10)。未改動任何既有 production
代碼(`s4_award_screenshot_compare.py`/`atlas_patch.py` 本身不變,只是換參數重跑)。

## 誠實限制

- 與前兩案例相同:相機框架(骨架包圍盒聯集+15% margin)是方法論近似,未對照真實遊戲
  實機顯示縮放比例;`nearest` 是 1b 盲選結果非唯一可能落地方法;人眼複查仍是 Claude
  vision 自評非真人標註。
- 三案例的佔比範圍(0.5%~7.3%)仍未觸及讓機械紋理材質「不明顯」結論翻盤的門檻——`光暈`
  佔比最大但材質本身平滑,不能代表機械紋理材質在同等佔比下也會沒事,這一點需要真實遊戲
  縮放比例才能確認,非本次可自主解決。
- 只測了單一 seed(0)、單一 frac(0.12)、單一 1b 盲選方法(`nearest`,與前兩案例相同)。
