# 2026-08-28 — S4 session 007(評分→採用→落地完整鏈路)

## 這次做了什麼

推進 `STATE_S4.md` 「下一個有界工作塊候選」第 1 項:把 `inpaint_eval.py` 的評分結果接上
`psd_inplace_patch.py` 的落地寫回,打通「評分→採用→落地」完整鏈路(之前兩支腳本是分開的:
一支對匯出 PNG 跑校準評分,一支對 PSD 圖層跑手動指定 baseline 的 demo)。

### 1. `inpaint_eval.py` 新增評分→選定共用邏輯

- `score_candidates(holed_rgba, mask, methods)`:對候選 baseline(`nearest`/`cv2_telea`/
  `cv2_ns`,不含只能當對照組的 `gt`/`none`/`random`)各跑一次,各算一次 1b 自我參照分數。
  真實補圖沒有真值,不能用 1a 分數選——1b 天生就是為這情境設計的(不比對洞內真實內容)。
- `select_best(scored, priority, applicable)`:依優先序(便宜的先試)挑第一個 1b pass 的;
  全部 fail 就退而求其次選 `seam_ratio` 最低者,標記 `no_pass_fallback_lowest_seam_ratio`。

### 2. `psd_inplace_patch.py` 新增落地端

- `patch_layer_auto(psd_path, layer_name, mask, out_path, mode)`:真實情境入口,呼叫端給
  mask,跑候選→盲選→用既有 `patch_layer_with_image()` 寫回同一個 PSD。
- `demo_auto_patch(...)`:本鏈路自己的評估器——合成挖洞模擬「盲選」情境(選擇邏輯全程不碰
  gt),寫回後才用 gt 算選中結果的 1a 分數「揭曉」(`reveal_1a_score_of_chosen`),驗證盲選
  沒有選到荒謬的結果。這個揭曉步驟只存在於自我測試,真實情境的 `patch_layer_auto()` 沒有。
- CLI 新增 `--auto`(合成自測)、`--mask`(真實情境,吃外部遮罩 PNG),兩者互斥有檢查。

### 3. 踩到並修正一個新坑:1b 的適用範圍沒有 gating

第一版測完 interior 案例(身體)後,順手測了 edge 案例(左手)驗證誠實度,結果發現:
`score_candidates`/`select_best` 沒有理會 `s4-inpaint-1b-lenient-gate.md` 已經校準出的
「1b 假設只在 interior 模式成立」——會讓 edge 洞的候選分數照樣套用 `THRESH_1B` 判定,
萬一某候選僥倖壓線通過,就會被標成有信心的 `pass_1b`,但那個信心在 edge 情境下沒有校準
依據。修法:`select_best` 新增 `applicable` 參數,`patch_layer_auto`/`demo_auto_patch` 都
要求呼叫端明確傳 `mode`(不自動偵測,因為要準確判斷洞是否跨真實輪廓需要挖洞前的完整外形,
真實已存在的破洞不一定拿得到,寧可要求明確告知而非猜測)。`applicable=False` 時一律走
fallback,reason 標成 `1b_not_applicable_edge_mode_fallback_lowest_seam_ratio`。

左手 edge 重跑驗證:三候選 1b 皆 fail(`tone_gap` 53~72,遠超閾值 28,呼應舊有 edge 模式的
輪廓天然梯度問題),fallback 正確觸發,沒有出現 `pass_1b`。

### 4. 驗證結果

- interior(身體,seed=0):候選三個皆 1b pass,盲選中 `nearest`(優先序第一個),寫回後
  `psd_slice.evaluate() overall_pass: true`;揭曉的 1a 分數 `ssim=0.33`、`reveal_1a_pass:
  false`——**符合預期**,呼應 `s4-inpaint-1b-lenient-gate.md` 已驗證的核心結果(機械紋理
  1a 嚴格標準必然 fail,1b 防穿幫標準下 CPU baseline 夠用),不是回歸。
- edge(左手,seed=0):三候選 1b 皆 fail,fallback 正確標不適用,無 `pass_1b` 誤判。
- 回歸:舊 `--method` 路徑、`--mask` CLI 串接(用合成 mask 測試)、`psd_slice.py --eval` 對
  原始檔、`inpaint_eval.py` 主流程校準,皆無影響。
