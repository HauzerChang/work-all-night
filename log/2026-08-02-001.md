## 過程與發現

1. **新工具 `tools/mesh_gen/validate_award_robot.py`**:reuse `atlas_crop.extract` + `evaluate_mesh` +
   `validate_against_real.artist_iou`,對 3 件跑端到端閘。
2. **發現機器人 mesh = weighted + 無 deform timeline**(與 main_draw 的 unweighted+deform-timeline 相反)
   → AC5(真實位移場轉移閘)對其 **N/A**;誠實標記,不硬套。(能力邊界:weighted 蒙皮變形目前無閘。)
3. **首跑全 fail**:固定 eps=0.008(窗簾校準)對有機輪廓覆蓋不足 — 光暈 0.929/artist 0.980(還生孤兒頂點)、
   左手 0.960/0.968、身體 0.968/0.976。藝術家 hull 78/42/40 vs 生成 14/18/21 → 輸在邊界解析度。
4. **epsilon 掃描證實 lever**:IoU 隨 eps 變細單調上升,更細 eps 也順帶清孤兒。
5. **修法**:`generate_mesh_v2` 非 strip 分支改走新 `refine_delaunay()` — 由粗到細掃 eps,取**最粗且
   IoU≥target_iou(0.98)且 0 孤兒且頂點≤預算**者(經濟性;只用件 alpha 自評,不需藝術家參照)。
6. **AC3 絕對 64 預算是資產相依**(藝術家用 78–98v)→ 閘改「≤藝術家頂點數」相對經濟。
