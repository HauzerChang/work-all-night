## 這次做了什麼(S3×S4 端到端:PSD件 → 生成 mesh → 對照 Award 真實 mesh)

推進 STATE「最高優先(有真值可比)」候選:把切圖 pipeline(S4)與 mesh 生成器(S3)串起,
對**真實生產 spine `Award`** 的藝術家 mesh 做量化對照。

### AC(動手前定的可檢查目標)
1. 對 光暈/身體/左手 3 件(Award 中為 mesh),生成 mesh 覆蓋率 ≥ 藝術家 mesh 覆蓋率 − 0.03(同一切件 alpha 真值)。
2. 生成 mesh setup 拓樸乾淨(0 退化/翻面三角)。
3. 頂點預算 ≤ 藝術家。

### 做法
- `psd_slice.py` 切 `robot_parts.psd` → 3 件緊湊 PNG(alpha 真值;texture-IoU 已證=spine 同素材)。
- 新工具 `tools/mesh_gen/compare_gen_vs_award.py`:
  - 生成 mesh:`generate_mesh_v2(mode="auto")` → `evaluate()` 在切件像素框算 IoU(座標框一致)。
  - 藝術家 mesh:Award uvs 為 region-local 正規化 [0,1] → `uvs*(W,H)` 光柵化三角面算 IoU(同一切件 alpha)。
    含 v-flip 自檢(方向不對時翻 v);本例 3 件皆無需翻轉。

## 關鍵結論 / 決策
- **Award 全 repo 無 deform timeline**(`animations.*.deform` 為空)→ 這些 mesh 是 **bone-weighted**,
  非逐頂點 deform warp。故對它們**只驗靜態覆蓋 + 預算**,真實位移場轉移閘(`deform_eval`)**不適用**(誠實記錄)。
- **拓樸選擇取決於變形模式**(新契約規則):deform-warp 柔性件(curtain/shadow)→ **strip(v2)**;
  bone-weighted 剛體團塊(Award 機器人件)→ **delaunay-v1**。strip 對不規則團塊覆蓋不足(0.88 < 基準),
  `mode="auto"` 已能依形狀正確二選一。
- 藝術家 uvs 無需 v-flip 即對齊 → 再次確認 Award mesh uvs region-local 自然方向(交叉驗證 texture-IoU 結論)。
