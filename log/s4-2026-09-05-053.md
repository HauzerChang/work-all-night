# S4 chunk 53(2026-09-05):九尾焰蓮拆解第一份完整組裝 PSD

## 背景

chunk 47-52 花了 6 個 chunk 把 `assets/jiuwei_yanlian_char_crop.suggestions.json` 20
個部件的框位置逐一裁圖複核、修正「框完全落錯」類錯誤,截至 chunk 52 已覆蓋全部 20 個
部件。但這整段工作每次只驗證單一/少數部件的裁圖,**從未真的跑完整的第3點(幾何裁切+
PSD組裝)pipeline 產出一份 .psd 交付物**——那條工具鏈(`s4_decompose_cut.py` +
`psd_node/manifest_to_psd.js`)chunk 46 就已建好並自我驗證過,但唯一一次「真實素材」
跑法用的是使用者當次手動調整、未持久化進 repo 的決策檔(chunk 49 才發現這個落差)。

本次排程開始無活人裁決(自動觸發)。剩餘的 `bodice`/`sleeve_right`(chunk48 已知演算法
歧異案例)與 `hair_front`(精確語意邊界)兩類問題都需要使用者裁決,依既有慣例(chunk
26/49/50/51/52)只做零成本、不需授權的部分。與其再做一輪「檢查有沒有新的框錯誤」
(chunk47-52 已確認這類問題已無新候選,重複意義不大),本次選擇把已修正的框位置變成
真正看得到、用得到的產出:跑完整第3點 pipeline 產出這份拆解迄今第一份完整 .psd。

## 執行

1. 複用 chunk52 重建的決策檔(`tools/mesh_gen/s4_data/chunk52/decision_reconstructed.json`,
   已反映 chunk52 對 `tag_pendant` 的修正),存快照到
   `tools/mesh_gen/s4_data/chunk53/decision_final.json`。抽查 `tag_pendant`/`skirt`
   兩項的 `bbox_px` 跟 `suggestions.json` 目前版本的 `bbox_pct` 換算後一致,確認快照
   忠實反映最新狀態。
2. `python3 tools/mesh_gen/s4_decompose_cut.py assets/jiuwei_yanlian_char_crop.png
   decision_final.json -o cut_rect --contour rect --eval`:
   - `AC1_parts_produced`:20/20,`pass: true`。
   - `AC3_no_orphan`:因來源圖 100% 像素 alpha=255(扁平未去背圖)略過,工具本身文件
     字串說明這是預期行為,非本次新狀況。
   - `overall_pass: true`。
3. `cd tools/mesh_gen/psd_node && npm install`(此環境第一次跑,裝 `ag-psd 24.x`/
   `pngjs 7.x`,`package-lock.json` 已鎖版本)。
4. `node manifest_to_psd.js cut_rect/manifest.json cut_rect
   jiuwei_yanlian_decompose.psd`:輸出 20 圖層 PSD,圖層名稱依序為各部件中文 label
   (頭部、狐耳、瀏海、長髮主體、耳環、頸飾、上半身胸衣、左/右側白紗寬袖、左/右手、
   腰帶、裙擺、垂墜符紙標籤、流蘇披帛、左/右腿、左/右靴、九尾狐尾)。

## 自我驗證

用 `psd-tools`(獨立於產出工具鏈的第三方 library,同 main_draw PSD-first pipeline
既有驗證方式)重新開啟輸出的 .psd,做兩層量化檢查(皆為腳本比對,非肉眼判斷):

1. **AC2 圖層幾何 round-trip**:逐圖層比對 `manifest.json` 記錄的 `name`/`offset`
   (`layer.left,layer.top`)/`size`(`layer.width,layer.height`)——**20/20 完全相符**。
2. **AC3 圖層像素 round-trip**:逐圖層 `layer.composite(force=True)` 轉 RGBA numpy
   array,跟 `cut_rect/` 對應的裁圖 PNG 做逐像素絕對差——**20/20 `max_diff=0`**(位元
   級精確,ag-psd 讀寫這批素材完全無損)。
3. **composite() 健全性**:`psd.composite(force=True)` 正常回傳 460×898 RGBA、全像素
   alpha=1.0(非 chunk28 記錄過的「重存後合併預覽壞掉」那種案例——這裡是首次寫入,
   非重存讀取,不適用該已知坑,僅做確認排除疑慮)。

三項檢查全部通過,`overall_pass` 邏輯延續(裁切階段)+ 新增的 PSD round-trip 兩項皆
pass,結論:這份 PSD 是忠實反映目前決策檔的完整交付物,沒有 pipeline 本身引入的資訊
損失。

## 誠實限制

- 這份 PSD 用的框位置反映 chunk52 為止的修正水準,`bodice`/`sleeve_right`(chunk48
  已知演算法歧異案例)與 `hair_front`(跟 `head`/`fox_ears` 大幅重疊、髮型本身無清楚
  瀏海分界)兩類已知問題**原樣保留在這份 PSD 裡**,不是本次修正範圍。這兩類問題底定後
  (需使用者裁決/assist viewer 確認)需要重跑本 pipeline 產生新版 PSD——這份是「目前
  最佳可用框」的快照,不是最終定案交付物。
- 邊緣 bleed(矩形窗口裁切鄰接部件內容)按既有授權(chunk46)原樣保留在各圖層裡,不是
  新引入的限制。
- `psd_node/node_modules` 此環境容器不持久化,下次排程重跑本 pipeline 需要重新
  `npm install`(`package.json`/`package-lock.json` 已鎖版本,理論上離線可重現)。
- 未做六階段第4點(GPT 局部修補),需要 API key 授權,同候選17既有阻塞點,本次未變。
- 未重跑 `--contour sam`(容器未持久化 MobileSAM 權重,同既有限制)。
