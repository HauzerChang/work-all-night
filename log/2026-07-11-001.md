# 2026-07-11 — session 001

## 這次做了什麼(S3 端到端泛化到真實生產標的 — 里程碑)

推進 STATE 的「最高優先」bounded chunk:**PSD 件 → S3 mesh → 對照 Award 真實藝術家 mesh**。
用 `robot_parts.psd` 對應到 Award spine 的 3 個 mesh 件(光暈/身體/左手),端到端驗收 S3 泛化。

### AC(動手前定的可檢查目標)
對 3 個 mesh 件,生成的 mesh 要:
1. 覆蓋率 IoU ≥ 藝術家 mesh 自身覆蓋率(baseline,不用武斷 0.95)。
2. 頂點數 ≤ 藝術家 ×1.25(不靠灌頂點取巧)。
3. setup pose 拓樸乾淨(0 自交/0 翻面/0 退化)。

### 過程
1. **探查標的**:Award `機器人拆件/{光暈,右手,頭,身體,左手}`,3 個 mesh(光暈/身體/左手)、2 個 region。
   3 mesh 全 **weighted、骨骼驅動、無 deform timeline** —— 與 main_draw 的 unweighted+deform 窗簾是不同拓樸類別。
2. **首跑 auto(舊預設)**:3 件 aspect < 1.2 → 全走 Delaunay-v1(正確,非窗簾)。但 IoU 略低於藝術家:
   光暈 0.929<0.979(差 0.05)、左手 0.960<0.968、身體 0.968<0.976 → **fail**。
3. **診斷 + 自動迭代(1 輪就收斂)**:覆蓋率由邊界簡化容差決定。epsilon 掃描 → **eps=0.002 對 3 件全達/超藝術家、
   且頂點 ≤ 藝術家**(73/67/77 vs 78/80/98);0.001 過細(頂點爆表)不採。
4. **改動**:`generate_mesh_v2.generate(..., epsilon=0.002)` 只作用於 Delaunay fallback(strip 路徑不動)。
5. **新評估器** `validate_award_mesh.py`:atlas 切件 → 生成 → IoU vs 藝術家 + setup 拓樸,機器可讀 pass/fail。
6. **回歸驗證**:curtain_left/right/shadow 仍 mode=strip、overall_pass → strip 路徑不受影響。

## 關鍵結論
- **S3 泛化到真實生產機器人身體零件成功**:3 mesh 件全 overall_pass(IoU 0.983/0.991/0.993 ≥ 藝術家)。

  同 S3「覆蓋率由邊界取樣密度決定、內部點次要」的一貫發現。

  這是對 2026-06-26 CCW→CW 修正的第三方(藝術家 UV 幾何)佐證。
