# 2026-07-11 — session 001

## 這次做了什麼(S3 端到端對照第二個真實骨架 Award + weighted mesh 發現)

推進 STATE 的最高優先 bounded chunk:**PSD件/atlas件 → S3 mesh → 對照 Award 真實 mesh**
(端到端「件→mesh」對第二個真實生產標的驗收)。

### AC(動手前定)
1. 取 Award 3 個機器人 mesh 件的藝術家真值,rasterize(uvs+triangles)→ 覆蓋率基準(需高,證明對齊)。
2. atlas 切件 → `generate_mesh` → 生成 mesh 覆蓋率 IoU ≥ 藝術家基準(margin 0.02)、0 孤兒、格式合法。
3. main_draw 回歸不破。

### 過程
1. **發現 weighted mesh**:對 3 件跑 `validate_against_real --gen v2` 全 crash
   (`ValueError: different number of values and points`)。追出根因:**Award 3 mesh 全 weighted**
   (`vertices` 為 `[boneCount,boneIdx,bindX,bindY,weight,...]` 變長,`len != len(uvs)`),
   而 `deform_eval` 假設 unweighted。→ deform 閘不能直接用於 Award。
2. **靜態路線**:覆蓋率只用 `uvs`+`triangles`(與加權無關),寫 `compare_award_static.py` 走此路。
3. **首跑**:身體/左手過(0.968/0.960 ≥ 基準),**光暈 fail**(IoU 0.929 < 基準 0.9795、且 1 孤兒)。
4. **診斷光暈**:近方形(aspect 0.97)大 blob → auto 走 v1 Delaunay;根因是 v1 邊界容差
   `epsilon_frac × perimeter` 對大件過鬆 → hull 抄捷徑。掃描 eps → 絕對像素容差 2.0px 最佳。
   strip 模式對 blobby 件反而更差(再確認 strip 專屬高長寬比件)。
5. **修 v1 兩缺陷**:(a) `boundary_points` 改**絕對像素**容差(尺度不變);(b) 加 `drop_orphans`
   (移除孤兒 + 重編索引 + 重算 hull,維持 hull-first 不變式)。
6. **回歸**:main_draw v2 curtains/shadow 全過、deform 乾淨;v1 curtain_left 0.98→0.9963。

## 關鍵結論 / 教訓

- **生產 mesh 是 weighted**(main_draw 全 unweighted 是特例);deform 閘要推廣必須先做骨架世界變換求解器。
- **邊界容差該用絕對像素**,相對周長對大件會抄捷徑(IoU 掉 + 孤兒)。尺度不變後大小件一致。
- **S3 通過第二個真實骨架的靜態端到端驗收** → 生成器不只 fit main_draw。
