# 2026-07-14 — session 001

## 這次做了什麼(S4→S3 端到端:PSD件 → 生成 mesh → 對照 Award 真實 mesh)

推進 STATE 標的「最高優先(有真值可比)」候選:把 S4 切件與 S3 生成器端到端串起來,
對真實生產 spine(Award)的藝術家手做 mesh 驗收。

1. **定 AC(AC-first)**:對 `robot_parts.psd` 中「在 Award 是 mesh」的 3 件(光暈/身體/左手):
   - AC1 coverage:生成 mesh IoU(vs 件 alpha)>= 藝術家 Award mesh IoU − 0.02。
   - AC2 topology:0 退化 / 0 孤兒 / 三角重心全在 mask。
   - AC3 budget:生成頂點數 <= 藝術家頂點數。
2. **切件**:`psd_slice.py` 切出 5 件(光暈/右手/頭/身體/左手)。
3. **座標系先驗**:實測 Award mesh uvs 對 PSD 件 alpha 的 4 種翻轉變體,"as-is" 唯一高
   (0.95/0.95/0.98,其餘 0.4~0.76)→ **推翻舊假設**「需轉 atlas→region」,uvs 已是 region-local。
4. **新工具 `validate_psd_to_mesh.py`**:切件 alpha → `generate_mesh_v2`(auto) → 同底 IoU 對照 + 拓樸閘。
5. **結果:3 件全 overall_pass**(身體反勝 0.966>0.948、光暈/左手 margin 內、頂點 35/60/59<78/98/80、拓樸乾淨)。
6. **對照圖**:`knowledge/figures/s4s3-psd-to-mesh-vs-award.png`(藝術家綠 vs 生成青,疊件 alpha)。

## 關鍵結論 / 教訓

- **這 3 件無 deform timeline(weighted、骨骼變形)** → 逐頂點 deform 耐受閘不適用;
  真值是輪廓覆蓋率 + 精簡度,`generate_mesh_v2` auto 對低長寬比 blob 回退 v1(Delaunay)正是對的工具。
- **座標系要實測不要沿用假設**:舊 STATE 記「需轉座標」是錯的;4 變體對照 = 廉價可信的座標系驗證法。
- 生成器對真實生產件覆蓋率**匹配或勝過藝術家、且更精簡** → S3 對真實標的可用性再確認。
