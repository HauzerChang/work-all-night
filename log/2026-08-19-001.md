## 這次做了什麼(S3 端到端 → 對照 Award 真實美術 mesh)

推進 STATE 最高優先 bounded chunk:把 S3 mesh 生成器對「真實生產 spine 的美術 mesh」做端到端驗收
(而非合成/自產真值)。標的 = Award「機器人拆件」的 3 個 mesh 件(光暈/左手/身體)。

1. **建對照工具** `tools/mesh_gen/compare_robot_mesh.py`:用 `atlas_crop.extract` 取 Award region
   (已 derotate + 0.70 縮放)的 alpha 當來源+真值,S3 也吃同一張 → 零跨檔套準誤差;在同一 region 框內
   把 S3 生成 mesh 與美術 mesh 做靜態覆蓋率 IoU 對照 + 拓樸閘 + 頂點經濟度。
2. **校正 STATE 舊假設**:先前寫「Award mesh uvs 為 atlas UV,需轉 region 局部」→ 實測錯。
   4 種組合(v-flip × derotate 手性)測下來,**mesh uvs 直接就是 region-local [0,1]、vflip=False**
   (3 件皆 IoU 0.97~0.98,其餘 <0.61)。對照覆蓋率不需 atlas 幾何轉換。
3. **首跑發現 2 問題 → 修**:
   - 光暈(軟邊 blob,羽化帶佔 38%)預設 epsilon 過度簡化 → 覆蓋率 0.923 < 美術 0.980。
     → `generate_mesh_v2` auto 新增 `soft_band_frac>=0.20` 偵測 → `boundary-dense-v1`(密邊界、無內部點),
     0.923 → **0.983**、頂點更省。只影響 delaunay 分支。
   - `filter_triangles` 造孤兒頂點(光暈 orphan=1)→ `generate_mesh.py` 加通用 `prune_orphans`
     (移除未引用頂點 + 重編索引 + 重算 hull)。
4. **重驗**:3 件全 `overall_pass`;**4 個 curtain/shadow strip 迴歸全 PASS**(strip 不走 delaunay,不受影響)。
5. 產視覺證據 `knowledge/figures/robot_mesh_gen_vs_artist.png`(綠美術/橙生成疊剪影)。

## 誠實限制(寫進 knowledge)

這 3 件是 **weighted mesh 且無 deform timeline** → 逐頂點 deform 閘不適用,本次僅驗靜態覆蓋率+拓樸。
美術的密集**內部**頂點(身體 98v)服務**骨骼權重變形平滑度**,我方 boundary-dense 幾乎只有邊界點。
**靜態 IoU 高 + 頂點省 ≠ bone-driven 變形一樣平滑**。要驗這維度需 weighted 生成 + BBW 權重(下一步)。
