# 2026-08-01 — session 001

## 這次做了什麼(S3×S4 端到端對真值閉環)

推進 STATE 最高優先 bounded chunk:**PSD 件 → S3 mesh → 對照 Award 真實生產 mesh**。

**AC(先定,可自量)**:對機器人 3 個 mesh 件(光暈/左手/身體;右手/頭在 Award 是 region 不比),
生成 mesh 的覆蓋率 IoU ≥ Award 藝術家 mesh 在同 region 幀的 IoU,且頂點數 ≤ 藝術家。

1. **探測**:3 件 aspect 皆 <1.2 → v2 auto 落回 v1 Delaunay。預設 eps=0.008 覆蓋率落後藝術家 1–5%
   (光暈 0.929 vs 0.980、左手 0.960 vs 0.968、身體 0.968 vs 0.976),失敗主因是藝術家用 ~1.5× 頂點、邊界更密。
2. **epsilon 掃描**:0.008→0.004→0.002→0.001。**eps=0.002 甜蜜點** — 3 件全達覆蓋率 parity
   (0.983/0.991/0.993)且頂點仍在預算內(73/67/77 ≤ 78/80/98)。
3. **腿 B(真上游 PSD)**:直接對 `psd_slice` 切出的 PSD 件生成 → IoU 0.98–0.99,證明整條上游通,
   非只靠 atlas region。
4. **deform 閘檢討**:Award 5 件無 deform timeline。把 curtain_left 真實場硬轉過來 → 直接套(絕對像素)
   假性失敗(左手 313px 位移套 181px 手);尺度歸一(同 49% 相對拉伸)後身體/左手 clean、光暈仍 self_int=3。
   判定此閘對無 deform 資產 **N/A**(跨資產場轉移未校準,RULES 警告的 miscalibration 類),只判靜態覆蓋率+預算。
5. **工具化 + 重現**:寫 `validate_psd_to_award_mesh.py`(腿 A 匹配幀嚴謹數字 + 腿 B PSD 上游)→ overall_pass、EXIT 0。
6. **回歸**:`validate_against_real --gen v2` curtain_left 仍 overall_pass(未動全域預設)。

## 關鍵結論 / 決策

- **統一發現**:mesh 覆蓋率保真度的**唯一槓桿 = 邊界取樣密度**——Delaunay 是 epsilon、strip 是 rows,同一原理。
- **預設 eps=0.008 不改**(為 main_draw strip 驗過,改會回歸);記錄「精緻 blob 件需 eps≈0.002」+ 開
  「自適應 epsilon」為下一步小塊,消滅手調參數。
- 圓形 blob 用 Delaunay 有薄三角風險(光暈在強剪切下 self_int);若未來對光暈做強變形,考慮放射狀拓樸。
- **S3+S4 首度對真值(Award 藝術家 mesh)端到端閉環** —— pipeline 從「各段自驗」升到「對真實生產標的達 parity」。
