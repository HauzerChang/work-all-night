# 2026-08-01 — session 001

## 這次做了什麼(bounded chunk:S3 端到端對真實生產 weighted mesh 驗收)

推進 STATE 候選 #1(最高優先、有真值):**PSD件 → S3 mesh → 對照 Award 真實 mesh**。
標的 = Award 機器人拆件 3 個 mesh(光暈/左手/身體),對應 `robot_parts.psd` 圖層。

### 先定 AC(AC-first)
- AC1 覆蓋:生成 mesh 靜態 IoU ≥ 藝術家 mesh 覆蓋 IoU − 0.03。
- AC2 頂點經濟:生成頂點 ≤ 藝術家 × 1.6。
- AC3 拓樸:0 degenerate / 0 orphan(靜態評估器)。
- deform 閘:先檢查是否適用。

### 關鍵發現 → 修正驗證體制
- 三個機器人 mesh 全是 **weighted**,且 **12 支動畫皆無 deform timeline** →
  骨骼 skinning 剛性驅動,不做逐頂點 deform。
- 直接套 `validate_against_real`(含 deform 閘)會炸(`transfer_deform_check` 無 deform 場)
  —— 非 bug,是**體制不對**:窗簾的「deform 耐受」閘對骨驅 mesh **N/A**。
- 建新工具 `tools/mesh_gen/validate_weighted_real.py`:覆蓋保真 + 頂點經濟閘,deform 標 N/A;
  可選 `--psd` 做 PSD 路徑交叉驗證。

### 結果
| 件 | 生成 IoU | 藝術家 IoU | 頂點比 | overall |
|---|---|---|---|---|
| 左手 | 0.960 | 0.968 | 0.60× | **PASS** |
| 身體 | 0.968 | 0.976 | 0.62× | **PASS** |
| 光暈 | 0.929 | 0.980 | 0.69× | **FAIL** |

- **左手/身體端到端過關**:覆蓋僅落後藝術家 0.008,只用 0.6× 頂點。
- **PSD 路徑交叉驗證**:PSD 圖層切件生成 IoU(左手 0.964 / 身體 0.967 / 光暈 0.934)
  與 atlas 路徑各自吻合(±0.006)→ **PSD→件→mesh 閉環對真實生產標的成立**。

### 光暈 fail 根因(已定位 + 修法方向已實測)
- alpha 31% 羽化半透明 → 硬門檻(127)切出孤島(orphan=1);外殼填不滿放射狀光暈(0.93)。
- 實測:門檻降 10 → orphans=0(morphological close 反而更糟)。
- 拓樸實驗:convexHull 過度外擴 0.79;**`approxPolyDP` eps≈0.005(21 邊界點)→ IoU 0.966**,逼近藝術家 0.98。
- **可推廣結論:件的形狀類別決定拓樸** — 硬邊實心→散點 Delaunay(OK)、軟邊放射→外輪廓邊界、
  高瘦→strip(舊窗簾發現)。三者皆「邊界主導 vs 散點」之別。
