# 2026-08-28 — S4 session 005(1b 防穿幫寬鬆閘)

## 這次做了什麼

依上一輪(session 004)使用者釐清的補圖三情境定義,推進最高優先候選:**補一組 1b(防穿幫)專用
寬鬆閘**,重新檢視先前「CPU 補不動」的結論是否對 1b 情境也成立。

### 1. 新增 `score_1b()`(`tools/mesh_gen/inpaint_eval.py`)

自我參照三指標,**不比對 gt 洞內真實內容**:
- `alpha_gap`:洞內仍完全透明的像素比例(門檻 alpha≤8,沿用全檔一致定義)。
- `seam_ratio`:洞邊界梯度強度 / 這件其餘正常區域的梯度基準(材質本來的邊緣強度)。
- `tone_gap`:洞邊界內外環帶的平均色差。

### 2. 校準,踩到一次真實 miscalibration 並修正

第一版用 `alpha<200` 判定殘留透明,結果正對照(gt)在 edge 模式大量 fail——排查發現光暈這類
軟邊素材輪廓天然有 alpha 9~255 的合法漸層,`<200` 誤判。改用 `alpha<=8` 後修正。

修正後仍有一個殘留:`左手::edge` 的正對照 `tone_gap=58.36` 未過——追查是**真實現象**(edge 洞
跨在真實輪廓邊界上,輪廓本身天然有較大 tone 變化,不是接縫)。**結論**:1b 的自我參照假設只在
`interior` 模式成立;`edge` 模式判定收斂為「不適用」(分數仍算,不下 pass/fail)。這個範圍收斂
概念上合理:1b(防穿幫)對應遮擋件蓋在角色**內部**,不是遮擋件本身定義輪廓。

### 3. 核心結果:驗證了使用者的假設

對 `光暈`/`身體`/`左手` 三件、interior 模式:
- 正對照(gt)3 件全 PASS,負對照(none/random)3 件全 fail → 校準通過。
- **身體/左手(機械紋理)之前 1a 嚴格標準下 fail 的 3 個 CPU baseline(nearest/cv2_telea/cv2_ns),
  在 1b 標準下全部 PASS。** 證實「CPU 補不動」是 1a(需表演)嚴格標準下的結論;1b(防穿幫)情境
  同一批廉價 baseline 其實夠用,不需要升 LaMa/GPU。

### 4. `psd_preview.html` 整合

補圖分頁每張卡片新增第二顆判定燈(1a/1b,綠/紅/灰=pass/fail/不適用),modal 大圖同步列出兩組
完整數字。用 Playwright + headless Chromium(base64 DataTransfer 模擬拖放,避開中文檔名的
`setInputFiles` 已知限制)驗證:互動正常,身體/左手 interior 卡片正確顯示「紅點(1a fail)+
綠點(1b pass)」分歧判定,edge 模式正確顯示灰點。
