## 驗收(5 AC 全 PASS,`python3 tools/analyzer/validate_c1_mesh.py`)

- **C1-1 entrypoint+schema**:公開 API 對 curtain 件(main_draw region,auto→strip)與 robot 件

  strip 全乾淨 → 證 strip 拓樸選型是 si=0 的原因(curtain_left 溫和處不鑑別,honest)。
- **C1-4 coverage+budget**:strip IoU(0.93/0.93/0.95/0.95)≥ 藝術家基準(0.918/0.914/0.473/0.473)+

  auto 選型資料驅動(窗簾→strip、軟邊光暈→boundary-dense、方正 robot body→delaunay)。

回歸:`check_readiness` **0 RED**(新增 cap `c1_mesh`)。

## 關鍵發現

- **naive Delaunay 靜態 IoU 反而更高(curtain_left 0.98 vs strip 0.93)但真實 deform 下撕裂** ——
  「靜態像得好」≠「變形下不壞」;strip 直條拓樸(沿拉伸軸的邊界取樣)才讓『真實 deform si=0』成立 →
  生成器的**拓樸選型是關鍵不是附帶**。
- 這是 `knowledge/s3-real-asset-finding.md`「散點靜態好但拉伸自交」結論在 2.0 入口層的實測復現,
  **用真實位移場轉移**(非合成 stress field——後者 mag=315 面積比 2.0 會造假性失敗,見 deform_eval 警語)。
- 從「只能檢查」到「能生成且自驗」是 v1.3.0 → 2.0 的真升級。

## 決策 / honest boundary

- mesh deform timeline 由動畫層負責、本模組只生 setup mesh 幾何(不涉 G1 末鍵 curve)。
- robot 件無自身真實 deform 真值(其 si=0 以 strip schema + 轉移 main_draw 真實場驗;真實 deform 真值僅 main_draw 4 mesh)。
- viewer/Cocos 實機載入 = 使用者端(排程 scope 邊界,用純 CPU 幾何真值替代)。
