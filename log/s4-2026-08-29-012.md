# 2026-08-29 — S4 session 012(候選 2:1b edge 模式支援)

## 這次做了什麼

從 `STATE_S4.md` 挑候選 2(1b edge 模式支援)推進——session 011(候選 9)用真實遮擋樣本
量出「頭」這類小尺寸圖層的遮擋洞天生易落在 edge 模式,而 1b(唯一能讓機械紋理材質給出
pass 的寬鬆閘)只在 interior 校準過,edge 洞完全沒有驗收線可用,把候選 2 的優先度上修
為「已卡住的真實案例」。

### 實作(`tools/mesh_gen/inpaint_eval.py`)

1. **第一版嘗試**(依 STATE_S4.md 候選 2 原始構想):edge 模式的 `seam_ratio`/`tone_gap`
   改成跟「這個材質沿真實輪廓其他段落的天然變化範圍」比的比值。量化校準時發現失敗——
   `random`(亂補負對照)的比值跟 `gt`(正對照)糾纏在一起,任何單一門檻都分不開(如
   `左手` gt tone_gap 比值 0.676 vs random 0.779,`框` gt 0.648 vs random 0.643)——查因:
   premultiplied 色彩在背景(alpha≈0)側恆為 0,補丁不管內容對錯,只要 alpha 補對,在真實
   輪廓交界處量出的落差量級都跟材質本身在別處的真實輪廓落差相近,鑑別力被稀釋。
2. **改法(採用版)**:新增 `_exclude_real_silhouette()`——mask 定義本身 ⊆ 挖洞前的原始
   內容,所以洞邊界「貼著真實輪廓」的那段落差是材質天然性質、不是補圖造成的接縫,不必評;
   排除這段後,剩下「洞邊界完全落在內容內部」的轉接部分跟 interior 模式的「材質內部紋理」
   問題同構,直接複用同一套 `local_ring` baseline(不重新發明),`tone_gap`/`seam_ratio`
   維持絕對值單位,與 interior 完全一致。
3. **踩到一個真實 bug**:`_exclude_real_silhouette` 原本直接用 `~content` 當背景判定,但
   `content` 在校準流程(`run_with_mask`)是挖洞前的完整輪廓,在真實落地情境
   (`score_candidates`)卻是已挖洞的 holed_rgba 算出的輪廓(洞本身沒有內容)——導致端到端
   測試(`psd_inplace_patch.py --auto --mode edge`)所有候選的 1b 分數全部是 0、
   `applicable` 恆 `False`,盲選完全沒發揮新支援。改用 `content|mask` 統一兩種情境的
   「完整真實輪廓」語意後修正。
4. 新增 `THRESH_1B_EDGE`(`alpha_gap<=0.02`、`seam_ratio<2.2`、`tone_gap<23.0`)——沿用
   `THRESH_1B` 的 alpha/seam 門檻,`tone_gap` 收緊到 23.0(排除後樣本區域較窄、統計波動
   較大,沿用 interior 的 28 會讓機器人家族內「左手」的負對照 random 以些微差距誤判 pass)。
5. `score_candidates()`/`select_best()` 同步更新:`score_candidates()` 新增 `mode` 參數
   傳給 `score_1b()`;`select_best()` 的 `applicable` 改由呼叫端從
   `score_candidates()` 回傳值讀取(不再自己用 `mode=="interior"` 猜測)——
   `psd_inplace_patch.py` 兩處呼叫點(`patch_layer_auto`/`demo_auto_patch`)同步更新。

### 核心結果

機器人拆件家族(光暈/身體/左手,合成挖洞 edge 模式):`calibration.pass=True`,三個 CPU
baseline(nearest/cv2_telea/cv2_ns)全部 1b pass,與既有 interior 模式的機械紋理結論同型。

真實遮擋樣本(`real_occlusion_eval.py` 全部 8 組,含 3 組 edge):`calibration.pass=True`。
候選 9 揭露的關鍵案例 `頭←右手`(小尺寸圖層,46.5% 遮擋比例,edge)現在 `applicable=True`,
gt/none/random 校準全過,3 個 CPU baseline 全 pass——這批之前「沒有任何量化閘能判定動態下
是否穿幫」的小尺寸機械材質補圖,現在有驗收線了。

端到端(`psd_inplace_patch.py assets/robot_parts.psd 左手 --auto --mode edge`)修 bug 後:
`chosen_method=nearest`,`chosen_reason=pass_1b`(修 bug 前是
`1b_not_applicable_fallback_lowest_seam_ratio`,盲選完全沒發揮);`reveal_1a` ssim=0.1359
(僅自我測試揭曉,證明盲選挑到一個 1a 嚴格標準下明顯不完美、但 1b 標準下有把握的 baseline,
符合這條鏈路設計初衷)。

### 已知限制延續(非新問題)

Symbol_Ww `框`(環形鏤空)edge 模式的 `tone_gap` 仍不可信(gt=27.234 壓線超標,同案例
random=25.64 反而更低)——這跟候選 8 已量化證明的「tone_gap 跨材質家族不可攜,框/臉部陰影
屬於此限制」是同一件事在 edge 模式的延續,不是新缺陷(該材質 interior 模式下本來就已
fail calibration)。`臉部陰影` edge 模式 `applicable=False`(排除後樣本 <60px),誠實跳過。
