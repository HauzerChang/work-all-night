## 關鍵發現:此排程容器的網路政策擋下 `api.openai.com`

用使用者提供的 key 測試 `GET https://api.openai.com/v1/models`(零成本的列模型呼叫,驗證
連線與授權,非圖片生成),結果:

```
curl: (56) CONNECT tunnel failed, response 403
```

查 proxy 狀態(`$HTTPS_PROXY/__agentproxy/status`)確認 `recentRelayFailures` 記錄:

```json
{"kind": "connect_rejected", "detail": "gateway answered 403 to CONNECT (policy denial or upstream failure)", "host": "api.openai.com:443"}
```

**這是網路政策層級的拒絕,連線在到達 OpenAI 前就被這個容器的 proxy 擋下**,跟 key 本身
是否有效無關(候選4/LaMa 探測時已知同一類阻塞擋過 `huggingface.co`/
`download.pytorch.org`,這次換成 `api.openai.com` 被擋,屬同一機制的新案例)。

**影響**:候選17原本設計的「從排程容器內 headless 呼叫 gpt-image-2」路線(接進
`inpaint_eval.py` 當第4個候選 baseline、批次量化校準)**目前技術上走不通**,需要使用者
調整此 environment 的網路政策才能放行。

**不受影響的路線**:使用者要求的第3項(viewer,瀏覽器端 HTML 工具,比照現有
`spine_inspector.html`/`psd_preview.html` 的純前端單檔架構)**完全不經過此排程容器**,
API 呼叫從使用者自己的瀏覽器/網路出去,不受此阻塞影響——key 由使用者在瀏覽器端輸入
(`localStorage`,不寫進工具原始碼、不進 git)。
