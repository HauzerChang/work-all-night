## 這次做了什麼(S3 端到端對照 Award 真實 mesh)

承 STATE / log-006 下一步候選 #1(最高優先、有真值可比):把 S3 生成 mesh 用在 Award「機器人拆件」
的 3 個真實 mesh 件(光暈/身體/左手),與 Award 藝術家 mesh 做 IoU 對照 →
端到端「件→生成 mesh→對照真實生產 mesh」驗收。

### AC(動手前定)
- AC_iou:生成 mesh 覆蓋率 ≥ artist 覆蓋率 − margin(0.03)。
- AC_topology:合法 mesh(格式 / 0 退化 / 0 孤兒)。
- AC_budget:頂點數 ≤ 120。
- deform 閘:**不適用**(這 5 件在 Award 無 deform timeline,無真實位移場可轉移;依 RULES 不用未校準 stress)。

### 做法
1. **修正前一假設**:log-006 推測 Award mesh uvs 為 page-relative atlas UV(需轉 region 局部);
   實測為 **region-local [0,1]、v-down**(u 0~1 滿幅,非局限於 region 矩形)。把 artist uvs 直接
   `(u*W, v*H)` 疊 `atlas_crop.extract` 切出的 region 遮罩 → artist IoU 0.968/0.979/0.976(v-down;
   v-up 僅 0.44–0.61)。同時再證 `atlas_crop` 的 **CW 去旋轉**對 rotate=true 件(光暈/身體)正確,
   且 artist 與生成 mesh 落同一像素框(IoU 公平可比)。
2. 新增 `tools/mesh_gen/validate_against_award.py`(extract → generate_mesh_v2 → 生成 IoU vs artist IoU + 拓樸 + 預算)。
3. 首跑:身體/左手 PASS;**光暈 FAIL**(IoU 0.929 < 0.980,且 1 孤兒頂點)。
4. 診斷 + 修 v1 兩 bug(`generate_mesh.py`):
   - **孤兒內部頂點**:`filter_triangles`(以重心剔凹形外三角)會把某內部頂點的相鄰三角全剔光 →
     新增 `prune_orphans()`(剔 index≥n_hull 的未引用點並重索引;hull 一律保留)。
   - **大平滑輪廓取樣過疏**:hull epsilon=`frac*peri`(純比例)對大件絕對偏差過大 →
     加 `max_dev_px=2.0` 絕對像素偏差上限。
5. 重跑:**3 件全 overall_pass**。回歸:curtain_left v1 + main_draw v2(curtain_left/right/shadow)全過。
