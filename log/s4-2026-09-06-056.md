# S4 chunk 56(2026-09-06)— 把 SAM 輔助點提示接線進 production

## 動機

chunk55 驗證「點提示對 `skirt` 有效」(單一正向點即可讓 MobileSAM 選中裙擺紅布而非皮膚),
但明確記錄「未修改任何 production 代碼」——只在 ad-hoc 腳本裡測過。STATE_S4.md 把「接線進
production(decision JSON schema + assist viewer UI + `s4_decompose_cut.py`)」列為唯一
「已知有效但未落地」的改進動作,優先度高於重複測試已定論無效的 `bodice`/`sleeve_right`。
本次執行這個候選。

## 做了什麼

1. **`s4_sam_segment.py`**:`segment()` 加選填參數 `points`(`[(x,y,label),...]`,
   1=正向/0=負向)。有點時呼叫 `predictor.predict(box=..., point_coords=...,
   point_labels=..., multimask_output=True)`;沒點時維持原本純 box-prompted 路徑不變
   (向後相容)。info 多一個 `n_points_used` 欄位供追溯。
2. **`s4_decompose_cut.py`**:decision JSON 的部件多讀一個選填 `points` 欄位
   (`[{x,y,label}]`),`--contour sam` 時轉成 tuple list 傳給 `segmenter.segment()`。
   檔頭 docstring 同步更新 schema 說明。
3. **`s4_decompose_assist.html`**:編輯面板新增「+ 正向點」「+ 負向點」切換按鈕,開啟後
   點畫布為選取部件加點(綠/紅圓點疊圖,可逐點刪除,Esc 或再按按鈕結束點選模式,跟原本
   畫框/選取/拖曳邏輯用 `pointMode` 變數互斥,不影響既有行為)。匯出決策檔時 `points`
   非空才寫入,維持 schema 精簡與向後相容。
