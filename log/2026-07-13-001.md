# 2026-07-13 — session 001

## 這次做了什麼(S3×S4 端到端:PSD 件 → 生成 mesh vs Award 藝術家真值)

推進 STATE 最高優先 chunk:用 `robot_parts.psd` 3 個「在 Award 為 mesh」的件
(光暈/左手/身體)跑 S3 `generate_mesh_v2`,對照 Award 生產 spine 的藝術家 mesh。

**AC(可自測)**:① 生成 mesh 過 evaluate_mesh 靜態閘(IoU≥0.95、格式、無孤兒/退化、≤64 頂點);
② 對照藝術家真值量覆蓋率 IoU + 頂點經濟性;③ 疊圖目視確認。

1. `psd_slice` 切件 → `generate_mesh_v2` 生成(3 件皆非高瘦 → 走 v1 Delaunay 回退)。
2. 初跑 **光暈 IoU 0.933 FAIL**;epsilon 掃描發現固定 epsilon 不通用(光暈需細邊界、
   但同 epsilon 下左手/身體爆 64 頂點預算)。**根因:靜態覆蓋只由 hull 決定,內部點不影響**。
3. **修法**:新增 `generate_mesh.generate_auto` — 自適應 epsilon(內建 hull-fill IoU 自測、
   達 0.97 即停)+ 預算感知內部點(`max_interior = budget - hull`);設為 v2 非 strip 回退。
   → 3 件全 PASS 且在預算內。
4. 對照藝術家:發現 Award mesh 為 **weighted**(不能直接用 vertices),改用 **uvs**;
   釐清 uvs = **region-local / 上正(atlas rotate 旗標與 uvs 無關)/ v-down**。
   藝術家 mesh 須疊在 **atlas 自身貼圖**(`atlas_crop`)而非 PSD 緊裁框(否則假性低 IoU 0.64)。

## 結果(乾淨對照)

| 件 | 藝術家 nv/IoU | 生成 nv/IoU | 頂點節省 |
|---|---|---|---|
| 光暈 | 78 / 0.980 | 54 / 0.983 | 31% |
| 左手 | 80 / 0.968 | 64 / 0.980 | 20% |
| 身體 | 98 / 0.976 | 64 / 0.971 | 35% |

→ 生成 mesh 覆蓋率 ≈/優於藝術家、頂點更省。首次「PSD→件→mesh」對真實生產標的端到端驗收。
