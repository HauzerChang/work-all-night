## 這次做了什麼(S3×S4 端到端:PSD 件 → 生成 mesh → 對照真實生產 mesh)

承 STATE 的「下一步(1)最高優先」:把 S4 切圖與 S3 生成串起來,對**真實生產標的**驗收。

1. **列真值**:`Award.json` 中機器人 3 個 mesh 件 —— 光暈(78v/76t/hull78)、身體(98v/154t/hull40)、
   左手(80v/116t/hull42)。確認它們 **weighted 且無 deform timeline**(靠骨骼權重變形)。
2. **關鍵判定校準**:因件為 weighted+無 deform,「真實位移場轉移」閘 **N/A** → 改用
   **coverage IoU 對藝術家 mesh** 當可比真值(誠實記錄,不硬套 deform 閘)。
3. **座標校驗**:Award mesh `uvs` 為 region-local(0..1)、未旋轉原圖朝向 → 直接對 PSD 全解析度 alpha
   渲染;以「y 翻轉 IoU 崩掉」反證朝向慣例正確。
4. **建工具** `tools/mesh_gen/validate_psd_mesh_vs_spine.py`:PSD 件切圖 → `generate_mesh_v2` →
   量 gen IoU / 藝術家 baseline IoU / 頂點預算 / 格式;內建正對照(藝術家自身 IoU)+ 負對照(翻Y)。
5. **跑驗**:3 件全 `piece_pass`、`overall_pass=true`、exit 0。

## 關鍵結論

- **生成 mesh 覆蓋率持平藝術家(±1.5%,身體反超),且頂點少 26–55%** → 「同覆蓋、更精簡」。
- 藝術家自身 IoU 也僅 ~0.95 = 低多邊形逼近曲線輪廓的自然上限;生成貼著上限。
- 3 件 aspect≈方形 → v2 auto 落回 v1 Delaunay(strip 是給高瘦 deform 件的)→ 對骨骼驅動件正合適。
- 第 4 次守住「先驗評估器再判定」:正/負對照都過才下 pass。

## 誠實留痕 / 限制

- 只驗**拓樸/覆蓋**,**未產權重**:生成 unweighted mesh,要 drop-in 進 Award weighted 件仍需 BBW。
- deform-robustness 對這批件 N/A(weighted、無 deform timeline);curtain 類仍走 v2 strip + 真實位移場閘。
- margin=0.02 吸收 PSD(全解析度)↔ atlas(0.70 縮小)跨源雜訊(前測 alpha-IoU 0.92~0.99)。
