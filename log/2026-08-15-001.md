1. **確認真值結構**:讀 `Award.json`,機器人拆件 3 個 mesh 件(光暈 78v / 身體 98v / 左手 80v)
   皆 **weighted 且無 deform timeline**(骨骼/權重驅動)。
2. **座標映射驗證**:Award mesh `uvs` 是 0..1 相對切件原圖 → `uvs×(W,H)` 直接落在 PSD 切件像素座標;
   實測 artist coverage 0.959/0.961/0.997 → 映射正確,免碰 atlas 0.70 縮放與 weighted bind 解算。
3. **新工具** `tools/mesh_gen/compare_award_mesh.py`:PSD 切件 alpha → `generate_mesh_v2` → 對照 Award
   藝術家 mesh 的 coverage / IoU / 頂點預算 / 拓樸 / 三角品質(sliver)。deform 閘標 N/A(此 3 件無 deform)。
4. **結果**:3 件全 `overall_pass`。生成 mesh 頂點 35/60/59(藝術家 78/98/80,少 25~55%),
   coverage/IoU 在藝術家基準 ±margin 內,**三角品質不輸真值**(光暈藝術家 sliver 0.55、我方 0.10)。
5. **負對照(第四次守則)**:縮小 0.5× → coverage 0.248(閘 FAIL);放大 1.4× → IoU 0.673(閘 FAIL)。
   閘有鑑別力、未過鬆。
