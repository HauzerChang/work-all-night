## 這次做了什麼(S3+S4 端到端:真實貼圖區 → S3 mesh → 對照 Award 藝術家 mesh)

推進 STATE 的最高優先候選(#1,有真值可比):把 S3 mesh 生成器接到真實生產標的做端到端驗收。

1. **定 AC**（AC-first）：對 Award 3 個 mesh 件(光暈/身體/左手),從真實貼圖區 alpha 生 mesh,對照藝術家 mesh:
   ①靜態輪廓 IoU ≥ 藝術家基準−0.02(核心閘)②有效性(0 孤兒/退化、重心在內)③頂點預算≤64 ④Spine 格式 ⑤變形探測。
2. **探測結構**：確認 3 件在 Award 中皆 `type=mesh`,aspect<1.2(→v2 auto 走 v1 Delaunay),**無 per-vertex deform**。
   進一步發現 `len(vertices)≠nv×2` → **三件全是 weighted mesh(骨骼蒙皮)**。
3. **新工具** `validate_against_award.py`:能處理 weighted 目標 mesh(藝術家 IoU 走 `uvs`,不碰 weighted `vertices`),
   補上 `validate_against_real.py` 對 weighted 會崩的空缺;變形改用「轉移 main_draw curtain 場」的最壞情況探測(標註非主閘)。
4. **首輪結果**:身體/左手 PASS;**光暈 FAIL**(IoU 0.929<0.9595、1 孤兒頂點)。
5. **診斷+修正(1 輪內收斂)**:光暈 496×480、solidity 0.79(大且凹);v1 固定 `epsilon_frac=0.008` 不隨件縮放 →
   邊界欠取樣。改 v1 為 **auto-refine**:頂點預算內選「最細、0 孤兒」的邊界(掃 0.008→0.002)。
   → 光暈 IoU **0.929→0.966**、孤兒 **1→0**、nv 61≤64。
6. **回歸驗證**:main_draw 4 mesh(走 strip,不受此改影響)重驗全 overall_pass;Award 3 件全 overall_pass。
7. **視覺自驗**:`knowledge/figures/s3-award-mesh-compare.png`(藝術家紅 vs S3 綠疊 alpha)確認輪廓貼合、頂點更精簡。

## 關鍵結論 / 決策

- **端到端「真實貼圖→S3 mesh→對藝術家真值」在靜態輪廓+拓樸層級通過**;S3 頂點比藝術家精簡且覆蓋率相當/更高。
- ⭐**被真值點名的落差:生產 mesh 是 weighted(蒙皮),S3 只產 unweighted** → 下一步做 **S3 BBW 權重**,
  才能對照蒙皮件的「變形」而非只有靜態輪廓。兩種變形機制(unweighted deform / weighted skin)在真實資產並存。
- 又一次「評估器/生成器對真實件才暴露的問題」:固定 epsilon 對大凹件欠取樣 → 改 budget-bounded auto-refine。
- 變形探測誠實標註為非主閘(curtain 場對近方形機器人件是 apples-to-oranges;生產中這些件不做逐頂點 deform)。
