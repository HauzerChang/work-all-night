## 這次做了什麼(S3×S4 端到端:Award 件 → S3 mesh → 對照藝術家 mesh)

推進 STATE「下一步候選 #1(最高優先,有真值可比)」:把 S3 mesh 生成器對真實生產標的
(Award 機器人拆件的 mesh)驗收,端到端串起 S4(切件)× S3(生成 mesh)× 對照藝術家真值。

### AC(動手前定的可檢查目標)
對 光暈/左手/身體 3 件,generate_mesh_v2 產出的 mesh 需:
- AC1 覆蓋 IoU ≥ 藝術家 mesh 自身覆蓋基準(不用武斷 0.95,對齊藝術家)。
- AC2 setup pose 靜態幾何:0 自交 / 0 翻面 / 0 退化。
- AC3 頂點數 ≤ 藝術家 mesh 頂點數(預算)。
- 並判定 deform 閘是否適用(有無真實 deform timeline)。

### 做法與結果
1. 新增 `tools/mesh_gen/compare_award_mesh.py`:atlas 切件(CW derotate,已校正)→ v2 mesh
   → 覆蓋 IoU vs 藝術家基準 + 靜態幾何 + 頂點預算 + `has_deform` 偵測。
2. **發現①**:Award 12 anim 中,3 件 mesh **零 deform 幀** → 它們是 bone-weighted rig
   (靠骨頭動,非 mesh 逐頂點變形)→ run.md 要求的「真實位移場轉移閘」對這些件 **N/A**。
   對照 main_draw 窗簾(deform 驅動)才適用該閘。→ 變形品質屬 S5 骨綁權重,不在拓樸。
3. **發現②(第一輪 fail → 迭代)**:預設 v1 delaunay `epsilon_frac=0.008` 對大件邊界過疏
   (光暈 hull 只 14 點,IoU 0.929 < 藝術家 0.980)→ 3 件 AC1 全 fail。
   epsilon 掃描確認**覆蓋率由邊界取樣密度決定**(與 strip 的 rows 同理);`0.002` 為三件甜蜜點。
4. 把 `epsilon_frac` 參數接進 `generate_mesh_v2.generate`(預設改 0.002)。
5. **重跑 → all_pass=true**:
   - 光暈 73v/hull38 IoU 0.9832 ≥ 0.9795
   - 左手 67v/hull43 IoU 0.9913 ≥ 0.9681
   - 身體 77v/hull37 IoU 0.9926 ≥ 0.9760
   全靜態乾淨、全在頂點預算內。
6. **回歸**:main_draw 4 mesh(走 strip,不受 epsilon 影響)真實位移場 deform 閘全 overall_pass
   (含 shadow2 走共用 region `image/shadow`,invocation `--slot image/shadow2 --name image/shadow`)。

## 關鍵結論 / 決策
- mesh 的正確性判準取決於它**怎麼被驅動**:deform 驅動 → 位移場閘(拓樸耐拉伸);
  bone-weighted 無 deform → 靜態覆蓋 + 預算 + 幾何,變形交 S5 權重。閘會自動辨別。
- 覆蓋率 = 邊界密度(epsilon / rows),內部點不影響覆蓋。大 blobby 件需更密邊界。
- 誠實記錄:第一輪 3 件 fail,靠 epsilon 掃描定位槓桿後迭代通過(SOP:AC-first + 預算內自修)。
