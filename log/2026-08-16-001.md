推進 STATE「下一步候選 #1(最高優先、有真值)」:把 `robot_parts.psd` 的 3 個 mesh 件跑 S3 生成器,
對照 Award 真實藝術家 mesh 做量化驗收。純 CPU、自驅。

1. **新工具 `tools/mesh_gen/validate_psd_to_mesh.py`**:端到端 PSD件 → `generate_mesh_v2` → 對照 Award mesh。
   - 座標對齊:Award mesh uvs 為 region-local(0..1,實測);attachment w/h = PSD 件 +2px(1px 對稱 padding)。
     把 PSD 件 bbox alpha 置中貼進 (attW×attH) 畫布 → 生成 mesh 與藝術家 mesh 同座標系,IoU/拓樸可公平比。
2. **結果:production-critical(覆蓋率+格式)3/3 全過**(`overall_pass=True`):
   - 光暈 gen 50v iou 0.929 vs artist 78v 0.923;身體 gen 38v 0.965 vs artist 98v 0.947;
     左手 gen 41v 0.962 vs artist 80v 0.966。→ **自動 mesh 以約半數頂點達藝術家覆蓋率**。
3. **修真實缺陷 ①:生成器孤兒頂點 bug**。`generate_mesh.py` `filter_triangles` 濾掉凹形三角後留下孤兒頂點
   (光暈 5、身體 1),違反格式清潔度。加 `compact_vertices()`(丟未引用頂點、保序重編、hull-first 保持)。
   修後 3 件 0 孤兒;**main_draw 4 mesh 回歸全過(v1 curtain_left + v2 全 4)無退化**。
4. **修真實缺陷 ②:deform 韌性 gate 幅度未校準(第 4 次同類教訓)**。3 件無原生 deform → 用 curtain 真實
   位移場轉移當韌性探針。但 curtain 位移是絕對像素(314px),施於小件(左手 259px)= >120% 拉伸,
   **連藝術家真值都撕裂** → gate 不可信。改**依目標件寬高等比縮放**位移場(相對 warp 不變,≈90% 尺寸)。
   校正後藝術家真值 3 件全 clean → gate 可信;鑑別出**光暈(blob,aspect≈0.97,落 v1 散點)在極端 warp 自交**,
   藝術家 78-hull 邊界扇形則耐撐。因光暈實際 deform=0,此為 out-of-envelope 探針,單列不併入 milestone。
