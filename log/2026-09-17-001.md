## 做了什麼(全 additive)

1. **`tier_variants._amp_scale_coupled(x, g)`** — 體積守恆耦合 scale 幅度增益:取 `q=x−1`(scaleX≥1 的拉長軸)、
   放大 `q'=g·q`、scaleY 依 `1/(1+q')` 重算 → `scaleX'·scaleY'≡1`。`x==1`(identity)→ (1,1) 不動。
   **等同以生成器的 `Q→g·Q` 重生成 squash**(非事後 hack)。
2. **`tier_variants.amplify_bone_tl(b, g, coupled_scale=False)`** + `amplify_anim(..., coupled_scale=)` —
   `coupled_scale=True` 時 scale 走耦合 amplify(捨入 4 位,同生成器精度 → g=1.0 逐位元 == base、守恆誤差 ~1e-4
   ≪ TOL_VOL=0.02);`False`(預設)走原單軸 `_amp_scale`。shear/rotate/translate 兩路徑相同。
3. **`tier_variants.MAIN_SHOW_CATS`** 加入 `squash`;新增 **`COUPLED_SCALE_CATS={squash}`**。
4. **`gen_animations.build_animations`** — 產 tier 變體時 `coupled = cat in COUPLED_SCALE_CATS`,透傳
   `amplify_anim(..., coupled_scale=coupled)`(等比 scale 節拍仍走單軸)。
5. **`validate_squash_tier.py`**(新,6 AC)。
6. **`validate_tier_combo_count.py` K5c** — 排除 `SHEAR_CATS`(見下「決策」)。
7. **`check_readiness.py`** 新增 cap `squash_tier_amplitude` L2;手動更新 `skills/READINESS.md`(header + 矩陣)。
8. knowledge `s1-squash-tier-amplitude.md` + 索引;圖 `knowledge/figures/s1_squash_tier.png`。

## 決策 / 關鍵發現

- **通道的 amplify 規則由該通道的「幾何自由度結構」決定**,不能一體適用。等比 scale 是「上方 overshoot」
  單向自由度(J,只放大上方)、純 shear 是「對 0 對稱」自由度(G-4'',v'=g*v)、**耦合擠壓是「scaleX/scaleY
  綁定的單一 q」自由度**(本次,兩軸一起放大 q)。用錯規則(單軸放大耦合 scale)會破壞該通道不變量(體積守恆)。
- **K5c 假陽性修正(集中化維護)**:`impact_peaks` 是 combo 專屬「衝擊峰」偵測器(有 prominence 門檻),對
  squash 的**耦合擠壓 scaleX**(非衝擊列)會因幅度隨檔位跨過門檻誤數 [0,1,1,1] → 誤判為 count 外洩。實則
  squash 的段數(nosc)各檔位恆定,那是**幅度效應非 count 外洩**。解法=K5c 排除 `TV.SHEAR_CATS`(同 G-4''''
  抽 SHEAR_CATS 集中化,後續再加 shear/coupled 節拍只改一處)。squash 的檔位差異化屬**幅度軸**(由
  `validate_squash_tier` 管),不在 count-aware 閘範圍。
- **honest boundary 逐條接上**:G-4'''' 明確標記「squash 未接 tier(需耦合 amplify)」→ 本次直接照邊界補上,
  且新閘 crux 負對照(ST6b)把「為什麼不能用舊 amplify」變成可機讀守衛。
