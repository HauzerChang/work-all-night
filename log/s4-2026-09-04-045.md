# S4 chunk 45 — 2026-09-04(研究分流:圖片切割 vs 圖片切片/圖層分解)

## 觸發

使用者要求把「拆解」底下容易混為一談的兩種動作正式拆成兩個獨立研究區塊:

1. 圖片切割:符合使用者裁切部件的需求,邊緣允許破損。
2. 圖片切片(此處可能牽涉到補圖):將單層圖片切成多層——淺層應用:同一部位切出物件層/
   陰影層/光源層;深層應用:目標部位帶著遮擋物(如墨鏡),切出遮擋物層+底下被遮住的
   內容(如墨鏡底下的眼睛)。

## 執行

寫研究筆記 `knowledge/s4-cut-vs-slice-research-split.md`,先釐清兩者本質差異再分開處理:

- **切割是空間切分**:部件本來就在畫面上並排/前後疊放,幾何裁切+局部修邊就能還原成
  獨立圖層,原始像素資訊都還在,不需要無中生有。
- **切片是訊號分離/反推**:同一像素位置疊了多種效果,要把疊在一起的東西拆開,依「底下
  內容是否還留在畫面裡」分兩級:
  - 淺層(陰影/光源):底下資訊理論上都還在(只是被混合了),屬於訊號分解,有機會用
    傳統影像處理做到。
  - 深層(遮擋物底下內容):像素在原圖裡完全不存在,本質上一定要生成式模型腦補,跟
    CLAUDE.md「情境2視角外推」同一難度等級。

### 區塊1(切割):判定不需另開新研究

確認就是既有六階段拆解流程的第3點,技術路徑已在 chunk 44 驗證(ag-psd 讀寫)。使用者
明確授權「邊緣允許破損」,正式解除裁切階段追求完美邊緣的壓力——裁切可以用最簡單的硬
邊界矩形/多邊形,邊緣品質交給第4點 GPT 局部修補收尾(用生成模型「畫順」邊緣,比傳統
演算法猜怎麼羽化更可靠)。

### 區塊2(切片):新研究主題

**2a 淺層(物件/陰影/光源分離)**:提出具體構想——

1. 對部件圖做顏色量化/分群(色相-飽和度 k-means 或 flood-fill),找出面積最大的
   打底基準色。
2. 每個像素跟基準色比較:亮度降低+色相相近 → 疑似陰影(multiply 疊色);亮度提高/
   偏白偏冷 → 疑似高光(screen/add 疊色)。
3. 用對應 blend mode 反函數,從合成後像素+基準色反推陰影/光源層本身的顏色與 alpha。

可行性評估中等信心:blend mode 數學是成熟已知技術,風險在「基準色分群」這一步——若
美術是漸層厚塗、陰影形狀複雜,分群會失敗。**尚未用任何真實素材驗證**,純構想階段。

**2b 深層(遮擋物+底下被遮內容分離)**:判定本質是「補全」不是「分解」。遮擋物本身的
分離(如墨鏡形狀)仍屬區塊1切割問題(語意分析+使用者框選即可拆出);但底下被遮的內容
(如眼睛)像素在原圖裡完全不存在,只能用生成式 inpainting——API 呼叫模式雖然跟已驗證
的 candidate 17(masked edit)相同,但**用途完全不同**:candidate 17 驗證過的場景是
小範圍邊緣延伸(周圍上下文直接告訴模型該長什麼樣);這裡的 mask 是遮擋物完整
footprint,需要模型做更多語意推理(參考另一側沒被遮的五官、角色設定)。明確標注**不能
直接沿用 candidate 17 已驗證的可靠度結論**,需要獨立測試,且必然要花真實 API 費用才能
驗證(CPU-only 方法本質上做不到)。

## 誠實限制

- 本篇是研究筆記+方向掃描,不是可執行的實作規格。2a 的 blend-mode 反推構想完全沒有
  經過任何真實素材測試,可行性是推論不是已驗證結論。
- 沒有花費任何 API 額度,也沒有動任何 production 代碼。
- 2b 深層應用是否有實際需求(墨鏡只是使用者舉的例子)尚未確認,提醒使用者若無實際
  案例建議先擱置,避免研究資源投在假設性需求上(呼應 candidate 15 先前的擱置決定)。
