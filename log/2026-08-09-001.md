# 2026-08-09 — session 001

## 這次做了什麼(bounded chunk:PSD件→S3 mesh→對照 Award 真實 mesh)

推進 STATE「下一步候選 1(最高優先,有真值可比)」:把 S3 mesh 生成器端到端接到**第二個真實生產
spine(Award「機器人拆件」)**,對其 3 個 mesh 件(光暈/身體/左手)驗收。

1. **確認資產與環境**:所有資產(含 Award.png/Award2.png/robot_parts.psd/main_draw.png)已在 repo;
   CPU 套件(numpy/cv2/scipy/triangle)可用。
2. **診斷既有閘不適用**:Award 3 mesh 皆 **weighted**(`len(vertices)!=len(uvs)`)且**無 deform timeline**。
   `validate_against_real` 的 deform 閘 `real_deform_field` 讀 unweighted 攤平頂點 → 對 weighted **crash**
   (griddata shape 不符)。
3. **新閘 `tools/mesh_gen/validate_award_mesh.py`**(weighted-safe,誠實):靜態 IoU(vs 藝術家真值基準)
   + 拓樸/格式健全;deform 閘標 **N/A + 原因**(weighted 靠骨骼權重變形,無逐頂點 deform),不做零位移假通過。
4. **初測發現 + AC 迭代(2 輪內)**:光暈 fail —— 固定 `epsilon_frac=0.008` 對細節外框過度簡化
   (hull 14 → IoU 0.929 < 藝術家 0.9795;還留 1 孤兒頂點)。epsilon 掃描確認是取樣密度問題。
5. **修正:自適應輪廓密度**(`generate_mesh.py` 新增 `adaptive_boundary_points`,預設開):由粗到細降 epsilon
   直到填充 IoU 達 target 或 hull 逼近預算;並動態夾 interior 使總頂點 ≤ 64。deterministic、評估器回饋驅動,無 ML。

## 關鍵結論 / 教訓

- **mesh 頂點預算不該是單一硬值**:形狀複雜度決定所需邊界密度。自適應輪廓 + 總頂點夾 > 固定 epsilon。
- **里程碑**:S3 現已對「兩個」真實生產資產驗收(main_draw unweighted + Award weighted),涵蓋 weighted mesh 新類別;
  評估器對其誠實處理(deform N/A)。
- 又一次體現方法論:先確認閘可信/適用範圍,再下判定;不硬套不適用的閘做假性通過。
