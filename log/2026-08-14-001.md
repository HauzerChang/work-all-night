## 這次做了什麼(S3×S4 端到端:PSD 件 → mesh → 對照真實 Award mesh)

承 STATE 的「下一步 (1) 最高優先」:把 S3 生成器對真實生產標的 + 真值拓樸做端到端驗收。

### AC(動手前定的可檢查目標)
對機器人 3 個 mesh 件(光暈/身體/左手),生成 mesh 需:
① 靜態覆蓋 IoU ≥ 藝術家真實 mesh - 0.03(共同框內);② 頂點數 ≤ 藝術家(預算);
③ 格式合法 / 0 孤兒 / 重心全在 mask 內。評估器需先過自一致性 pre-check。

### 步驟
1. **切 PSD**:`psd_slice.py` 切 `robot_parts.psd` → 5 件(光暈/右手/頭/身體/左手)。
2. **選共同框**:先驗「Award mesh uvs 疊 PSD 件 alpha」IoU = 0.949/0.948/0.977 → **uvs 是 region-local**
   (推翻 s4 筆記「需轉 atlas UV」的過度保守假設),PSD 件(未旋轉/未 0.70 縮)即為最高保真共同框。
3. **寫工具** `tools/mesh_gen/validate_psd_to_mesh.py`:PSD 件 alpha 當 mask → 藝術家 mesh baseline IoU
   → `generate_mesh_v2(auto)` → `evaluate_mesh` → 逐 AC 判定。
4. **跑驗收**:3 件全 `overall_pass`(exit 0)。
5. **視覺確認**:`knowledge/figures/psd-to-mesh-robot.png`(藝術家橘/生成綠線框疊 alpha)。

## 關鍵結論

- **端到端成立**:生成器對真實 big-win 主角件、對藝術家真值拓樸,**同級覆蓋、頂點更省**。第一次脫離窗簾/合成。
- **auto 啟發式對**:3 件長寬比 < 1.2 → 全路由 v1 Delaunay(strip 只適合窗簾式單向長條)。
- **Award uvs = region-local**:更新對真實生產檔的認知,簡化後續對照(不需 atlas UV 轉換)。
- ⚠️ **誠實界定**:只驗**靜態**。件為 weighted(無 deform timeline)、生成為 unweighted →
  **未**驗「動畫下正確變形」。這是 S3 唯一剩下的真值缺口。
- **軟邊觀察**:光暈粗 hull(16)裁掉羽化細突起(0.933);軟放射形狀宜調低 epsilon 加密 hull。
