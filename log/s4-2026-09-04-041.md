## 過程:取檔(核心技術挑戰)

1. 使用者是透過對話直接貼圖,不是給本機路徑、也不是走任何上傳到可存取位置的機制。
   `find / -iname "*.png" -mmin -N` 等多輪嘗試都找不到任何對應檔案——確認這個排程容器
   沒有現成工具能把「對話裡貼的圖」直接存成檔案。
2. 想到 Claude Code CLI 會把整個 session 的完整逐輪記錄(含 base64 編碼的圖片內容)寫成
   JSONL,存在 `~/.claude/projects/<repo路徑對應目錄>/<session-id>.jsonl`。用
   `grep -c base64` 確認該檔確實含大量 base64 內容(274 處命中)。
3. 寫 Python 腳本遞迴解析 JSONL 每一行的 JSON 結構,找
   `{"type":"image","source":{"type":"base64","media_type":...,"data":...}}` 這種內容
   區塊,把 `data` 欄位 base64 解碼寫成檔案。跑出 4 張圖:1 張 1024×1536 webp(尺寸符合
   先前肉眼判斷的角色設定圖比例)、3 張是本 session 稍早我自己產出送給使用者的比較圖
   (candidate15/17 視覺化,寬扁比例明顯不同)。用 Read 工具開 1024×1536 那張確認正是
   使用者貼的角色設定圖。

## 過程:裁出角色主圖

1. 用 OpenCV 嘗試自動偵測面板框線(Canny 邊緣偵測 + 輪廓分析,篩選左上區域大矩形)——
   **失敗**,找不到任何符合條件的候選矩形。原因:這張圖的背景本身是有暗紅漸層/紋理的
   (不是乾淨黑色或留白),面板框線在此紋理背景下不構成穩定可偵測的邊緣輪廓。也試過用
   逐行/逐列像素統計(找低變異的分隔線)找垂直邊界,同樣因背景非純色而失敗。
2. 改用**視覺疊代**:裁一個估計框→用 Read 工具實際看結果→依看到的瑕疵調整座標→再裁,
   3 輪收斂到 `(x0,y0,x1,y1) = (0, 46, 460, 944)`(對 1024×1536 畫布,即
   `0%, 3%, 45%, 61.5%`)。第一版裁太緊(靴底/尾巴邊緣被切到);第二版跳過標題文字但切到
   耳朵尖端;第三版(最終)五官/雙耳/全部靴底/尾巴邊緣皆完整在框內,左上角殘留一點點
   標題文字/引言裝飾,判斷不影響下游使用,未進一步去除。
