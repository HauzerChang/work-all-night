## 這次做了什麼(S3×S4 端到端:PSD→件→S3 mesh 對照 Award 真實生產 mesh)

接手續跑。從 `STATE.md` 挑最高優先 bounded chunk:**用機器人 mesh 件跑 S3 生成器,對照 Award 真實 mesh**
(有真值、純 CPU 可自驅)。

1. **定位 Award 中 3 個 mesh 件**:`機器人拆件/光暈`(78v)、`/左手`(80v)、`/身體`(98v),皆 weighted。
2. **AC 定義**(可量測):生成 mesh 靜態 IoU ≥ 藝術家自身 mesh IoU(用藝術家真值當基準,非武斷 0.95);
   若件有 deform timeline 再加真實位移場轉移閘。
3. **首輪對照**(v2 auto → 因 aspect<1.2 落 delaunay-v1,預設 eps=0.008):
   光暈 0.929(< 藝術家 0.980,FAIL)、左手 0.960、身體 0.968(略低於藝術家)。
4. **診斷 + 自我修正迴圈**:光暈缺口是**邊界取樣太粗**(14-gon hull)。epsilon 掃描確認覆蓋率由 hull
   密度決定、`max_interior` 無關;`eps=0.002` → 78v(恰等藝術家)、IoU 0.983 已超越藝術家。
   對齊藝術家頂點預算(`eps=0.0015`)後 3 件全 ≥ 藝術家:光暈 0.988、左手 0.993、身體 0.993。
5. **抓到並修掉一個評估器陷阱**:這 3 件**無 deform timeline**(bone-weighted,靠骨骼變形)。
   `de.real_deform_field` 對無 deform frame 回**零位移場** → 套用後幾何必「乾淨」= **假性通過**。
   修 `validate_against_real.py`:偵測 `frame is None` → deform 閘標 `applicable:false`,
   `overall_pass` 只採信靜態 IoU。加 `--epsilon` 參數、`artist_vertices` 輸出。
6. **驗收**:3 件 harness `overall_pass=true` 且 exit 0;main_draw curtain_left v2 回歸測試仍走真實 deform 閘且過。
