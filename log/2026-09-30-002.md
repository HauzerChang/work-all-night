# 2026-09-30 run 002 — S1 (J-5) cascade 波方向由空間位置決定

## 這次做了什麼(bounded chunk)

推進 STATE 建議的 **(J-5)**:cascade 波**方向**由空間位置決定 —— 跨件時序通道的**第三條正交軸 = 方向(相位來源)**。
繼結構(nrip,J-3:掃幾道波)、幅度(span,J-4:一道多開)之後,補上「波往哪個方向掃」。

至今各件相位一律由**件序**決定(`phase=pi/(n−1)`),波方向 = 件在規格清單 `parts` 的排列,與件在畫面上的空間位置無關。
本次讓相位來源改由**空間位置排名**決定:

| mode | 排名鍵 | 波方向 |
|---|---|---|
| `order`(預設) | 件序 | 舊行為(逐位元相容) |
| `x` | 件中心 `bd.x` 升序 | **左→右**(x 小者先亮) |
| `radial` | 件中心到畫布中心距離升序 | **中心→外擴**(近者先亮) |

相位仍以**排名** `rank/(n−1)` 均勻映到 [0,1] → span/nrip/幅度語意**全部不變**;平手以件序打破(確定性)。

## 核心新意(honest distinction)

相位來源軸與前兩軸的**機制分野**:它**既不重生成關鍵幀窗(不像 nrip/span)也不做值增益(不像 J 深度)** ——
只是把**同一組峰時刻重新指派**給不同的件(a permutation of who-peaks-when)。由此兩個強斷言:

1. **峰時刻多重集合三模式相同**(真實骨架 {0.158,0.296,0.429,0.567,0.70},只是指派給不同件)→ 證與 span/nrip/深度**正交**。
2. **真實 robot 件序 ≠ x 序 → 方向真的改變**:件序 `[光暈,右手,頭,身體,左手]`,但 `右手 x=320.5 < 光暈 x=359.0` →
   x 模式下**右手與光暈 who-peaks-first 互換**(order 光暈先 τ=0.158、x 右手先 τ=0.158),同一骨架只換相位來源。

## 關鍵發現
