## 做了什麼

1. **`estimate_alpha_taper` 新增診斷用 `debug`(dict,選填)與 `min_ring`(參數化,不傳則沿用
   舊行為的呼叫端完全不受影響)**:`debug` 回傳 `ring_count`/`used_fallback`/`local_grad`/`ell`,
   讓外部量化腳本能觀察每次呼叫的內部狀態而不用重寫核心邏輯。
2. **新增 `tools/mesh_gen/s4_alpha_taper_robustness.py`**:跨 12 個材質(機器人拆件 5 層全部;
   Symbol_Ww 7 層,含之前沒測過的 底/頭/身體/墨鏡/wild)、`punch_hole` circle(6 種 frac ×
   interior/edge)+ ellipse(4 種 aspect × 3 種 frac × 3 種 angle,只支援 interior)、3 個
   seed,共 1233 次取樣。記錄每次的 `ring_count` 與實際 `alpha_mae`(洞區域 alpha 估計 vs
   真值)。
3. **假設檢驗結果**:按 `ring_count` 分桶,`[5,10)`/`[10,20)` 兩桶 mae 平均 4.3~12.2、最差到
   139.9——確認候選 10 撞見的 n=7 案例不是單一意外,是「剛好卡在舊門檻 5 之上、樣本仍不足以
   讓中位數穩定」的一整個縫隙。`[0,5)` 桶(舊門檻本來就會退回全域 fringe)mae 近乎 0——退回
   全域對這批材質一直是安全的。
4. **門檻決策用資料驗證,不是猜的**:對候選 `min_ring∈{10,15,20,22,25,28}`,重跑因門檻改變
   而切換到全域 fallback 的案例,量測 mae 變好/變壞/不變:20~22 是最後「零負面案例」的安全帶
   (25 起出現 2 個因誤傷有效局部樣本而變差的反向案例,28 惡化到 12 個)。**採用
   `min_ring=20`**(留安全餘裕)。
5. **回歸驗證(修改前後同一份程式碼分別跑,完整 JSON/文字輸出逐位元 diff)**:
   - 機器人 3 材質(光暈/身體/左手)interior+edge:文字摘要 diff 為空。
   - `real_occlusion_eval.py`(8 組真實遮擋洞):完整 JSON diff 為空。
   - Symbol_Ww `框`/`臉部陰影` interior(既知 tone_gap 限制,candidate 8):完整 JSON diff 為空。
   - `psd_inplace_patch.py --auto --mode edge`(左手):除輸出檔名外 JSON diff 為空。
   全部零反向,因為這三組案例的 `ring_count` 剛好都落在不受此次門檻調整影響的桶
   (`[0,5)` 或 `[50,∞)`)。
6. **新發現候選 14(誠實範圍界定,本次未修)**:同一批 1233 筆資料裡,也有 `ring_count` 很大
