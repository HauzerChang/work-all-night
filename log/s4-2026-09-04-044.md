## 執行

任何 API):

- **載入圖片**:拖曳或 file input,單張 PNG/JPG(含 `psd_slice.py` 匯出的
  composite.png)。
- **載入建議(選填)**:讀 Claude 產出的 part list JSON,依目前圖片尺寸把 `bbox_pct`
  換算成像素框,套用信心色(綠 high / 黃 medium / 紅 low / 藍 user_confirmed),`bbox_pct`
  含 `null` 的項目自動跳過(對應 schema 允許「完全無法定位、留給使用者從零框」的情況)。
- **canvas 互動編輯**:`baseCanvas` 顯示圖 + `overlayCanvas` 疊框。空白處拖曳畫新框;
  點框選取(右側可編輯 id/label/confidence/notes);拖曳框內部移動;拖曳四角 handle
  (6px 容許誤差)調整大小;Delete/Backspace 刪除(輸入框有焦點時不觸發);Esc 取消選取。
- **右側部件清單**:即時同步數量/顏色/標籤,可點選/點 × 刪除。
- **匯出決策檔**:JSON(`source_image`/`image_size`/`generated_by`/
  `parts:[{id,label,confidence,notes,bbox_px:[x0,y0,x1,y1]}]`),座標用**像素**(跟
  輸入建議檔的百分比刻意不同),供下游第3點直接整數裁切不用再換算。

## 順帶完成:PSD 寫入路徑驗證(關閉 chunk 43 技術問題#2)

chunk 43 留下的疑點:「PSD 轉換」(第3點)技術路徑未定,現有 Python pipeline 只有讀 PSD
能力。用 Playwright 直接呼叫瀏覽器端 `ag-psd`(專案已在用這個函式庫做 PSD 讀取)的
`writePsd()`:

- 建構 2 層測試 PSD(100×100 畫布,`part_head` bbox (10,5,50,35) 紅色、`part_body`
  bbox (20,40,80,90) 藍色),用 `writePsd({width,height,children:[...]})` 產出
  `ArrayBuffer`,存成 `.psd` 檔。
- 用**獨立的** Python `psd-tools`(不是同一套函式庫,交叉驗證才有意義)重新讀取:
  畫布尺寸 100×100、兩層名稱/bbox/像素顏色**全部精確匹配**輸入值。

**結論**:`ag-psd` 讀寫能力都足夠,第3點「裁切結果組回 PSD」不需要另尋 `pytoshop`
等替代方案。測試後清除暫存 `.psd` 檔(不留在 repo)。

## 誠實限制

- 這個 viewer 只做「使用者確認邊界」,完全不做任何影像處理(不裁切/不生成/不呼叫
  任何 API)——裁切執行是下一步(第3點),要交還給 Claude 讀決策檔後用 Python 做實際
  幾何裁切。
- 框與框之間沒有防呆:允許重疊、允許超出畫布邊界(`bbox_px` 可能是負值或超過圖片
  寬高),第3點裁切時要自行 clamp;`id` 重複已擋且跳出提示,其餘無驗證。
- 沒有復原(undo)機制:清空全部有二次確認,單一部件刪除沒有。
- 只支援單張圖,不支援直接載入 PSD——來源是 PSD 要先用既有工具匯出 composite PNG。
- PSD 寫入驗證只是 2 層 100×100 的最小可行性測試,不是第3點的完整實作(例如沒測試
  半透明/裁切遮罩/圖層順序等真實場景可能遇到的細節)。
