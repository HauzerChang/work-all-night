# 2026-06-27 — session 001

## 這次做了什麼(S3 端到端對 Award 真實 mesh 驗收 + 自適應覆蓋)

接 STATE 候選 #1(最高優先、有生產真值、純 CPU 可自驅):用 Award 機器人拆件的 3 個真實
mesh 件當 ground truth,量化 S3 生成器與藝術家的差距。

1. **對齊基礎(比對有效性 gate)**:確認 Award mesh `uvs` 為 region-local [0,1](非 atlas 全域);
   `atlas_crop.extract`(CW)還原上正件,藝術家 `uvs×(W,H)` 填回 alpha **alpha-IoU 0.968~0.980**
   → 比對座標系一致、extract 方向正確。先過這關才信後續判定(遵 RULES「閘要先驗可信」)。
2. **基準對照**:預設 epsilon_frac=0.008 對 3 件 blobby 生產 mesh **全部低於**藝術家覆蓋
   (光暈 0.929<0.980、身體 0.968<0.976、左手 0.960<0.968)。三件皆 aspect<1.2 → auto 正確回退 v1 Delaunay。
3. **參數掃描 → 發現**:IoU 由 hull 密度(epsilon_frac)決定、max_interior 幾乎不影響
   —— 與 v2 strip「IoU 由 rows、cols 不影響」同一結論,對 blobby 件亦成立。
4. **新增自適應覆蓋(opt-in,零回歸)**:`generate_mesh.generate(target_iou=, vertex_budget=)`
   沿 eps 階梯加密輪廓,取「達標且最省點」解;預算內達不到回退最高覆蓋並標 `_budget_capped`。
   target_iou=None 時 byte-identical 舊行為(已驗)。`generate_mesh_v2` 透傳。
5. **結果**:budget=100(≈藝術家密度)時 **3/3 達或超過藝術家覆蓋,且用更少頂點**
   (光暈 73<78、身體 69<98、左手 57<80),static AC 全過。budget=64 僅 1/3 → 量化
   **64 預算 vs 藝術家密度(78–98)的張力**(細緻近圓件如光暈需 ~73v)。
6. **回歸**:main_draw `validate_against_real --gen v2` 4 mesh 仍全 PASS(exit 0;走 strip 不受影響)。

## 關鍵結論 / 教訓

- **S3 通用性再擴一類真值**:從「strip unweighted(main_draw)」擴到「blobby weighted(Award 生產件)」,
  給足預算即可達/超藝術家覆蓋。生成器本身不是瓶頸,**參數(輪廓密度)與預算選擇**才是。
- **覆蓋率是輪廓(hull 密度)性質**,兩種拓樸一致 → 自適應只需調 epsilon/rows 這一個旋鈕。
- **預算 vs 保真張力**屬主觀/專案決策(里程碑審查項),非客觀失敗;客觀面「可達標」已證。
- 對齊 gate 先行(alpha-IoU 0.97)是這次能信任 IoU 判定的前提。
