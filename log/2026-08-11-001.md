## 這次做了什麼(bounded chunk:S3 端到端對真實 Award mesh 靜態驗收)

接續 STATE.md 最高優先候選:**PSD/atlas 件 → S3 mesh → 對照 Award 真實藝術家 mesh**。
標的:`機器人拆件/光暈 | 身體 | 左手`(Award big win spine 裡的 3 個 mesh 件,有 ground truth)。

### AC(可檢查驗收目標)
1. 校準:藝術家自身 mesh 光柵化對 atlas 切件 alpha 自身 IoU 高(證座標映射正確)。
2. 生成 IoU ≥ 藝術家自身 IoU(以藝術家覆蓋率為基準)。
3. 靜態品質閘:0 退化 / 0 孤兒 / 重心全在 mask 內 / 合法 Spine 格式。

### 過程與結果
1. **校準(評估器可信度先驗)**:藝術家 uvs*(W,H) 對 atlas 切件自身 IoU =
   光暈 0.9795 / 身體 0.9760 / 左手 0.9681 → 座標映射正確(含 2 件 rotate=true 由 atlas_crop derotate 對齊)。
   順帶排除「身體 uv-x 只到 0.759」的疑似錯位(自身 IoU 高證明只是未占滿寬度)。
2. **首跑生成器(預設 epsilon 0.008)**:3 件 IoU 0.927/0.969/0.960 全 < 藝術家 → **fail**。
   診斷:預設邊界簡化太粗(hull 僅 14~21),追不上這批 dense/複雜輪廓(藝術家 78~98v)。
3. **IoU 準則迭代(epsilon 掃描,預算內)**:0.008→0.004→0.002→0.001。
   **epsilon_frac=0.002** 為甜蜜點:hull 37~43,3 件 IoU 0.983/0.993/0.991 全過藝術家,頂點數落在藝術家鄰域。
4. **落地**:把 epsilon(及 max_interior/min_dist)透傳進 `generate_mesh_v2.generate` + CLI `--epsilon`;
   **不改 auto 預設**(保住已驗的 main_draw 4 mesh)。寫可重現工具 `validate_award_static.py`。
5. **最終驗收**:`validate_award_static.py` → 3 件全 overall_pass,**exit 0**。
   (工具用預設 interior,生成僅 67~77v 甚至 < 藝術家,IoU 仍全過 → 再證覆蓋率只吃邊界密度。)

## 關鍵結論
- **端到端「真實 atlas 切件 → S3 mesh → 對照藝術家真值」對生產標的成立**(里程碑:合成/main_draw → 真實 Award)。
- **dense 件 IoU 由邊界簡化 `epsilon_frac` 決定**(0.002 甜蜜點)。這是 v2 strip「IoU 由 rows 決定、
