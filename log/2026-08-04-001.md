# 2026-08-04 — session 001

## 這次做了什麼(排程 session:S3 端到端對真實生產 mesh 驗收)

推進 STATE 的最高優先候選 1：**PSD件 → S3 mesh → 對照 Award 真實 mesh**（有真值、純 CPU 可自驅）。

### AC（動手前定的可檢查目標)
- 對機器人 3 件 mesh(光暈/身體/左手,Award 中為 mesh)用生成器產 mesh,在**同一張真實貼圖**上
  比對三角覆蓋 IoU vs Award 藝術家真實 mesh 的覆蓋 IoU。
- PASS 條件:生成 IoU ≥ 藝術家 baseline − 0.03,且頂點數在預算內。

### 做的事
1. **新增 `tools/mesh_gen/validate_robot_mesh.py`**:真值取 `assets/Award.json`,atlas 切真實貼圖
   (`extract`,已含 CW derotate+多頁)→ 生成 mesh → 覆蓋 IoU vs `artist_iou`。
2. **關鍵辨識**:這 3 件是 **weighted(骨骼驅動)、無 deform timeline**(與 main_draw 4 mesh 的
   unweighted+deform 不同)→ 逐頂點 deform 轉移閘**不適用**,改做靜態覆蓋對照(誠實記錄限制)。
3. **首跑(固定 ε=0.008)**:身體 0.968 / 左手 0.960 **PASS**;光暈 0.929 vs 藝術家 0.980 **FAIL**(gap 0.05)。
4. **參數掃描診斷光暈**:`max_interior` 40↔60 對 IoU 幾乎無影響;`epsilon_frac` 0.008→0.003 使 hull 14→32、
   IoU 0.929→0.978(追平藝術家)。→ **覆蓋率由 hull 密度決定、interior 無關**(再證 S3 定律)。
   藝術家對光暈本人用 78 頂點(超出 64 budget)→ soft glow 預算偏緊。
5. **修法(opt-in,不動主線)**:`generate_mesh.generate_adaptive()` 掃 ε 由粗到細,回傳「達 iou_target
   的最粗 hull」但不超 vertex_cap。`validate_robot_mesh --adaptive` 用 per-shape 預算=藝術家頂點數+4。
6. **回歸驗證**:main_draw curtain_left v1/v2 皆 overall_pass(exit 0)→ 主線無回歸。
