# 2026-08-04 — session 001

## 這次做了什麼(S3 端到端:真實生產貼圖件 → 生成 mesh → 對照 Award 真實 mesh)

接 STATE「最高優先(有真值可比)」候選:用機器人 3 個 mesh 件對照 Award 生產 mesh,把
「素材件 → S3 生成 mesh」對**真實生產標的**閉環驗收。

1. **對照框架**:新工具 `tools/mesh_gen/validate_award_mesh.py`。以 **Award atlas 切件**
   (`atlas_crop.extract`,多頁+CW derotate)為共同座標系 → 我方 mesh 與 Award 真實 mesh 的
   region-local UV 同框,IoU 直接可比。三閘:cover(我方 IoU ≥ 藝術家−1%)/ budget(頂點 ≤ 藝術家)/
   clean(setup 0 自交)。
2. **初驗抓到 FAIL**:光暈覆蓋率 0.929 < 藝術家 0.980(身體/左手已過)。
3. **診斷(掃描)**:覆蓋率**單調隨邊界密度上升、幾乎不隨內部點變化**(maxint 0→40 同 IoU)——
   與 S3 strip「IoU 由 rows 決定、cols 不影響」同構。根因:`epsilon_frac` 周長相對 → 大而平滑的
   光暈(周長 1927px)得到 ~15px 絕對 epsilon,DP 切過平滑曲線 → 覆蓋率不足。
4. **修正**:`generate_mesh.py` 加**絕對像素容差** `epsilon_px`(預設 2px,向後相容;CLI `--epsilon-px`);
   `generate_mesh_v2.py` blob 回退 Delaunay 改 `max_interior=12, epsilon_px=2`(內部點對覆蓋率無益,
   調精簡以守頂點預算)。
5. **重驗 ALL PASS**:光暈 0.992/68v、身體 0.993/49v、左手 0.988/48v —— 覆蓋率全**超過**藝術家、
   頂點數 0.5–0.6×、0 自交。
6. **無回歸驗證**:main_draw 4 mesh 走 strip(不觸 Delaunay);`validate_against_real --gen v2`
   4 件全 `overall_pass`(strip,IoU 0.933/0.933/0.955/0.955)重驗通過。

## 關鍵結論 / 決策

- **首次對真實生產 mesh 閉環**:生成器對真實標的不只達標、還更精簡,靜態拓樸站得住。
- **覆蓋率 = 邊界擬合密度**(兩種拓樸各自版本:strip=rows、Delaunay=epsilon_px);內部點只服務
  變形品質,不服務靜態覆蓋率 → 頂點預算該花在邊界。
- **絕對像素容差 > 周長相對**:DP 容差本質是「對真實輪廓的固定像素偏差」,與件大小無關;
  周長相對會讓大件失準。已設 `epsilon_px=2` 為預設。
- **誠實聲明**:Award 3 件是 weighted+無 deform timeline,本輪只驗**靜態**;weighted-mesh deform
  對照(需 BBW 權重生成)列為後續。
