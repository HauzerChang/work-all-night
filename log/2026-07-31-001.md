# 2026-07-31 — session 001

## 這次做了什麼(S3 端到端對照第二生產資產 Award — 靜態覆蓋率)

接 STATE「下一步」最高優先候選(1):PSD 件 → S3 mesh → 對照 Award 真實 mesh。
`Award` 是機器人拆件對應的生產 spine(77 bones/47 slots),與 `main_draw` 不同來源 → 推廣驗證。

1. **盤點目標**:Award 機器人 3 件 `機器人拆件/{光暈,左手,身體}` 在 Award 中是 **weighted mesh**
   (78/80/98 頂點)。查 deform timeline → **這 3 件無任何 deform**(純骨骼蒙皮),故 deform 閘 N/A。
2. **寫端到端驗收工具** `tools/mesh_gen/validate_award_static.py`:
   PSD 件(robot_parts.psd 圖層 composite)→ 剪影 ⇄ atlas region 一致性 IoU → `generate_mesh_v2`
   → 生成覆蓋 IoU(evaluate/vertices) vs 藝術家覆蓋 IoU(uvs+triangles,weighted-safe)+ 頂點預算。
3. **跑出結果 + 發現**:default preset 下 3 件覆蓋率略低於藝術家(光暈 −0.046、左手 −0.004、身體 −0.009)。
   探因:光暈是柔邊 glow(單輪廓無孔),default `epsilon_frac=0.008` 過度簡化 spiky 邊 → 欠覆蓋。
   密度掃描證**覆蓋率由輪廓取樣密度界定**:eps 0.008→0.001 使 nv 37→136、IoU 0.934→0.992 單調。
4. **公平判準**:加 `gen_budget_matched`(對齊藝術家頂點預算取覆蓋率最高)+ margin **0.015**
   (三角化雜訊地板:藝術家自身也僅 0.968–0.980)。→ **all_static_pass=True**:光暈預算對齊 103v→0.988
   超越藝術家;左手/身體 default 更省即在雜訊內達標(59–60v vs 80–98v)。
5. **評估器可信度(先驗負對照)**:evaluate(吃 vertices)頂點內縮 75%→0.559;artist_iou(吃 uvs)
   uvs 內縮 70%→0.506 → 兩者皆有鑑別力。修正一次假陰性(初版打錯欄位:對 evaluate 擾動 uvs 無效)。

## 關鍵結論 / 決策

- S3 生成器**推廣到第二個生產資產成功**:對 blobby 機器人部件靜態覆蓋率達生產品質,不只窗簾/陰影。
- **覆蓋率 = 輪廓密度的旋鈕,不是拓樸缺陷**;「省頂點」與「追平藝術家」是兩個獨立故事,分開報。
- 誠實邊界:3 件無 deform → 沒驗變形;生成 unweighted 未做 BBW 權重/骨綁 → 未真正取代生產 mesh。
