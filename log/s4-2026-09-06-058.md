# S4 chunk 58(2026-09-06)— `head`/`sash_train` 點提示測試,第三份 production PSD

## 動機

chunk57 誠實限制清單留下 `head`/`sash_train` 兩者:自 chunk47/54 起就被 heuristic 正確
標記 `low_confidence`(fragmented)的兩個部件,一直未測過點提示(`skirt` 已在
chunk55-57 測過並落地,`bodice`/`sleeve_right` 已測 4 次無效是 A 類岔路)。STATE_S4.md
沒有明確候選清單指名這兩者,但依既有慣例(chunk49/55 皆是承接前次記錄的誠實限制、
無活人裁決時執行不需授權的下一步),這是唯一「已知有效方法論(點提示)、尚未套用到的
候選」,零成本、純 CPU、可自驗。本次執行。

## 做了什麼

1. 重裝環境依賴(容器不持久化,沿用 chunk54/56/57 記錄的可重現指令):下載
   `mobile_sam.pt`(sha256 核對通過)、`git clone` MobileSAM 原始碼、
   `pip install torch timm`。
2. 用 chunk57 `decision_final.json` 的框重跑純 box-only SAM,重現 `head`/`sash_train`
   的 fragmented baseline(數字與 chunk47/54 記錄一致)。
3. 額外檢視 box-only SAM 回傳的**全部 3 個候選遮罩**(不只是被 `argmax(scores)` 選中
   的那個),發現乾淨/單一連通的候選其實已經存在,只是分數不是最高——這是先前
   `bodice`/`sleeve_right`(候選全選錯)、`skirt`(純box缺方向性)之外的**第三種病因**。
4. 格線疊圖定位座標,測點提示組合(比照 chunk55 方法論),`head`/`sash_train` 皆找到
   讓 `low_confidence` 轉為 `false` 的點組合。
5. 把驗證過的點疊加進 chunk57 `decision_final.json` 基準(逐 part 比對確認其餘 18
   部件位元級不變),重跑完整 `s4_decompose_cut.py --contour sam --eval` →
   `manifest_to_psd.js`,產出 `jiuwei_yanlian_decompose_sam_v2.psd`(20 圖層)——
   第三份 production PSD。
