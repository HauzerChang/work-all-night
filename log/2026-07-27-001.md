# 2026-07-27 — session 001

## 這次做了什麼(S3 對 Award 真實生產 mesh 端到端驗收)

接續 STATE 最高優先候選:用 Award spine 的機器人 mesh 當真值,驗 generate_mesh_v2。

1. **定位真值**:Award.json 中機器人拆件 3 個 mesh(光暈 78v / 身體 98v / 左手 80v),
   皆 **weighted**;逐一掃 12 支動畫 → **無任何 deform timeline 觸及這 3 件**(靠骨骼變形)。
   PSD `robot_parts.psd` 圖層 bbox 與 Award attachment 尺寸吻合(+2px),確認同素材。
2. **抓修評估器 crash**:`validate_against_real` 無條件跑 deform-transfer,對 weighted mesh 把
   `vertices`(`[骨數,骨idx,bindXY,權重,...]` 變長格式)誤 reshape 成 Nx2 → 與 uvs 數不符 →
   scipy griddata `ValueError`。這暴露評估器只為 unweighted+deform(窗簾)設計。
3. **老實化 deform 閘**:改 `validate_against_real` 先判 `weighted` 與 `has_deform`:
   - 無 deform → `AC_real_deform.applicable=false`(靠骨骼),overall 只看 IoU;不 trivially pass 造假訊號。
   - weighted+deform → 標 applicable=false(轉移尚未支援 weighted)。
   - unweighted+deform → 原窗簾閘。報告加 `slot` / `artist_mesh` 欄位。
4. **IoU 迭代(預算內)**:預設 eps=0.008 對機器人 blobby 件太粗(光暈 IoU 0.929 < 藝術家 0.980)。
   掃 epsilon:0.002 為 3 件全過的最小值,且 hull(38/37/43)、nv(73/77/67)接近藝術家精簡度。
   確認 main_draw 4 mesh 全走 **strip 模式**(不吃 epsilon)→ 改 delaunay 回退預設 eps=0.002 無回歸。
5. **重驗**:3 機器人 mesh 靜態 IoU **全 PASS**(0.983/0.993/0.991 ≥ 0.980/0.976/0.968,頂點更少);
   main_draw 3 mesh 回歸重驗仍全 PASS(strip、真實 deform 乾淨)。

## 關鍵結論 / 教訓

- **S3 對真實生產 mesh 端到端(PSD→spine→S3)靜態覆蓋率驗收通過**:生成 mesh 覆蓋 ≥ 藝術家、更精簡。
- **hull 密度(epsilon)需隨輪廓複雜度調**:窗簾平滑 vs 機器人複雜;0.002 對兩類都安全。
- **評估器要對「不適用」老實**:weighted/骨骼驅動 mesh 沒有 deform timeline,強跑 deform 閘不是 crash
  就是假 pass。標 N/A 才誠實(呼應 RULES「閘要可信」)。
- **揭露真正的 gap**:機器人靠**骨骼權重**變形,現有 deform_eval 無法驗其變形穩健性 → 下一個評估器。
