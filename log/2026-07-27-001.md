# 2026-07-27 — session 001

## 這次做了什麼(S3 端到端對照生產 mesh + 自適應 epsilon)

推進 STATE 最高優先 bounded chunk:端到端「PSD 件 → S3 生成 mesh」對 `Award` 生產 spine 的
3 個 warp 件(光暈/身體/左手)做**靜態覆蓋率**對照(有真值、純 CPU 可自驅)。

1. **探查真值**:確認 Award 這 3 件是 **weighted mesh(vertices≠uvs 長度)、無 deform timeline**
   —— 骨驅動,與 main_draw 4 件(unweighted+deform)機制根本不同。故 deform 閘不適用,只驗靜態幾何。
2. **寫對照工具** `tools/mesh_gen/validate_robot_parts.py`:atlas_crop 取去旋轉 region 當共同遮罩,
   量「生成 mesh 三角覆蓋 IoU」vs「藝術家 mesh uvs 光柵化覆蓋 IoU」(apples-to-apples,同遮罩)。
3. **首跑失敗**:v1 覆蓋略低於藝術家(光暈 0.929 且有孤兒頂點)。掃描 epsilon 證明**差距純為邊界取樣密度**
   (eps 0.008→0.002 三件 IoU 全升至 0.983~0.993、孤兒歸零)。
4. **修 S3**(`generate_mesh.py`):加 `epsilon_frac="auto"`(沿階梯細化到覆蓋 target_iou 或碰頂點預算)
   + `compact_orphans()`(只移 index≥n_hull 未參照內部點,hull 順序/數不變);`generate_mesh_v2.py`
   塊狀件回退改用 auto。
5. **重跑通過**:3 件覆蓋 0.982~0.986 **≥ 藝術家 0.968~0.980**,頂點 69~78(vs 78~98)、零孤兒/退化,
   `overall_pass=true`。
6. **回歸驗證**:main_draw 4 mesh(strip 路徑,不走 v1)`validate_against_real --gen v2` 全 overall_pass
   (deform 0 自交/0 翻面)→ **無回歸**。

## 關鍵結論

- **幾何層對生產標準驗收通過**(第一次對非 main_draw 生產標的):S3 自動拓樸覆蓋 ≈ 藝術家手做。
- **最重要(結構性)**:生產 warp 件是 **weighted + 無 deform**;S3 只產 unweighted 幾何 →
  **缺 BBW 權重 + 骨綁(S3 路線圖列出但未建)= 下一個真正槓桿**(幾何等價 ≠ 生產等價)。
- **方法**:固定 epsilon 不通用(窗簾調的常數對塊狀件覆蓋不足/孤兒化)→ 自適應 epsilon 讓覆蓋自對齊。
