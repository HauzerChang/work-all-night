1. **網路政策探測**:
   - `pip download torch`(預設 PyPI index)✅ 成功,526MB/21s。
   - `curl -L https://github.com/.../releases/download/v0.1.0/big-lama.pt` ✅ 200,196MB。

     403 Forbidden。
   - `curl https://huggingface.co` ❌ 同樣 403。
   - 結論:網路政策**非全擋**,但唯一可行安裝路徑(預設 PyPI `torch`)會多帶 ~2GB
     NVIDIA CUDA 依賴(cublas/cudnn/cufft/nccl/triton…),因為 CPU-only wheel 的官方 index
     被擋。`pip install simple-lama-inpainting`(完整依賴,含 `fire`)本身在此環境會因
     `fire` 的 setuptools build 相容性問題失敗,改用 `--no-deps` 安裝(核心程式碼實際只用
     到 torch/numpy/opencv/pillow,`fire`/`torchvision` 未被 `model.py`/`util.py` import)。
2. **新增 `tools/mesh_gen/s4_lama_probe.py`**:一次性 probe 工具,復用 `inpaint_eval.py` 的
   `punch_hole`/`score`/`score_1b`/`estimate_alpha_taper` 等既有函式(alpha 通道沿用
   `fill_cv2_inpaint` 同款 `estimate_alpha_taper`,只讓 RGB inpainting 品質這一個變因不同,
   才能跟既有 cv2 candidate 公平比較)。`simple_lama_inpainting`/`torch` 的 import 延遲到
   `main()` 內,不裝這兩個套件不影響其他 S4 工具正常 import 此檔案(雖然本檔案目前只有
   probe 用途,無其他檔案 import 它)。
3. **對已知 1a fail 案例跑分**(機器人拆件 `身體`/`左手`,`frac=0.12`,與既有 baseline
   同一組挖洞參數,直接可比):通用預訓練 `big-lama.pt`(未微調)interior+edge 共 8 個
   指標,6 個贏過全部 3 個 CPU baseline(`身體` ssim 0.441→0.574,`左手` premult_mae
   66.4→57.7),但**沒有任何一個案例跨過 1a 門檻**(ssim>0.75)。1b 標準下兩者本來就已
   pass,LaMa 也 pass 但無新增益。推論速度 0.6~1.9 秒/件,非瓶頸。
