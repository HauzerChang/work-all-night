# S3 對 held-out 生產標的(Award 機器人)泛化 + 自適應邊界密度

> 結論:S3 mesh 生成器**泛化到未參與調校的真實生產 mesh**(Award 機器人 3 件),但需把
> 邊界取樣密度做成**自適應**才達藝術家覆蓋基準。同時揭示兩個「窗簾校準」的隱藏假設。
> 依據:`tools/mesh_gen/validate_award_robot.py`(端到端 PSD/atlas→S3→對照 Award 真值)。
> 信心:高(對真實藝術家 mesh 逐件量化,自一致評估器)。相關階段:第 2 階段 S3。日期:2026-08-02。

## 背景

- main_draw 4 mesh 是 S3 的**調校標的**;Award 機器人是**held-out**(沒參與任何調參)生產標的。
- Award 中為 mesh 的 3 件:`機器人拆件/光暈`(708×685)、`左手`(259×217)、`身體`(381×427)。
- 端到端閘用 atlas-crop 當來源 alpha(=藝術家真正貼的貼圖;PSD↔atlas 同素材已於 s4 確認),
  對同一 silhouette 比「生成 mesh 覆蓋 IoU」vs「藝術家 mesh 覆蓋 IoU」→ apples-to-apples。

## 發現 1:Award 機器人 mesh 是 weighted + 無 deform timeline(與 main_draw 相反)

| | main_draw 窗簾/影子 | Award 機器人 |
|---|---|---|
| 權重 | **unweighted** | **weighted(骨骼蒙皮)** |
| 變形驅動 | **deform timeline** | **骨骼 transform(無 deform timeline)** |

→ AC5(真實位移場轉移閘)基於 deform timeline,對這些件 **N/A**;weighted 蒙皮是另一種變形
模式,現有 `deform_eval` 不覆蓋。**誠實標記 N/A,不假裝通過。**(未來 S5 若要驗蒙皮變形,
需另建「骨骼→頂點」蒙皮重現閘。)

## 發現 2:固定 epsilon=0.008 對有機輪廓覆蓋不足(泛化缺口)

v1/v2-auto 原本對非 strip 件退回固定 `epsilon_frac=0.008`(Douglas-Peucker),這是**窗簾校準值**。
對機器人有機輪廓:

| 件 | 藝術家 IoU / 頂點 | 舊(eps=0.008)IoU / 頂點 / 孤兒 |
|---|---|---|
| 光暈 | 0.9795 / 78 | **0.929** / 54 / **孤兒 1** |
| 左手 | 0.9681 / 80 | 0.960 / 48 / 0 |
| 身體 | 0.9760 / 98 | 0.968 / 61 / 0 |

- 三件覆蓋率全**低於藝術家基準**;凹形光暈還產生**孤兒頂點**(centroid 濾三角把凹處三角刪掉
  → 該 hull 頂點沒被任何三角用到,AC2c fail,無效 Spine mesh)。
- 藝術家用**遠多的邊界頂點**(hull 78/42/40)貼合輪廓;v1 hull 只有 14/18/21 → 覆蓋輸在邊界解析度。

## 發現 3:IoU 由邊界密度決定(再證);自適應密度可經濟達標

epsilon 掃描(atlas-crop alpha,IoU / 頂點 / hull / 孤兒):

```
件    藝術家 | 0.008          0.004         0.002         0.001
光暈  0.9795 | 0.929/54/14/1  0.966/61/22/0 0.983/73/38/0 0.992/92/58/0
左手  0.9681 | 0.960/48/18/0  0.982/57/30/0 0.991/67/43/0 0.996/107/84/0
身體  0.9760 | 0.968/61/21/0  0.986/69/29/0 0.993/77/37/0 0.995/100/60/0
```

- IoU 隨 eps 變細單調上升(與 s3-four-mesh「IoU 由 rows 決定」同理,只是這裡是 Delaunay 的 eps)。
- 更細 eps 也**順帶清掉孤兒**(邊界密→凹處被更多小三角覆蓋)。

**做法**:`generate_mesh_v2.refine_delaunay()` — 由粗到細掃 eps,取**最粗且 IoU≥target_iou(預設 0.98)
且 orphans=0 且頂點≤預算**者(經濟性:最少頂點達覆蓋目標,近藝術家精簡度)。只用件本身 alpha 自評,
**不需藝術家參照**。非 strip 分支改走此路(取代固定 eps=0.008);strip 分支不動(窗簾/影子不受影響)。

## 驗收結果(target_iou=0.98)

| 件 | 生成(eps / 頂點 / hull) | IoU ≥ 藝術家? | 頂點 ≤ 藝術家? | 結構 | overall |
|---|---|---|---|---|---|
| 光暈 | 0.002 / 73 / 38 | 0.9832 ≥ 0.9795 ✅ | 73 ≤ 78 ✅ | ✅ | **PASS** |
| 左手 | 0.003 / 61 / 36 | 0.9884 ≥ 0.9681 ✅ | 61 ≤ 80 ✅ | ✅ | **PASS** |
| 身體 | 0.005 / 68 / 28 | 0.9834 ≥ 0.9760 ✅ | 68 ≤ 98 ✅ | ✅ | **PASS** |

`validate_award_robot.py` → all_pass=True。回歸:main_draw 3 個可抽取的 strip mesh
(curtain_left/right、shadow)v2 仍全 overall_pass(shadow2 與 shadow 共用 atlas region,
名稱抽取本就失敗,非本次回歸)。

## 發現 4:AC3 絕對頂點預算(≤64)是資產相依的

藝術家對這些有機件用 78–98 頂點;64 是**窗簾/影子(12–21v)校準值**,對有機件過嚴。
→ 泛化的 AC3 應為**「≤ 藝術家同件頂點數」(相對經濟)**,而非絕對常數。閘已改用相對預算。
(無藝術家參照時,退回絕對 `max_verts` 上限當保險。)

## 教訓

- **held-out 生產標的是泛化的真考題**:窗簾校準的默認值(eps、頂點預算)一換有機件就露餡。
- **自評閘要用相對基準**:IoU 對齊藝術家覆蓋、頂點對齊藝術家精簡度,比絕對門檻更能跨資產。
- 誠實面對能力邊界:weighted 蒙皮變形**目前無閘**,標 N/A 而非硬套 deform-timeline 閘。
