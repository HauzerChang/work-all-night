## 出發點:S4 的原始使命是什麼

依 `handoff_S4.md` §1:S4 = 把「一張(或分層)原始美術圖」變成「可綁進 Spine 的乾淨部位件」,
拆兩個子能力——(A) 切圖、(B) 補圖。補圖的問題定義(`handoff_S4.md` §2):角色動起來時原本
被遮擋的部位會露出,若切出的件在被遮區沒有像素,動畫幀會破圖;補圖任務是把「會露出的被遮區」
補上合理像素,依 CPU 可行性分級(邊緣外擴/cv2 inpaint → LaMa → GPU/人工)。

## 結論:S4(切圖+補圖)範疇的核心研究問題已經全部有答案

把上表攤開看,原始使命列出的每一個問題(切圖可靠性、補圖評估器、CPU 補圖能力邊界、
邊界的實戰意義、LaMa 值不值得、分類法有效性、類別2 歸屬)**都已經有經過交叉驗證的答案**,
沒有一項是「不知道」或「還在猜」的狀態。剩下唯二兩個未落地項目,性質都不是「问题没解」,
而是「答案已經有了,只是要不要花資源去套用」的**執行層決策**:

- **候選15**(`estimate_alpha_taper` 修法 trade-off):已知 13 例改善換 9 例新增輕微 fail,
  是否接受這個 trade-off 純粹是「要不要接受這個特定數字」的取捨,不是研究問題。
- **候選17**(headless 生成式補圖):已知需要 API key+費用授權,且已知像素對位是主要工程量;
  在 1b(實戰標準)已經被 Level 1/2 CPU baseline 解決的前提下,候選17 能帶來的增量價值只在
  1a(過嚴標準,已知對本專案實戰不必要)上,優先級本來就低。

## 建議

**建議把 S4「切圖+補圖」標記為已達成核心目標(研究問題已閉環),轉為維護/按需模式**,理由:

1. 三個 CPU baseline(nearest / cv2_telea / cv2_ns)+ 自動盲選 pipeline(`inpaint_eval.py`
   `select_best()` + `psd_inplace_patch.py` `patch_layer_auto()`)已經是一條完整可用的
   生產工具鏈:給一張 PSD 圖層 + mask,能自動選出最佳補法、寫回 PSD、跑閘驗證。
2. 已知邊界誠實記錄在案(1a 對機械紋理材質做不到、1b 對機械紋理材質夠用、類別2 不歸 S4
   管),往後接手的人或排程不會踩到「以為補圖萬能」的認知陷阱。
3. 候選15/17 都是「已有答案、待裁決是否套用」而非「需要更多研究」,繼續在 S4 範疇內鑽研
   不會再帶出新的核心發現(候選16 路徑a 的兩次嘗試已經證明,在既有 1b 三指標框架外加
   第4指標這個方向已經逼近 1a `ssim` 的職責重疊,價值遞減)。
4. `PLAN.md`/`CLAUDE.md` 的策略優先序本來就指向「S3 mesh 生成器」是槓桿最大的下一步
   (純 CPU 可全自動、最大解鎖點)——S4 這邊繼續投入邊際報酬已經在遞減,把排程資源轉向
   S1/S2/S3/S5 符合既有的槓桿排序判斷。

**不建議標記為 `DONE`**(依 `RULES.md`,`DONE` 代表目標完全達成不再需要回頭),因為:
候選15/17 仍是合理的、有明確價值的後續工作(只是優先度較低、需要使用者裁決),且切圖/補圖
作為 S1→S5 pipeline 的一環,未來接上 S1(反推分析器)/S5(骨架半自動)實際跑真實素材時,
可能會冒出本輪 25 個 chunk 沒覆蓋到的新材質類型或新邊界情況。**建議狀態維持 `ACTIVE`
但降低排程優先度**,或由使用者決定是否把這條獨立排程(`claude/spine-s4-inpainting`)
暫停,把運算資源轉給主排程的 S1/S2/S3/S5。
