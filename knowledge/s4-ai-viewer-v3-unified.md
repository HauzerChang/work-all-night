# S4 AI Viewer v3:統一主素材架構(2026-09-04,chunk 40)

> 分支 `claude/spine-s4-inpainting`。使用者要求:「viewer 主畫面 以 匯入的 png或psd為主,
> 我想看到 主素材及當前的圖層, 補圖/切片/拆解 等功能, 對焦到同一個檔案(不要各別載入)」。

## 問題:v2 的三個功能各自為政

v2(chunk 39)把切片/拆解/需求精靈接進 viewer,但拆解分頁自己有一個獨立的
`#decomposeInput` file picker,跟左側「圖層/圖片」載入區完全無關——使用者要拆解一張圖,
得在拆解分頁重新選一次檔,即使那張圖已經在補圖分頁載入過。這正是使用者這次要求改掉的。

## v3 架構:單一「主素材」狀態,三個模式共讀共寫

拿掉「分頁各自獨立載入」的設計,改成:

- **一個持續存在的「主素材」面板**(`mainCanvas`+`maskCanvas`),不管在哪個模式都顯示,
  不會因為切換模式而消失或重置。
- **`setMainAsset(img, name, isComposite)`** 是唯一的狀態寫入點——不管是點左側圖層清單、
  點「◆整體(composite)」偽列、還是補圖套用結果後,都走這一個函式,確保「目前對象」只有
  一份真相(single source of truth)。
- **補圖**:直接在主素材畫布上畫遮罩、送出、套用——套用後主素材本身更新,遮罩清空,
  可以繼續疊代編輯(例如先補一塊,套用,再補下一塊),不用重新載入。
- **切片**:左側圖層清單本來就是同一份 `manifestParts`,v3 只是拿掉了切片分頁自己重複的
  composite canvas(`#sliceComposite` 移除),改成直接用共用的主素材面板顯示 composite。
- **拆解**:拿掉獨立的 `#decomposeInput`,改成「送出」按鈕直接讀 `mainImg`(目前主素材
  顯示的內容,不管是整層還是 composite)當來源——**完全對焦到同一個已載入的檔案**,符合
  使用者的要求。
- **新增「◆整體(composite)」偽圖層列**:PSD 或 manifest(`psd_slice.py` 輸出含
  `composite.png`)載入後,圖層清單最上面會多一列可點選的「整體」,選它會把主素材切回
  完整合成圖(拆解通常想對整張角色圖操作,不是對單一圖層)。載入完成後**自動選取**
  composite(如果有的話),不需要使用者手動點一次。

## 驗證(2026-09-04,Playwright + headless Chromium,全程 mock 真實付費 API)

寫測試的過程中**抓到一個真實 bug**:遮罩畫布(`#maskCanvas`)原本設計成只有在「切換到
補圖模式」時才會被 JS 加上 `.active`(pointer-events 生效),但「補圖」在頁面載入時就是
預設啟用的模式,從未觸發那個切換事件——結果是**頁面剛載入時遮罩畫不出來**,要先切到別的
模式再切回來才會生效。已修正:HTML 裡 `#maskCanvas` 直接帶上 `class="active"` 當初始狀態。
這個 bug 若沒有寫自動化測試、只用肉眼看介面截圖很可能不會發現(畫面看起來完全正常,只是
滑鼠事件被吃掉)。

5 組測試:

1. **單張 PNG 載入 → 自動成為主素材**,補圖模式預設啟用。
2. **遮罩繪製 + mock 補圖呼叫**:修 bug 後遮罩涵蓋率正確算出(28.7%),送出、結果顯示、
   用量記錄新增一列、套用後主素材正確更新且 `targetLabel` 維持一致。
3. **真實 PSD 載入(`robot_parts.psd`)**:composite 偽列正確出現,載入後**自動選取
   composite**顯示(713×693);點一個圖層(光暈)後主素材正確切換(706×683);**切換到
   切片模式,主素材不受影響**(共用狀態,不因為換模式而重置);點回 composite 列,正確
   切回整體視圖。
4. **拆解直接用主素材,無需另外上傳**:切到拆解模式,確認頁面上**不存在**
   `#decomposeInput` 元素;送出後 mock API 回傳合成測試圖(3 個獨立色塊),分割正確偵測
   出 3 個部件;用量記錄表格累積到 2 列(補圖 1 筆 + 拆解 1 筆,同一份共用 log,不因模式
   切換而分開計)。
5. **需求精靈跳轉**:選項 A 的建議按鈕正確切換到切片模式。

全程 **零 JS console error**,全程 mock 真實付費 API 呼叫(未產生任何實際費用)。

## 誠實限制

- 「套用」補圖結果後會覆蓋主素材,若當時主素材是某個 PSD 圖層(非整體),套用只更新那個
  圖層在瀏覽器記憶體裡的顯示內容,**不會寫回原始 .psd 檔案**(這仍是已知限制,寫回 PSD
  需要 ag-psd 的 `writePsd` 或現有 Python `psd_inplace_patch.py`,本次未做)。
- 拆解操作的來源永遠是「目前主素材顯示的內容」——如果使用者想拆解 composite 就要先點選
  「◆整體」,如果只想拆解單一圖層裡糾纏的子部件也可以先選那個圖層再拆解,行為上是彈性的,
  但没有額外提示引導使用者選對層級,容易選錯了才發現。
- 其餘既有限制(拆解核心假設未驗證/需求精靈是規則表非智慧規劃/無像素對位管線)維持不變,
  見 `s4-ai-viewer-v2-slicing.md`。
