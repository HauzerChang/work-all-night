# 真實資產驗證 — 關鍵發現:靜態品質 ≠ 變形穩健

- **相關階段**:PLAN.md S3(mesh 生成器);專案第 2 階段。**里程碑級發現**。
- **信心**:高(用真實貼圖 + 真實藝術家 mesh 對照)。
- **圖**:`knowledge/figures/curtain_left_generated_vs_artist.png`

## 一句話

**我的生成器在真實 `curtain_left` 貼圖上靜態 IoU 0.98 通過,但耐變形 @315px 失敗
(13 自交、2 翻面);藝術家手做的同一片窗簾乾淨。** → 評估器抓到了「看起來對、動起來壞」。

## 對照

| | 我生成 | 藝術家手做 |
|---|---|---|
| 頂點 | 41 | 21 |
| hull(邊界點)| 7(17%) | 16(76%) |
| 內部點 | 34 | 5 |
| 三角 | 73 | 24 |
| 靜態 IoU | 0.98 ✓ | — |
| 耐變形@315px | ✗ 13 自交/2 翻面 | ✓ 乾淨 |
| 結構 | Canny+格點散佈 | **直條狀**(成對邊界點沿兩側,水平帶) |

## 根因

1. **hull 過度簡化**:Douglas-Peucker `epsilon=0.008*周長` 把高瘦窗簾的外框砍到只剩 7 點;
   窗簾兩側需要多個邊界點才能波浪起伏。
2. **內部點佈局與變形軸無關**:Canny 沿視覺褶痕 + 格點散佈,產生大量內部點;在「窗簾橫向拉開」
   這種大幅單向拉伸下,散佈內部點互相穿插 → 自交。
3. **藝術家的智慧**:窗簾用**直條(vertical strip)**拓樸 —— 邊界點為主、成對沿左右兩側排,
   形成水平帶。變形時各帶平滑滑動,不會纏在一起。**拓樸要順著運動方向設計**。

## 行動(下一步 S3 v2)

1. **hull 解析度**:降低 epsilon 或對長邊強制最小邊界點密度(讓兩側有足夠 ripple 點)。
2. **deform-aware 內部佈局**:改用結構化格點(理想上對齊拉伸軸),取代 Canny 散點;
   或對「高瘦 / 大單向拉伸」件偵測為「strip 型」,套直條拓樸。
3. **把耐變形@315px 納入 S3 生成器的正式 AC**(不只靜態 IoU)。

## 方法論意義

這正是鍛鍊計畫「評估器是樞紐」的實證:沒有 deform 評估器,這個 mesh 會被靜態 IoU 0.98 判定為「好」,
直到動畫上線才發現撕裂。**自評閘門必須涵蓋『動起來』的品質,否則自主迴圈會收斂到錯的解。**
