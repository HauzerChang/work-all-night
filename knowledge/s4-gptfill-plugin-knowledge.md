## 0. 一句話總結:S4 唯二沒有解的兩格,使用者手上已經有一條在跑的路

S4 既有量化邊界(見 `s4-inpaint-evaluator.md`、`s4-inpaint-taxonomy.md`、`s4-lama-feasibility.md`):
**1b 防穿幫已用純 CPU 解決;1a 需表演、情境 2 視角外推兩格無解**,且既有結論都指向「需要生成式 AI」。
這支插件正好落在那兩格:`manifest.json` 宣告 `requiredPermissions.network.domains =
["https://api.openai.com"]`,`main.js` 的 `MODEL_NAME = "gpt-image-2"`。

**對候選 4 的意義(重要,但不是推翻數據)**:候選 4(`s4-lama-feasibility.md`)結論「不建議投入
生成式路徑」的**前提**是「本容器要自建 GPU/LaMa 路徑,代價 ~2GB CUDA 依賴且通用權重跨不過 1a
門檻」。那批量化數字仍然有效,但**前提變了**:使用者端已有可用的 API 生成路徑,不需要在容器裡
養 GPU。**待驗證**:`gpt-image-2` 對本 repo 已知 1a 全 fail 的機械紋理材質(`身體`/`左手`)
能不能跨過 1a 門檻(`ssim>0.75`)——這是候選 17,尚未跑,不可先當結論。

## 1. mask 慣例:外部真值(回答了我們一直沒有基準的問題)

| 常數 | 值 | 用途 |
|---|---|---|
| `REPAIR_MASK_DILATE` | **8px** | 重建型補圖:真實透明洞 dilate 8px 當可編輯區——「洞 + 一條薄融合邊界」 |
| `REMOVED_SHADOW_DILATE` | **24px** | 移除物件:被移除件的 footprint dilate 24px 併入遮罩,讓**陰影**能重建並融進邊界 |
| `REPAIR_HOLE_THRESHOLD` | **0.3** | 自動判定任務模式:選區內透明像素占比 ≥30% → 判定為「重建缺失」而非「改內容」 |
| `REPAIR_MIN_CONTEXT` | **512px** | 重建模式給模型的上下文**下限** |

**mask 的編碼方式**(OpenAI images edit API 慣例):輸出一張 RGBA PNG,RGB 全白,
`alpha = 255 - selection`——**透明處 = 可編輯**。我們若要自己呼叫 API,這個編碼不能弄反。

**兩個防呆門檻,與本 repo 同型思維**:精準洞遮罩只在 `holeCount > 25` 時才啟用(樣本太少不 refine);
遮罩尺寸與預期不符時**直接拋錯中止**而不是硬跑(「為避免錯位,本次已停止生成」)。這跟我們
`punch_hole` 材質太薄時「縮洞或明確報錯,不偽造不合規範的洞」是同一種紀律。

**對本 repo 的直接用處**:我們的 `punch_hole` 產出的洞直接就是補圖區,**從來沒有「洞」與
「融合邊界」分離的概念**。插件的 8px 融合邊界是一個實戰在用的外部參考值,對候選 15(A 類岔路,
`estimate_alpha_taper` 邊界漸縮寬度的 trade-off)是有價值的第三方基準——**注意**:8px 是給
生成模型「可以在這裡調和」的餘裕,與我們 `ell`(從材質量出的 alpha 漸縮寬度)物理意義不同,
不能直接當 `ell` 用,但可以當「邊界處理該有多寬」的量級參考。

## 2. 任務模式 ↔ 我們的 taxonomy 對照(高價值:外部獨立分類與我們收斂到近似結構)

| 插件模式 | 觸發 | 對應我們的 taxonomy |
|---|---|---|
| 補圖修復(repair,不勾移除) | 洞占比 ≥30% | **1a 需表演**(補接斷掉的尾巴/手腳,要真的畫對) |
| 移除物件(repair + removeObject) | 使用者勾選 | **1b 防穿幫**(挖掉鈴鐺/墨鏡後補背後內容) |
| 修改內容(modify) | 洞占比 <30% | 我們沒有這個情境(S4 不做內容改動) |

**關鍵差異(不要看漏)**:同一個「移除遮擋件後補背後」的情境,插件用的是**負面參考圖 +
footprint 24px + 陰影推理 prompt** 這麼重的機器,而我們的 1b 用 3 個廉價 CPU baseline 就過關了。
不矛盾——**因為驗收標準不同**:插件要的是「美術品質上真的對」(≈我們的 1a 嚴格標準),我們的 1b
只要求「動態下不穿幫」。這反而**再次佐證 taxonomy 的分級是對的**:同一個情境,標準拉高就需要
生成式路徑,標準拉到「防穿幫」就 CPU 夠用。

**情境 2(視角外推)在插件裡也沒有專門模式**——一致確認它不是遮罩/幾何問題,只能靠生成模型的
prompt 去畫原圖不存在的內容,呼應我們既有結論(屬 S1 需求前移範疇)。

## 3. ⚠️ 生成結果不會像素對位 —— 我們完全沒處理過的一整類問題(最大工程教訓)

**這是本次吸收到最重要的新知識**:生成模型回傳的 crop **不會與原圖像素對位**(會漂移、會整體
縮放)。插件為此做了一整套對位管線,而我們的 `psd_inplace_patch.py` 目前假設「補出來的像素直接
落在 mask 原位」——那個假設只對 CPU baseline 成立(它們就地運算),**一旦接生成式路徑就會破**。

插件的五層對位(全部在**梯度圖**上比 SAD,且**只用選區外的環狀帶**(寬 24px)當比對區,
避開被編輯的內容本身):

1. **全域平移搜尋**:`DRIFT_RADIUS = 10`px 全掃。
2. **全域縮放搜尋**:±5%、step 0.5%(`SCALE_STEPS=10` × `SCALE_STEP=0.005`)。
3. **邊界錨點局部位移場**:選區周圍 8 個錨點(四角+四邊中點),每點在 `ANCHOR_WINDOW=48`px
   視窗內做 ±`ANCHOR_SEARCH=4`px 局部搜尋,再用 **IDW 反距離加權**(`w = 1/(d²+400)`)內插成
   連續位移場 → 修正非剛體的局部形變。
4. **次像素**:拋物線插值(parabolic fit,`0.5*(f₋−f₊)/(f₋−2f₀+f₊)`,夾在 ±0.5)。
5. **接受門檻(防止亂對位)**:平移要 `sad ≤ 92%` of zero-shift 才接受;縮放要 `≤90%` of zero
   **且** `≤97%` of 純平移;局部錨點要 `≤97%`。**「改善不夠顯著就不套用」——與 RULES.md
   「先校準才可信、負對照要有鑑別力」是同一種紀律,獨立收斂。**

另外兩個直接可轉移的實作細節:

- **單次重採樣回貼**:scale + shift + warp 全部合成成一組座標後**只做一次 bilinear 取樣**,
  避免多次重採樣累積模糊。(對應我們 `atlas_crop` derotate 的插值品質考量。)
- **premultiplied 插值**:有 alpha 時,RGB 先乘 alpha 加權再除回(`pm/a`,且 `a>0.001` 才除),
  避免透明邊緣把黑色吃進半透明像素。**我們 S4 全程用 premultiplied 比對(踩過三次
  miscalibration 才定下來),這裡是完全獨立的第三方收斂佐證。**
- **多候選選優的分數**:插件用「**對位品質**(SAD/n)最低」挑候選,而不是「哪個補得最好看」。
  對照我們 `select_best` 用 `seam_ratio` 盲選——兩者都是**用便宜的幾何/梯度代理指標代替
  沒有的真值**,思路同型。「最容易對準原圖的候選就是最可信的」是一個我們可以借用的免費代理。

## 4. 若我們要自己(headless)呼叫同一個 API:幾何與尺寸限制

從 `computeCanvasGeometry()` / `computeContextBounds()` 抄出的硬性條件:

- 長邊 ≤ **2560**(硬上限 3840);面積 **≥655360**(0.65MP,**太小的件要放大**)、≤8294400。
- 長寬比必須落在 **1:3 ~ 3:1**,否則直接拋錯。
- canvas 尺寸對齊 **16 的倍數**(`ceil16`);右/下多出來的部分補中性 padding 條,**並用 mask
  保護 + 在 prompt 裡明講「keep it exactly unchanged」**(雙保險)。
- **上下文給多少**:repair 模式 pad = 選區的 **1.2 倍**(下限 160、上限 1600),且整體
  **不小於 512px**;`preserveOriginal` 模式 pad = 0.28 倍(48~320)。
- **3 張參考圖**:IMAGE1 = composite crop(編輯畫布,mask 只作用於它)、IMAGE2 = 孤立目標圖層
  (識別主體;移除模式下改當**負面參考**)、IMAGE3 = 完整原圖(全域設計參考,長邊 ≤1536)。
- 重試 `MAX_API_ATTEMPTS = 3`;色彩管理:API 側統一 sRGB(`sRGB IEC61966-2.1`),送出前轉、
  收回後轉回原 profile。**我們的 pipeline 完全沒處理 ICC profile**,若接生成路徑要補上。

### ★ 這回答了一個我們沒意識到的方法論問題

插件給重建模式的上下文**下限是 512px**,而我們的補圖閘從頭到尾都是**單一圖層的裁切、沒有任何
周圍上下文**(`inpaint_eval.py` 吃單張 RGBA 件)。也就是說,我們「1a 對機械紋理材質全 fail」
的結論,是在**「只看單層、沒有上下文」**的條件下量出來的。這不表示結論錯(CPU baseline 本來也
用不到上下文),但它揭露一個**零成本、純 CPU、可立即做的實驗**:給 baseline 更大的上下文
(整張 composite 而非單層)會不會改變 1a 判定?→ 列為候選 19,優先度高。

## 5. Prompt 工程知識(可直接複用,尤其陰影推理)

`buildEditPrompt()` 依模式組出三套完整 prompt,每一條都是踩雷後加的。最有價值的幾條:

- **SHADOW REASONING(v1.17 核心)**:「讀洞的邊界像素當**光照證據**:邊緣暗 = 被移除物下方
  的表面處在陰影裡,你**必須**把那個陰影延續進補區——從暗邊界像素、從還在的遮蔽物、從全圖
  光照方向推出它的形狀/方向/柔度/衰減。」並且明確禁止:「**不要用平坦、均勻亮度的顏色填洞。
  一個亮度與它的暗邊界不匹配的填補看起來就是貼上去的,是錯的。**」
- **★ 與本 repo chunk 18(候選 7)的發現完全同構**:我上一個 chunk 用 vision 剛發現,CPU
  baseline 在機械紋理上產出的「奶油糊」平滑模糊之所以看起來錯,正是因為它**是 flat 的、
  沒有延續邊界證據所暗示的結構與明暗**。兩個完全獨立的來源(一個是 prompt 工程實戰、一個是
  我們的視覺自評)指向同一個失真維度 → **強力支持候選 16「1b 缺第 4 個指標」**,而且
  **給了比原本「高頻細節保留度」更可實作的指標方向**:量「洞內的亮度/梯度場有沒有延續邊界
  暗邊所暗示的陰影」,而不是籠統的細節量。列為候選 18。
- 其他反覆出現的約束(對生成式補圖都適用):嚴禁移動/縮放/重繪選區外的東西;嚴禁在輪廓上加
  描邊/輪廓光/發光/背景色;色調(hue/sat/brightness/漸層/AO/高光)在選區邊界必須無法分辨;
  線寬與筆刷風格要像同一個畫師;斷件要重建成**一個連續物件**(厚度/曲率/透視/花紋跨洞延續)。
- **v1.18 的事故分析本身就是教訓**:「移除物件模式」的設定**跨次記住**沒關掉,加上使用者選到
  的是**插件上一次自己產出的結果圖層**被當成「被移除的物件」送進去當負面參考 → 等於告訴模型
  「尾巴這種東西絕不能出現」,結果必然詭異。修法三件套:(a) `PLUGIN_LAYER_PREFIX = /^GPT\s*•/`
  守衛,自己產的圖層永不當參考;(b) 面板常駐黃色警告;(c) 生成時再提醒。
  → **對我們的意義**:「模式與門檻/參考不匹配」這類 bug 我們也踩過同型的
  (edge 模式套 interior 校準的 1b,靠 `applicable` 旗標修掉)。**自我輸出污染自我評估**是
  兩邊都出現過的坑,值得當成一條通則記住。

## 6. 誠實界定 / 尚未驗證

- **未跑分**:本檔沒有任何 `gpt-image-2` 對本 repo 素材的實測數字。「能不能跨過 1a 門檻」
  是候選 17 要驗的,現在不知道。
- **能不能無人驅動**:插件本體是 UXP panel,**必須有人開著 Photoshop**,進不了我們的自動
  驗收迴圈。但它打的是**純 HTTP API**(`api.openai.com`),原則上可以從 Python headless 呼叫
  ——本檔第 4 節抄下的幾何限制與第 5 節的 prompt 就是為此準備的配方。**需要 API key 與
  逐次費用 → 屬需使用者授權的 A 類岔路。**
- **不是所有東西都該照抄**:插件服務的是「美術在 Photoshop 裡手動修一張圖」,我們服務的是
  「排程自動批次處理 + 量化驗收」。對位管線、mask 慣例、prompt 是高度可轉移的;UXP/Photoshop
  的文件操作(duplicate/crop/putPixels/batchPlay)對我們無用。
- **驗證紀律不變**:不管插件寫得多有道理,任何要落地的東西都要過本 repo 既有的閘
  (`inpaint_eval.py` 的 1a/1b + 正負對照校準)。這條排程已踩過三次 evaluator miscalibration,
  外部來源的權威性不能取代自己的校準。
