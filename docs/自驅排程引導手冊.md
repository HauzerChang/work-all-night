# 自驅排程引導手冊

> **目的**:教你把一個 repo 變成「**交給 AI、每天自動推進的長期任務**」——研究、開發、維運、產報告皆可。
> 適用於 **Claude Code on the web** 的 **Routines(排程)**。讀完照做即可從零完成自己的排程。
>
> 本手冊通用;文中以「Spine mesh 自驅研究」這個 repo 當實例,但任何長期任務都適用。

---

## 0. 先懂一個關鍵限制(否則排程會「失憶」)

雲端執行環境是**臨時的**:容器閒置或 session 結束後會被回收,記憶體裡的一切(進度、裝好的套件)都會消失。
所以**不能**靠「開一個 session 一直跑好幾天」。正確模型是:

> ### 檢查點 + 續跑(Checkpoint & Resume)
> 把進度寫進 repo 檔案 → 排程定期開一個**全新、沒有記憶**的 session → 它讀檔案、推進**一小塊**、把結果 commit 回 repo → 結束 → 下次從斷點接續。

**核心心法:每個排程 session 都失憶,所以「要續跑的一切都得寫在 repo 裡」。** 整本手冊都圍繞這句話。

---

## 1. 它是怎麼運作的(一張圖)

```
每天到點
   │
   ▼
平台開一個全新雲端 session(無記憶)
   │   └─ SessionStart hook 自動裝好依賴
   ▼
讀 RULES.md → PLAN.md → STATE.md（這是它的全部記憶）
   │
   ▼
推進「一個有界工作塊」（只做一步，求穩定可續跑）
   │
   ▼
自我驗證（用可量測的標準，不靠人）
   │
   ▼
更新 STATE.md / knowledge/ / log/ → commit & push 回 default 分支
   │
   ▼
結束。下次從新的 STATE.md 接續。
```

---

## 2. 前置:把 repo 變成「可自驅」

排程要能自主推進,repo 裡需要這幾個檔案(這是讓失憶的 session 能自我啟動的最小集合):

| 檔案 | 角色 | 一句話 |
|---|---|---|
| `RULES.md` | 操作守則 / 遞迴規則 | 每次怎麼做、怎麼分解、何時停、何時找人 |
| `PLAN.md` | 階段目標 / 路線圖 | 要去哪、每階段的完成條件 |
| `STATE.md` | **續跑核心** | 現在在哪、**下一步做什麼**、未解問題。每次跑完必更新 |
| `prompts/run.md` | 每次的指令 | 排程 prompt 指向它 |
| `knowledge/` | 長期記憶 | 累積的發現、結論 |
| `log/` | 執行紀錄 | 一次 session 一個檔,方便回溯 |
| `requirements.txt` 等 | 依賴清單 | 讓每個新容器裝得回環境 |
| `.claude/hooks/` + `settings.json` | SessionStart hook | 新 session 自動裝依賴 |

> 本 repo 已有完整範例,可直接抄(見 §7 範本)。

### 2-1. SessionStart hook(讓每個新容器自動就緒)

因為容器會被回收,**每次新 session 都要重裝依賴**。用 SessionStart hook 自動做:

`.claude/hooks/session-start.sh`(remote-only、idempotent):
```bash
#!/bin/bash
set -euo pipefail
[ "${CLAUDE_CODE_REMOTE:-}" != "true" ] && exit 0
cd "$CLAUDE_PROJECT_DIR"
[ -f requirements.txt ] && python3 -m pip install --quiet --disable-pip-version-check -r requirements.txt
echo 'export PYTHONPATH="'"$CLAUDE_PROJECT_DIR"'/tools:${PYTHONPATH:-}"' >> "$CLAUDE_ENV_FILE"
```
`.claude/settings.json`:
```json
{ "hooks": { "SessionStart": [ { "hooks": [ { "type": "command",
  "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh" } ] } ] } }
```
記得 `chmod +x .claude/hooks/session-start.sh`,並**驗證**:
```bash
CLAUDE_CODE_REMOTE=true CLAUDE_PROJECT_DIR="$PWD" CLAUDE_ENV_FILE=/tmp/envtest ./.claude/hooks/session-start.sh
```

> 替代方案:Routine 的環境也有「Setup script」欄(結果會被快取)。hook 的好處是**跟著 repo 走**,換環境也有效。

### 2-2. 分支策略(關係到「續跑能不能成立」)

- Routine **每次從 default 分支 clone**。所以你要續跑的進度,必須在 **default 分支**上。
- Routine 預設只能 push 到 **`claude/` 開頭**的分支。
- **最省事的組合**:讓你的開發分支名為 `claude/xxx`,並把它設成 repo 的 **default 分支**。
  這樣:clone 讀到最新進度 ✅、改完能推回同一條 ✅、續跑閉環成立 ✅。
- 在 `prompts/run.md` 明確要求「**push 回啟動時所在的 default 分支**」,確保下次讀得到更新。

## 3. 寫好「每次的指令」(prompts/run.md)

這是排程 prompt 的內容。原則:**它失憶,所以指令要自足、明確、有界、可驗證、會收尾**。

範本(可改):
```markdown
你正在接手一個長期、跨 session 的自主專案。你沒有上次的記憶,repo 檔案是你的全部記憶。

0. 環境:SessionStart hook 會自動裝依賴。若工具 import 失敗,先 pip install -r requirements.txt。
1. 讀 RULES.md、PLAN.md、STATE.md、CLAUDE.md,以及 knowledge/ 索引與 log/ 最近 1–2 筆。
2. 依 RULES.md 行事(AC-first、自我驗證、自主程度、迭代預算)。
3. 從 STATE.md 找下一步,推進「一個有界工作塊」(只做一步)。
4. 用可量測的標準自我驗證(別靠肉眼)。評估器本身也要可信(對照真值/負對照)。
5. 記錄:新發現寫 knowledge/(更新索引);更新 STATE.md;在 log/YYYY-MM-DD-NNN.md 新增一筆。
6. 用清楚訊息 commit & push 回啟動時所在的 default 分支,然後結束。不要無限長跑。
遇到需人類決策 / 連續無進展 / 目標達成,依 RULES.md 標記狀態並停止。
```

## 4. 建立排程 Routine(Claude Code on the web)

> 排程功能叫 **Routines**,在 **https://claude.ai/code/routines** 設定。
> 在 web session 內 `/schedule` 指令是隱藏的;用網頁 UI。(CLI 本機 session 可用 `/schedule daily ...`。)

照下列步驟(對應官方建立表單):

1. 開 **https://claude.ai/code/routines** → 點 **New routine**。
2. **Name + Prompt**:取名;Prompt 貼「`請依照 prompts/run.md 的指示推進這個專案。`」;
   **Model 選擇器**選一個夠強的模型(研究/開發建議 Opus)。
3. **Select repositories**:加入你的 repo。它每次從 **default 分支** clone(確認你的進度在 default 上)。
4. **Select an environment**:一般選 **Default**(Trusted 網路,允許套件庫如 PyPI/npm)。
   若你的任務要連自家服務或清單外網域,進環境設定把 Network access 改 Custom/Full。
5. **Select a trigger → Schedule**:選頻率(Hourly / Daily / Weekdays / Weekly)。
   時間用你的當地時區,平台自動換算;實際會晚幾分鐘啟動(stagger),正常。
   - 想要「每兩小時 / 每月一號」等自訂:先選最接近的預設,再用 CLI `/schedule update` 設 cron(最短間隔 1 小時)。
   - 想「未來某時跑一次」:設 one-off(跑完自動停用)。
6. **Connectors / Permissions**(表單底部):
   - Connectors 預設帶入你所有連接器,**用不到的移除**(縮小權限)。
   - 若需要推到非 `claude/` 分支,才開 **Allow unrestricted branch pushes**(一般不用)。
7. 點 **Create**。

---

## 5. 驗證(務必做一次)

建好後在詳情頁點 **Run now**,立刻跑一次,別等明天:

- 它會開一個新 session,可即時看。
- **預期**:hook 裝好依賴 → 讀 STATE.md 下一步 → 推進 → commit & push 回 default 分支。
- 跑完檢查:repo 有沒有**多一筆 commit**、`log/` 有沒有**新增一筆**、`STATE.md` 的「下一步」有沒有更新。

> ⚠️ **綠燈 ≠ 成功**:run 列表的綠燈只代表 session 沒有基礎設施錯誤。要點進去看 transcript、或看 commit/log 才知道任務真的有進展。被擋的網路請求、缺的工具、任務失敗都在裡面,不在綠燈上。

---

## 6. 日常怎麼掌握 & 何時會被找

**掌握進度**:看 `log/`(每天一筆)、`STATE.md`(永遠是「現在/下一步」)、commit 歷史。

**何時會被找**(建議寫進 RULES.md 的升級政策):只在三種情況停下找你——
1. **不可自決的岔路**(創意/結構決策);
2. **超迭代預算卡關**;
3. **里程碑審查**。
其餘自主進行。

## 7. 範本(可直接抄)

最快的方式:**直接複製本 repo 的這些檔案**到你的專案,再改內容:

```
RULES.md                      # 操作守則 / 遞迴規則 / 升級政策
PLAN.md                       # 階段目標 / 路線圖
STATE.md                      # 進度狀態(續跑核心)
prompts/run.md                # 每次排程的指令
knowledge/README.md           # 知識庫索引
log/README.md                 # 紀錄格式
requirements.txt              # 依賴
.claude/hooks/session-start.sh
.claude/settings.json
SCHEDULE.md                   # 你這個專案專屬的排程設定速查
```

最小 `STATE.md` 骨架:
```markdown
# STATE — 續跑核心
## 專案狀態
ACTIVE        <!-- SETUP / ACTIVE / BLOCKED / DONE -->
## 目前階段
(現在在哪)
## 下一步動作 (next action)
1. (下一個有界工作塊,要具體可執行)
## 未解問題 / 阻塞
- (需人類決策或外部資源的事)
## 進度摘要
- YYYY-MM-DD:(做了什麼)
```

## 8. 疑難排解

| 症狀 | 原因 / 解法 |
|---|---|
| 排程跑了但「沒記憶、每次從頭」 | 進度沒推回 **default 分支**,或沒更新 `STATE.md`。確認 run.md 有「push 回 default」且每次更新 STATE。 |
| 工具 import 失敗 / 缺套件 | SessionStart hook 沒生效。確認 `.claude/` 已在 default 分支、hook 有 `chmod +x`、`requirements.txt` 正確。 |
| 連不到某網域(403 host_not_allowed) | 環境網路是 Trusted(只允許常見套件庫)。到環境設定把 Network access 改 Custom 加網域,或 Full。 |
| 推不上去 / 只推到別的 `claude/` 分支 | 預設只能推 `claude/` 分支。讓 default 分支本身是 `claude/xxx`,或開 Allow unrestricted branch pushes。 |
| `/schedule` 指令找不到 | 你在 web session 內(該指令隱藏)→ 用網頁 UI。或:用了 API key/Bedrock 登入、設了 DISABLE_TELEMETRY 等、CLI 太舊。 |
| 綠燈但沒進展 | 綠燈只代表沒崩。點進 run 看 transcript / 看 commit。 |
| 跑太兇 / 想暫停 | 詳情頁 **Repeats** 區的開關可暫停;或降低頻率。One-off 不計每日上限。 |
| 想改方向 | 直接編輯 `STATE.md` 的「下一步」或 `PLAN.md`,下次排程就照新方向走。 |
